# Reachy Mini 로컬 LLM 음성 대화 앱 — 설계

- 작성일: 2026-07-29
- 대상: Reachy Mini **시뮬레이터**(MuJoCo) — 실기 없음
- 검증 환경: macOS 26.5.2 / Apple M5 Pro / 48GB / Python 3.12.13

---

## 1. 목표

말을 걸면 로봇이 알아듣고, 감정 모션으로 반응하며, 음성으로 답한다. 전 구간이 로컬에서
돈다. 나중에 클라우드 LLM API로 옮기거나 Windows에 배포할 수 있어야 한다.

범위 밖: 실기 하드웨어, 카메라·비전, 발화 중 끼어들기(인터럽션), 머리·안테나 각도 직접 제어.

## 2. 결정 사항과 근거

측정은 전부 이 환경에서 직접 수행했다.

| 결정 | 선택 | 근거 |
|---|---|---|
| LLM 서빙 | llama.cpp `llama-server` (8080) | 이미 구축됨. `llamactl.sh reach-llm` |
| 모델 | `gemma-4-E4B-it` Q4_K_M (4.6GB) | 공식 Reachy Mini 로컬 구성과 동일 모델 |
| 출력 제약 | OpenAI `response_format: json_schema` (strict) | 이식성(B안)과 형식 보장(A안)을 동시에 취함 |
| thinking | 서버 `--reasoning off` | **`--reasoning-budget 0`은 끄지 못한다**(§9 참조) |
| STT | `mlx-whisper` + `whisper-large-v3-turbo` (8090) | 한국어 지원 확인. RTF 0.020 실측 |
| TTS | macOS `say -v Yuna` → Piper `ko_KR/kss` | 공식 권장 Kokoro-82M은 **영어 전용** |
| VAD | 에너지 임계 **RMS 0.010** | 노이즈 바닥 0.0014 vs 음성 0.068 — 양쪽에서 7배 여유 |
| 로봇 동작 | 감정·댄스 모션 재생만 | 열거형 선택이라 작은 모델에서도 안정 |
| 앱 형태 | CLI 스크립트 | 반복 속도 우선. 검증 후 공식 앱으로 포장 |

### 2.1 기존 사례를 따르지 않은 지점

공식 HF 블로그와 커뮤니티 포크의 권장 조합은 **한국어에서 성립하지 않는다.**

| 사례 | 권장 | 한국어 |
|---|---|---|
| HF 공식 블로그 | STT `nvidia/parakeet-tdt-0.6b-v3` | ❌ 25개 유럽어 전용 |
| dwain-barnes 포크 | TTS `hexgrad/Kokoro-82M` | ❌ 태그가 `en` 하나 |

대체안은 §2 표와 같다. macOS는 한국어 음성 9종을 내장하고 있어 TTS 다운로드가 0이다.

## 3. 아키텍처

```
[앱 (CLI)]
   │
   ├── 마이크 직접 캡처 (GStreamer osxaudiosrc)
   │     ※ 데몬을 경유하지 않는다 — 데몬의 webrtcdsp 가 음성을 깎는다(§9)
   │
   ├── HTTP → STT   127.0.0.1:8090  /v1/audio/transcriptions   (OpenAI 호환)
   ├── HTTP → LLM   127.0.0.1:8080  /v1/chat/completions       (OpenAI 호환)
   ├── SDK  → 데몬  127.0.0.1:8000  → MuJoCo 시뮬 (모션 + 자체 사운드)
   └── 재생 → 스피커 (TTS)
```

데몬은 **미디어 ON**으로 둔다(감정 모션의 자체 사운드 재생). 앱이 마이크를 따로 잡아도
충돌하지 않음을 실측 확인했다.

### 3.1 한 바퀴

```
마이크 → 에너지 VAD로 발화 구간 검출
      → WAV 조립 → STT → 텍스트
      → 프롬프트 조립(불변 시스템 블록 + 사용자 발화)
      → LLM (json_schema strict)
      → {"action": "<enum>", "args": {...}, "say": "..."}
      → 열거형 멤버십 + args 스키마 방어 검증
      → 레지스트리가 실행 (내장 모션 재생 / MCP 호출)  ∥  TTS 발화
      → 재생 동안 마이크 게이팅 → 다시 듣기
```

## 4. 컴포넌트

파일 하나에 책임 하나를 둔다.

| 파일 | 책임 | 외부 의존 |
|---|---|---|
| `audio_in.py` | 마이크 캡처, 에너지 VAD, 발화 WAV 조립 | GStreamer |
| `stt.py` | WAV → 텍스트 (HTTP 클라이언트) | STT 서버 |
| `moves.py` | 모션 카탈로그 로드·화이트리스트 → `Capability` 목록 | reachy_mini |
| `capabilities.py` | **액션 레지스트리** — 내장·MCP·플러그인을 합쳐 스키마 컴파일 (§6.1) | — |
| `mcp_source.py` | MCP 서버 연결, `tools/list` → `Capability` 정규화 (§6.2) | `.mcp.json` |
| `skills.py` | `skills/*.md` 로드·우선순위 정렬 → 시스템 블록 합성 (§6.3) | — |
| `llm.py` | **제공자 어댑터 경계** (§5) | LLM 엔드포인트 |
| `robot.py` | 데몬 연결, `play_move` | reachy_mini |
| `tts.py` | `speak(text)` 하나만 노출 (§7) | `say` 또는 Piper |
| `main.py` | 루프, 구간별 지연 계측, 폴백 | 위 전부 |
| `stt_server.py` | 로컬 STT 서버 (이미 작성됨) | mlx-whisper |

`main.py`는 능력이 어디서 왔는지 모른다 — 레지스트리에서 받아 스키마를 만들고,
모델이 고른 이름을 레지스트리에 돌려줄 뿐이다. 능력을 늘리는 데 `main.py`는 바뀌지 않는다.

`moves.py`는 화이트리스트를 상수로 갖는다. 카탈로그 85개를 전부 넣지 않고
**24개**로 시작한다 — 컨텍스트가 줄어 지연과 선택 정확도가 함께 좋아진다.
개수를 바꾸면 시스템 블록이 바뀌어 프롬프트 캐시가 무효화되므로(§5.2),
실행 중이 아니라 코드 수정으로만 바꾼다.

## 5. LLM 제공자 이식성

로컬에서 클라우드 API로 옮기는 것을 전제로 설계한다. `llm.py` 밖의 코드는
어떤 제공자를 쓰는지 알지 못한다.

### 5.1 어댑터가 감추는 것

```python
class LLMClient:
    def __init__(self, base_url, model, api_key=None, thinking=None, timeout=5.0): ...
    def decide(self, user_text: str, actions: ActionSpace) -> Action: ...
    #  Action = {"action": str, "args": dict, "say": str}
    #  ActionSpace 는 레지스트리(§6.1)가 컴파일한 스키마 — llm.py 는 내용을 해석하지 않는다
```

| 제공자마다 다른 것 | 어댑터 처리 |
|---|---|
| 인증 | `api_key`가 있으면 `Authorization` 헤더, 없으면 생략 |
| 모델 식별자 | 설정값. 로컬은 임의 문자열 |
| thinking 제어 | **로컬**: 서버 `--reasoning off`(요청에 아무것도 안 넣음)<br>**API**: 제공자별 파라미터를 어댑터가 매핑 |
| 구조화 출력 | 1순위 `response_format: json_schema` strict<br>2순위 tool calling<br>3순위 프롬프트 + 파싱 재시도(최대 2회) |
| 스트리밍 | 사용 안 함 — 응답이 짧고 모션 시작이 곧 반응이다 |

**OpenAI 호환 엔드포인트가 아닌 제공자**는 어댑터 구현체를 하나 더 두어 대응한다.
호출부 시그니처는 `decide()` 하나로 고정이므로 그 외 코드는 바뀌지 않는다.

### 5.2 프롬프트 구조 — 캐싱 가능하게 고정

로컬에서는 프롬프트 길이가 사실상 공짜지만 API는 토큰 과금이다. 그래서
**시스템 블록을 요청마다 바이트 단위로 동일하게** 유지한다.

```
messages[0] system : 스킬 팩(§6.3) + 액션 카탈로그(§6.1)   ← 불변. 프롬프트 캐시 대상
messages[1] user   : 사용자 발화                           ← 매 요청 변동분
```

카탈로그를 사용자 메시지에 섞거나 순서를 바꾸면 캐시가 깨진다. 무효화 조건 전체는 §6.4에 있다.

### 5.3 비용·프라이버시 가드

원격 제공자를 쓸 때만 적용한다.

- 전사된 발화가 외부로 나간다. **`LLM_REMOTE=1` 같은 명시적 opt-in 없이는 원격을 쓰지 않는다.**
- 요청당 `max_tokens` 상한을 둔다(대사 80자 제한이 스키마에 이미 있다).
- **분당 20회** 상한을 두고 초과 시 조용히 건너뛴다 — VAD 오검출이 과금으로 이어지지 않게.
- 원격 실패가 연속 3회면 로컬 엔드포인트로 폴백하고 알린다.

## 6. 확장 지점 — 스킬과 MCP

기능을 늘릴 때 `main.py`를 고치지 않아도 되게 만든다. 늘어나는 것은 두 종류다 —
**로봇이 할 수 있는 일**(액션)과 **로봇이 구는 방식**(행동 팩).

### 6.1 액션 공간 추상화

모션 재생을 특별 취급하지 않는다. 모든 능력을 같은 형태로 등록한다.

```python
@dataclass(frozen=True)
class Capability:
    name: str                 # 스키마 열거형에 그대로 들어가는 식별자
    description: str          # 모델이 고를 근거. 없으면 오선택한다(§9)
    params: dict | None       # JSON Schema. 인자 없으면 None
    invoke: Callable          # 실행 진입점
```

공급원은 세 가지이고 모두 같은 레지스트리에 들어간다.

| 공급원 | 예 | 비고 |
|---|---|---|
| 내장 | 감정·댄스 모션 24개 | M1 범위 |
| MCP 서버 | `reachy-mini` MCP의 조작 도구 | 선택. 기본 비활성 |
| 로컬 플러그인 | 사용자 정의 파이썬 함수 | 파일 추가만으로 등록 |

### 6.2 MCP 통합 — 도구를 tool calling 이 아니라 스키마로 컴파일한다

**이것이 이 절의 핵심 결정이다.** MCP 도구를 모델에 네이티브 `tools`로 넘기면
제약 디코딩 보장이 사라져 작은 모델에서 형식 실패가 다시 생긴다(§2 결정 근거).

그래서 기동 시 한 번:

```
MCP 서버 연결 → tools/list 로 도구 목록 수집
              → Capability 로 정규화 (이름·설명·입력 스키마)
              → 내장 능력과 합쳐 하나의 json_schema 열거형으로 컴파일
              → 이후 요청은 지금과 동일하게 스키마 제약 1회 호출
```

모델은 여전히 `{"action": "<enum>", "args": {...}, "say": "..."}` 하나만 낸다.
`args`는 선택한 액션의 `params`로 검증하고, 실행은 레지스트리가 MCP 호출로 넘긴다.

**규약**

- 프로젝트 `.mcp.json`을 그대로 읽는다 — 별도 설정 파일을 만들지 않는다.
  (`agentculture/reachy-mini-mcp`가 이미 프로젝트 스코프로 등록돼 있다.)
- `MCP_ENABLED=0`이 기본값이다. 켜지 않으면 내장 능력만 쓴다.
- **화이트리스트 필수** — 서버가 노출하는 도구를 전부 열지 않고 설정에 적은 것만 등록한다.
  도구 이름이 바뀌면 조용히 사라지는 편이 낫다(잘못된 능력이 열리는 것보다).
- 기동 시 도구 목록 수집이 2초 안에 안 끝나면 그 서버를 건너뛰고 경고만 남긴다.
  MCP 때문에 앱이 못 뜨는 일은 없어야 한다.
- 액션 실행 타임아웃은 **3초**. 초과 시 실패로 처리하고 `say`만 수행한다.

**안전**: 시뮬레이터에서는 물리적 위험이 없어 MCP 런타임 제어의 부담이 낮다.
**실기로 옮기면 전제가 달라진다** — 그때는 파괴적 액션에 사람 승인 게이트를 두고,
화이트리스트를 읽기 전용 도구부터 다시 짠다.

### 6.3 스킬 = 행동 팩

로봇의 성격·말투·상황별 규칙을 코드가 아니라 파일로 둔다.

```
skills/
  base.md          # 항상 로드. 역할·출력 규칙
  persona-*.md     # 성격 (택 1)
  situation-*.md   # 상황별 규칙 (다중 로드 가능)
```

각 파일은 프론트매터 + 산문이다.

```markdown
---
name: persona-friendly
kind: persona
priority: 10
---
사용자 말을 그대로 되받지 마라. 짧게, 한 문장으로 답하라.
```

로더는 `priority` 순으로 이어붙여 시스템 블록을 만든다. 새 성격을 추가하는 데
코드 수정이 필요 없다. 공식 하네스의 `skills/*.md` 패턴과 같은 발상이되,
**대상이 코딩 에이전트가 아니라 런타임 로봇**이라는 점이 다르다(§6.5).

### 6.4 프롬프트 캐시와의 관계

스킬과 MCP 능력은 **시스템 블록에 들어간다**(§5.2). 따라서 캐시 무효화 조건이 늘어난다.

| 바뀌면 캐시 깨짐 | 대응 |
|---|---|
| 스킬 파일 내용·구성 | 기동 시 1회 로드. 실행 중 재로드하지 않는다 |
| MCP 도구 목록 | 기동 시 1회 수집. 런타임 재탐색하지 않는다 |
| 화이트리스트 | 설정 변경은 재시작을 요구한다 |

시스템 블록의 해시를 로그에 남긴다 — 캐시가 깨진 시점을 나중에 추적할 수 있어야 한다.

### 6.5 개발 시점 하네스와 혼동하지 말 것

이름이 겹쳐 헷갈리기 쉽다.

| | `harness/skills/*.md` | `skills/*.md` (이 절) |
|---|---|---|
| 대상 | Claude Code 등 **코딩 에이전트** | 런타임 **로봇 앱** |
| 시점 | 앱을 만들 때 | 앱이 돌 때 |
| 소유 | Pollen 공식 (v1.9.0 고정, 수정 금지) | 이 프로젝트 |

## 7. TTS 이식성 (Windows 배포 대비)

```python
def speak(text: str) -> None: ...
```

| 백엔드 | 플랫폼 | 비고 |
|---|---|---|
| `say -v Yuna` | macOS 전용 | 기본값. 다운로드 0, 합성 0.75초 실측 |
| Piper `ko_KR/kss` | Windows·Linux·macOS | 배포 경로. 약 60MB |

`TTS_BACKEND=say|piper`로 고른다. STT도 서버 경계 뒤에 있어 Windows에서는
`transcribe()` 구현만 `faster-whisper`로 바꾸면 된다. LLM은 OpenAI 호환이라 플랫폼 무관이다.

## 8. 지연 예산

| 구간 | 값 | 출처 |
|---|---|---|
| 발화 종료 감지 (VAD hangover **0.4s**) | 0.4s | 설계값 — 임계 미만이 0.4초 지속되면 발화 종료로 본다 |
| STT | 0.06~0.25s | 측정 (RTF 0.020) |
| LLM (스키마 응답, 로컬) | 1.2s | 측정 (6/6) |
| TTS 합성 | 0.75s | 측정 (`say`) |

**발화 종료 → 모션 시작 1.6~1.9초**, **→ 음성 응답 시작 2.3~2.6초**.

지배적 비용은 LLM 하나다. 원격 API로 가면 네트워크 RTT가 더해지므로 타임아웃은
설정값으로 두고 기본 5초로 잡는다.

## 9. 반드시 알아야 할 함정 (전부 실측 확인)

| 함정 | 내용 |
|---|---|
| **`--reasoning-budget 0`은 thinking 을 끄지 못한다** | 사고를 없애는 게 아니라 `reasoning_content`로 분리하지 않을 뿐이다. 자유 대화에서 사고 텍스트가 `content`로 새어 11.6초·`finish_reason=length`. 끄려면 **`--reasoning off`** |
| 데몬 경유 마이크는 죽어 있다 | 데몬이 하드웨어 AEC 대신 켜는 `webrtcdsp`가 음성을 깎는다. 직접 캡처는 정상(노이즈 대비 50배) |
| 스키마 없이는 사고가 샌다 | 6/6·1.19초가 깨끗했던 이유는 JSON 스키마 문법 제약이었다 |
| 모션 이름만 주면 오선택 | 설명을 함께 주자 의미 적중이 6/6으로 올랐다. 프롬프트 문제이지 모델 크기 문제가 아니었다 |
| macOS 시뮬 기동은 `mjpython` 필수 | `./run-sim.sh`가 캡슐화. GStreamer 스캐너·오디오 프로바이더 랭크까지 함께 처리 |
| 대사가 사용자 말을 되받는다 | `say` 필드에 "사용자 말을 반복하지 말 것" 지시와 예시를 넣는다 |

## 10. 오류 처리

| 실패 | 처리 |
|---|---|
| LLM·STT·데몬 미기동 | 시작 시 헬스체크 한 번. 하나라도 없으면 안내 후 종료 |
| STT 빈 문자열 | 무시하고 다시 듣기 (침묵·잡음) |
| 스키마 밖 `move` | 열거형 검증 실패 → 모션 생략, `say`만 |
| LLM 타임아웃(기본 5s) | 요청 취소 + 폴백 대사 |
| 원격 401/429/5xx | 재시도 1회 → 연속 3회 실패 시 로컬 폴백(§5.3) |
| 모션 재생 중 새 발화 | 재생 완료까지 무시(half-duplex) |
| MCP 서버 기동 실패·목록 수집 2s 초과 | 그 서버를 건너뛰고 경고. 앱은 정상 기동 |
| MCP 액션 실행 3s 초과·오류 | 실패로 처리하고 `say`만 수행 |
| 스킬 파일 파싱 오류 | 해당 파일만 제외하고 경고. 나머지로 진행 |
| 에코 | 재생 중 마이크 게이팅 — 하드웨어 AEC가 없으므로 필수 |

## 11. 테스트

| 층위 | 대상 | 방법 |
|---|---|---|
| 단위 | 카탈로그 로드·enum 생성·스키마 검증 | 서버 불필요 |
| 단위 | WAV 디코딩·리샘플 | 합성 사인파 |
| 계약 | LLM 스키마 준수·의미 적중 | 고정 문장 12개 평가 하네스 |
| 계약 | STT 정확도 | 낭독 5문장, 문자 단위 오류율 |
| 단위 | 레지스트리 스키마 컴파일 | 내장 + 가짜 MCP 능력 → 열거형·`args` 스키마 검증 |
| 단위 | 스킬 로더 | 우선순위 정렬·프론트매터 파싱·깨진 파일 제외 |
| 통합 | 발화 → 모션 | 시뮬 기동 후 `GET /api/state/full`로 자세 변화 확인 |
| 통합 | MCP 경로 | `MCP_ENABLED=1`로 능력 1개 등록·호출 확인 |
| 회귀 | 지연 | 구간별 타임스탬프 로깅, 임계 초과 시 경고 |

평가 하네스는 **제공자·모델 교체 시 그대로 재사용**한다 — 로컬 E4B ↔ 26B-A4B ↔ 원격 API
비교가 같은 잣대로 가능해야 한다.

## 12. 마일스톤

| # | 범위 | 완료 기준 |
|---|---|---|
| **M1** | 텍스트 입력 → 모션 | 12문항 스키마 준수 100%, 의미 적중 ≥80%, 입력→모션 <2s |
| **M2** | 음성 입력 (VAD + STT) | 낭독 5문장 인식, 발화 종료→모션 <2s |
| **M3** | 음성 출력 (TTS) | 대사 발화, 재생 중 마이크 게이팅 동작 |
| **M4** | 이식성 | `TTS_BACKEND=piper` 동작, 원격 LLM 어댑터 1종 연결 확인 |
| **M5** | 확장 지점 | 스킬 팩 2종 교체 동작, `MCP_ENABLED=1`로 MCP 능력 1개가 스키마에 컴파일되어 실행 |

M1은 핵심 부품이 모두 검증돼 있어 조립에 가깝다.

## 13. 실행 전제

llama reach-llm                          # LLM(8080) + STT(8090)

켜진 기본값이므로 이 앱에는 쓰지 않는다.
