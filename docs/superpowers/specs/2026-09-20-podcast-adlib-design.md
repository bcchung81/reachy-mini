# 팟캐스트형 대담 — 사회자 애드리브와 관람객 수준

2026-09-20. 대상: `stage/` (무대감독). **로봇 앱은 바뀌지 않는다.**

## 1. 왜

지금 사회자 대사는 큐시트에 박힌 **고정 문장**이다. 그 자체가 기능이었다 — 사회자가
고정 대사를 3~5초 읽는 동안 도슨트 대사를 생성해 **LLM 지연을 숨긴다.** 대신 두 로봇의
대화가 대본 낭독처럼 들린다.

목표는 두 AI 가 팟캐스트처럼 주고받는 것이다. 여기에 세 가지가 얹힌다.

1. **관람객 수준**(초등·중고등·일반·전문가)에 따라 말이 달라져야 한다. 기동 시 지정한다.
2. **발화가 너무 짧다.** 원인은 §5 에 적었다 — 우연이 아니라 구조적이다.
3. **큐시트 내용에 사실 오류가 있다.** 조사 파일럿에서 세 건이 나왔다(§6).

## 2. 무엇을 바꾸지 않는가

먼저 못박는다. 이 설계가 **건드리지 않는 것**:

- `TurnMachine` 의 상태 4개와 불변식 2개(발화 중 마이크 금지, 동시 발화 금지)
- 와이어 규약(`say`/`mic`/`gaze`/`abort` ↔ `heard`/`speaking_started`/`speaking_ended`/`error`)
- 로봇 앱(`apps/voice_chat/`) — 받은 텍스트를 말할 뿐이다
- 섹션 19개의 순서와 진행 단위
- 관람객 창구가 **하나**라는 원칙(사회자만, 1인 모드면 남은 한 대)

즉 실기 배포 영향이 없다. 전부 노트북에서 도는 감독의 내부 변경이다.

## 3. 턴 흐름

```
지금:  사회자(고정) → 도슨트(생성) → 사회자(고정) → 듣기(무한 대기, "다음" 필요)

바뀜:  사회자(사전 생성) → 도슨트(생성) → 사회자(받아치기, 이중 생성)
                                          → 듣기(질문 대기, 침묵이면 자동 진행)
```

**섹션마다 질의응답을 연다.** 사회자가 받아치기 끝에 "궁금한 점 있으실까요?" 로 **묻고**
기다린다. 지금은 마이크만 열리고 관람객은 그것을 모른다.

질문이 오면 기존 경로(사회자 확인 멘트 → 도슨트 답변)를 그대로 타고, 답이 끝나면 다시
묻고 기다린다. **침묵이 `QUESTION_WAIT_S` 를 넘으면 다음 섹션으로 자동 진행**한다.
관람객이 "다음" 이라는 낱말을 알아야 진행되던 의존이 사라진다(`is_advance` 는 그대로
살려 둔다 — 아는 사람은 즉시 넘길 수 있다).

새로 필요한 것은 **침묵 타이머 하나**다. 감독에 이미 `_deadline` + `tick()` 이 있지만
그것은 "발화 종료 응답이 없다" 는 뜻이라 **섞으면 안 된다.** 질문 대기용 기한을 따로 두고
`tick()` 이 둘을 구분해 본다.

`QUESTION_WAIT_S = 8.0` 으로 시작한다. 근거는 비대칭이다 — 너무 짧으면 말을 꺼내려던
관람객을 자르고(회복 불가, 사람이 무안하다), 너무 길면 정적이 흐를 뿐이다(운영자가
콘솔 `n` 으로 즉시 넘긴다). 그래서 넉넉한 쪽으로 잡는다. 실기에서 조정한다.

## 4. 생성 구조

### 4.1 사전 생성 + 런타임 이중 생성

| 무엇 | 언제 만드나 | 왜 |
|---|---|---|
| 섹션 여는 대사(사회자) | **시연 전, 스크립트로** | 지연 0. 사람이 미리 읽고 고칠 수 있다 |
| 도슨트 해설 | 섹션 시작 시 | 사회자 여는 대사(~6초)가 시간을 산다 |
| 받아치기 **예비** | 섹션 시작 시(해설 다음 순번) | 실제 반응이 늦을 때의 여유분 |
| 받아치기 **실제** | 도슨트 대사를 보낼 때 | 도슨트 발화(~7-8초)가 시간을 산다 |

받아치기는 **먼저 준비된 쪽**을 쓴다. 제시간에 실제 반응이 오면 그것을, 늦으면 예비를
읽는다. 그래서 지연은 0 이면서 대부분은 진짜 반응이 나간다.

여는 대사를 사전 생성하는 이유는 지연만이 아니다 — **시연 전에 사람이 76개(19섹션 ×
4수준)를 읽어볼 수 있다.** 런타임 생성은 그 검토 기회가 없다.

캐시 키에 **수준과 지시문 해시**가 들어간다. 큐시트를 고치면 낡은 항목이 드러난다.
캐시가 없거나 낡았으면 큐시트의 `mc` 원문으로 폴백하고 **경고를 남긴다.**

### 4.2 생성 슬롯을 역할별로 나눈다

지금은 슬롯이 하나다(`_pending_text`/`_pending_ready`/`_gen_token`, 주석에 "한 턴에
생성은 하나뿐"). 도슨트 해설과 받아치기가 동시에 살아 있어야 하므로 **이름을 가진
슬롯**으로 나눈다. 세대 토큰도 슬롯마다 둔다.

2026-09-20 에 `on_speaking_ended` 의 유예 대기를 진입 락 밖으로 뺀 구조를 그대로 쓴다
(`docs/lessons.md` 의 "같은 규칙의 나머지 구멍"). 슬롯이 늘어도 규칙은 같다 — **락을 놓고
기다렸으면 깨어나서 상태와 세대 토큰을 다시 본다.**

### 4.3 LLM 은 하나·직렬 그대로

두 화자가 **하나의 대화 이력**을 봐야 말이 이어진다. 그래서 B 의 대사는 A 가 정해진
뒤에야 만들 수 있다 — 병렬이 아니라 **파이프라인**이고, 클라이언트를 늘려도 얻는 것이
없다. 엔드포인트도 하나면 된다.

페르소나가 둘이므로 `generate(brief, history)` 가 **역할을 받게** 바뀐다. 시스템
프롬프트만 역할별로 갈리고 락과 이력은 공유한다.

> ⚠️ 알려진 병목: `stage/__main__.py::build_generate()` 의 락은 **버려진 생성이 아직
> 돌고 있으면 새 생성이 시작조차 못 하게** 한다. 옛 호출이 유예를 넘기면 새 대사가
> 폴백으로 떨어진다. 이번 범위 밖이지만 슬롯이 늘면 더 자주 드러난다 — 취소 가능한
> 호출이 제대로 된 고침이다.

## 5. 분량 — 발화가 짧은 이유

세 겹이고 **셋을 같이 고쳐야 한다.**

1. **길이 규정이 전부 상한뿐이다.** 큐시트 19섹션이 "3문장 이내"×7, "4문장 이내"×6,
   "5문장 이내"×5, "6문장 이내"×1 — 전부 *이내* 다. 하한도 목표치도 없어 한 문장으로
   답해도 지시 위반이 아니다.
2. **시스템 프롬프트에 분량 얘기가 없다.** `_system_prompt()` 는 톤·표기·정직성만 말한다.
3. **`llm.py:79` 에 `max_tokens: 200` 이 하드코딩돼 있다.** 감독도 이 클라이언트를 쓴다.
   한국어는 토큰당 글자가 적어 200토큰이면 대략 200~300자다. 이건 "짧다" 의 원인이라기보다
   **천장**이다 — 1·2 를 고쳐 길게 쓰라고 시키는 순간 문장이 중간에서 잘린다.

고침:

- 분량을 **섹션이 아니라 수준 프로필로 올린다.** 분량은 관람객 수준의 함수다 —
  초등에게 6문장은 길고 전문가에게 2문장은 부실하다. 섹션별 "N문장 이내" 는 **삭제**한다.
- 수준마다 **목표 범위**(하한+상한)를 준다. 상한만 주면 모델이 하단에 붙는다.
- 그 규정을 시스템 프롬프트에도 올린다.
- `max_tokens` 를 하드코딩에서 빼고 수준의 목표 글자 상한에서 계산한다.
  한국어는 토큰당 글자가 적으므로 **상한 글자 수 × 2 + 여유 64** 정도로 잡는다
  (전문가 400자 → 864). 잘리는 것보다 넉넉한 편이 낫다 — 잘리면 TTS 가 끊긴 문장을
  읽는데, 그건 분량 미달보다 나쁘다.
- 생성 결과가 목표 범위에 **한참 못 미치면 경고**를 남긴다. 조용히 짧게 나오는 것이
  지금 문제의 본질이므로 최소한 로그에는 드러나야 한다.

## 6. 데이터 구조

```
data/cues.yaml              최종 큐시트 (한 파일, 섹션당 수준별 브리프)
data/cues-research/*.yaml   조사 산출물 (섹션당 한 파일) — cues.yaml 의 재료
data/levels.yaml            수준 프로필 4개
data/personas/mc.md         사회자 페르소나
data/personas/docent.md     도슨트 페르소나
```

### 6.1 `Cue` 스키마

기존 `id`·`title`·`gaze` 유지. `mc`·`mc_after` 는 **폴백 원문**으로 남는다(생성 실패 시
그대로 읽는다 — 시연이 멈추지 않는다). 여기에 더한다:

- `topic` — 조사 주제
- `facts` — 출처와 등급이 달린 사실 묶음
- `briefs` — 수준 → `{mc_brief, docent_brief}`

섹션별 문장 수 지정은 **삭제한다**(§5).

**한 파일에 수준별 브리프를 두는 이유**: 파일 4개로 쪼개면 섹션 뼈대(id·순서·gaze·폴백
대사·사실·출처)가 4벌로 복제돼 한쪽만 고쳐지는 사고가 난다. 이 저장소는 그 복제를
직전 코드리뷰에서 이미 findings 로 겪었다.

### 6.2 수준 프로필 (`data/levels.yaml`)

수준이 가르는 축 다섯. 시작값은 아래 표로 두고 실기에서 조정한다.

| | 초등 | 중고등 | 일반 | 전문가 |
|---|---|---|---|---|
| 문장 수 | 2~3 | 3~4 | 4~5 | 5~7 |
| 목표 글자 | 70~120 | 120~200 | 180~280 | 260~400 |
| 어휘 | 전문 용어 회피 | 풀어서 | 풀어서 쓰되 용어 병기 | 그대로 |
| 깊이 | 비유 중심 | 비유 + 원리 | 원리 | 수식·수치·표준번호 |
| 숫자 정밀도 | 말하지 않음 | 연도만 | 연도·개략 수치 | 정확한 날짜·원수치 |
| 출처 노출 | 없음 | 없음 | 기관명까지 | 기관·조항·표준 번호 |

글자 수는 **발화 길이**로 환산된다. `CHARS_PER_SEC = 4.0`(실측) 기준으로 초등 약
18~30초, 전문가 약 65~100초다. 전문가 수준에서 한 발화가 길어지면 관람객의 인내와
타임아웃 예산(`_estimate` 가 글자 수로 자동 확장한다) 양쪽을 실기에서 봐야 한다.

### 6.3 페르소나

프롬프트는 **[공통 규약 + 역할 + 수준]** 세 조각을 조립해 만든다. 공통 규약은 지금
`_system_prompt()` 에 있는 것(TTS 가 읽는다, 절대연도, 지어내지 않는다, 지시문을 따라
읽지 않는다)이다.

**코드에서 데이터로 내린다.** 시연 전에 사람이 읽고 고쳐야 하는데 코드에 박혀 있으면
못 고친다. 이 저장소에는 이미 프롬프트를 파일로 두는 선례가 있다
(`apps/voice_chat/voice_chat/prompt.md`).

## 7. 수준 지정

`REACHY_AUDIENCE_LEVEL` 을 설정 사다리로 읽는다(환경변수 → 설정파일 → 기본값 `일반`).
오타는 `role_of_env()` 처럼 **소리 내서 실패**시킨다.

**기동 로그에 수준을 반드시 찍는다.** 엉뚱한 수준으로 도는 것은 조용히 품질만 떨어지는
전형적인 실패이고, 이 저장소 규약이 가장 싫어하는 방식이다.

수준은 감독에만 필요하다 — 로봇 앱은 받은 텍스트를 읽을 뿐이다.

## 8. 조사 규약

**19번이지 76번이 아니다.** 사실은 수준과 무관하다 — "마르코니가 1901년에 수신했다" 는
초등이든 전문가든 같은 사실이고, 수준은 *어떻게 말하느냐* 만 가른다.

```
주제 19개 → 조사(사실 + 출처 + 등급) → 섹션별 파일 → 수준별 브리프 4개 파생
```

출처 등급 셋:

- **A** 정부·표준화기구(ITU·KCA·과기정통부)·학술 원문
- **B** 백과·교과서·기관 해설
- **C** 언론·블로그 — **교차확인 전에는 발화에 쓰지 않는다**

`corrections` 필드는 **필수**다. 파일럿에서 기존 큐시트의 사실 오류가 셋 나왔다:

| 기존 큐시트 | 확인된 사실 |
|---|---|
| "1785년에 전파의 존재가 처음 발견됐다" | 1785년은 **쿨롱 법칙** 발표 연도다. 전파는 맥스웰이 예언하고 헤르츠가 증명했다 |
| "1600마일" | 약 **2,200마일(3,500km)** |
| "영국에서 캐나다까지" | 1901년 뉴펀들랜드는 **캐나다가 아니었다**(1949년 합류) |

이게 조사의 가장 큰 값이다. 지금 프롬프트의 "모르는 것은 지어내지 않는다" 는 **검증할 수
없는 약속**인데, 사실에 출처를 달아 브리프에 넣으면 적어도 브리프 안의 수치는 근거가
보장된다.

파일럿 2섹션은 `data/cues-research/{01-intro,02-history}.yaml` 에 있다.

## 9. 실패와 폴백

조용히 물러나지 않는다 — 전부 경고를 남긴다.

| 실패 | 대응 |
|---|---|
| 여는 대사 캐시 없음/낡음 | 큐시트 `mc` 원문 |
| 받아치기 생성 둘 다 실패 | 큐시트 `mc_after` 원문 |
| 생성이 빈 문자열 | 폴백 원문 |
| 생성 결과가 목표 분량에 한참 못 미침 | 그대로 쓰되 경고 |
| 수준 값이 틀림 | 기동 거부(소리 내서 실패) |
| 마무리 질문이 빠짐 | 고정 질문 문장으로 교체 — `QA_ACK_LINES` 처럼 몇 개를 돌려 쓴다 |

## 10. 테스트

- 침묵이 한도를 넘으면 다음 섹션으로 자동 진행한다
- 질문이 들어오면 침묵 타이머가 멈추고 답변 경로로 간다
- 받아치기: 실제 반응이 제시간에 오면 그것을, 늦으면 예비를 읽는다
- 역할별 슬롯이 서로를 침범하지 않는다(도슨트 생성이 받아치기 슬롯을 지우지 않는다)
- 수준마다 프롬프트의 분량 규정이 실제로 달라진다
- 수준 오타는 기동에서 실패한다
- 캐시가 낡으면(지시문 해시 불일치) 감지하고 폴백 + 경고
- 생성 실패·빈 문자열·분량 미달이 전부 경고를 남긴다
- 기존 스위트 전체가 그대로 통과한다(상태기계·불변식·1인 모드·타임아웃)

## 11. 단계

1. **분량 고침 중 수준과 무관한 부분**(§5) — 시스템 프롬프트에 분량 규정을 올리고,
   `max_tokens` 를 설정으로 빼고, 분량 미달 경고를 넣는다. 이때 목표 범위는 아직
   큐시트의 "N문장 이내" 를 쓴다. 지금 당장 값이 있고 되돌리기도 쉽다.
   (섹션별 문장 수를 **삭제**하고 수준 프로필로 옮기는 것은 3단계다 — 프로필이
   있어야 옮길 자리가 생긴다.)
2. **역할별 생성 슬롯**(§4.2) — 사회자는 아직 고정 대사. 동작이 안 변해 안전하게 검증된다.
3. **수준 + 페르소나**(§6·§7) — 데이터 계층과 조립, 기동 지정. 여기서 §5 의 분량
   규정이 수준 프로필로 올라가고 큐시트의 "N문장 이내" 가 사라진다.
4. **사전 생성 + 받아치기 이중 생성**(§4.1) — 애드리브가 실제로 켜지는 단계.
5. **턴 흐름**(§3) — 마무리 질문과 침묵 자동 진행.
6. **나머지 17섹션 조사**(§8) — 병렬 팬아웃. 3~5 와 무관하게 진행할 수 있다.
