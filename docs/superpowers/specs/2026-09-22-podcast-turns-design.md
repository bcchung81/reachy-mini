# 팟캐스트 다채롭게 — 큐당 N회 주고받기 설계 (2단계)

2026-09-22. 선행: `2026-09-21-launch-and-modes-design.md`(1단계, 기동 통합·모드 골격).
1단계 로드맵 표의 2번 항목을 이 문서에서 구체화한다:

> 2. 팟캐스트 다채롭게 | 큐 = 주고받기 N회(턴 대본), 큐시트 수준별 `points`(오프라인 생성 + 사람
> 검수), 사회자 말투 카드, 발화 중 다음 턴 선생성 | 로봇 재배포 없음(PC 쪽만) | **위험 높음 —
> 감독 핵심 흐름**

## 배경

지금은 큐 하나당 도슨트 해설이 **통짜 한 덩어리**다(`mc`(오프닝) → `docent_brief` 한 번 →
`mc_after`(받아치기+질문 권유)). 도슨트가 40~90초를 혼자 말하는 동안 사회자는 아무 것도
안 한다(1단계 배경 문서의 표현: "도슨트가 40~90초 혼자 말하는 동안 사회자가 논다"). 이걸
사회자↔도슨트가 소주제 단위로 짧게 주고받는 여러 라운드로 쪼갠다 — **총 분량은 지금과
비슷하게 유지하고, 잘게 나눈다**(1단계 결정 표에 이미 못박힌 제약).

관람객이 실제로 질문했을 때 도는 왕복(확인멘트→도슨트 답→재질문, `on_heard`/`_answer` 경로)은
**이미 있고 이 작업과 무관하다** — 그건 관람객이 말을 걸어야만 도는 반응형 왕복이고, 이 작업은
관람객 발화 없이도 해설 본문 자체가 여러 라운드로 도는 것이다. 둘은 같은 상태기계
(`stage/machine.py::TurnMachine`) 위에서 공존한다.

## 결정 (Q&A)

| 항목 | 결정 | 근거 |
|---|---|---|
| 라운드 수 | **포인트 개수가 곧 라운드 수** — 별도 count 필드를 안 둔다 | 데이터 하나로 진실을 유지한다. 저자가 초등에 포인트 2개를 쓰면 그게 2회다. 1단계가 정한 초등2/중고등3/일반3/전문가4는 **목표치**로 저작 가이드에 적되, 코드가 강제하지 않는다(포인트가 그보다 하나 적거나 많아도 시스템은 그대로 돈다 — 저작 유연성을 코드 제약보다 우선한다) |
| 데이터 위치 | `Cue.briefs[level]`에 `docent_brief` 대신(또는 함께) **`points: list[str]`** 추가 | 기존 `brief_for()`의 "비었으면 폴백" 패턴을 그대로 잇는다 — `points`가 없는 큐(아직 안 옮김)는 지금처럼 `docent_brief` 단일 라운드로 돈다 |
| 사회자 다리 대사 | **오프라인 사전 생성 + 사람 검수**, `data/mc_lines.yaml`에 캐싱 | 도슨트 답을 듣기 전에 나가야 하므로 도슨트 발화에 기댈 수 없다 — 포인트 문구만 보고 미리 지어 둘 수 있고, 그래야 매 라운드 생성 지연이 0이다(오프닝 대사와 같은 이유) |
| 도슨트 답 | **실시간 생성 유지**(지금과 같은 경로), 포인트 문구가 브리프 역할 | 도슨트 쪽 생성·폴백 사다리(실제→예비→원문)는 이미 검증됐다 — 새로 만들지 않고 브리프 소스만 바꾼다 |
| 분량 재배분 | 수준별 총 분량(`levels.yaml`)을 포인트 개수로 나눠 **포인트당 예산**을 새로 정한다 | 1단계 결정("총 길이는 비슷하게, 잘게 나눈다")의 직접 계산 — 구체 수치는 아래 §3 |
| 상태기계 확장 | `on_speaking_ended`에 **접두어 매칭 한 갈래**를 추가(`f"{cue.id}:pt{i}"`/`f"{cue.id}:pt{i}:docent"`), 기존 고정 elif들은 손대지 않는다 | 포인트 개수가 수준마다 달라 elif를 N개 하드코딩할 수 없다. 마지막 포인트의 도슨트 답이 끝나는 자리가 지금 `f"{cue.id}:docent"`가 받아치기로 넘어가는 그 자리를 대신한다 |
| 관람객 개입 | 포인트 왕복 중에는 **마이크가 안 열린다**(불변식 ①, `*_SPEAKING` 내내) — "다음"으로 끼어들 방법이 없다. 콘솔 `a`(abort)는 기존 그대로 무조건 IDLE 리셋 | 기존 LISTENING 판정(`is_advance`)과 충돌하지 않는다 — 새 상태 분기가 필요 없다 |
| 마이그레이션 | **한 번에 19큐×4수준=76조합을 다 옮기지 않는다** — 2~3개 큐로 먼저 저작·시연·검수하고 나머지를 잇는다 | 76조합의 "사람 검수" 비용이 크고, 처음 몇 개로 라운드 길이·템포·다리 대사 품질을 먼저 확인하는 게 싸게 먹힌다(1단계도 "2~4단계는 각자 설계"로 단계적이었다) |

## 1. 데이터 스키마

```yaml
# data/cues.yaml, 한 큐의 한 수준
briefs:
  일반:
    mc_brief: "..."          # 오프닝(기존)
    docent_brief: "..."       # 폴백용으로 유지(포인트 없는 큐의 옛 경로)
    points:                   # 신규, 선택 필드 — 없으면 docent_brief 단일 라운드로 폴백
      - "정전기부터 시작해 어떻게 전자기 유도로 이어지는지"
      - "패러데이가 1831년에 무엇을 실험했는지"
      - "그게 지금 발전기·변압기와 어떻게 연결되는지"
```

`points`는 **도슨트 브리프 조각**이다(`docent_brief`와 같은 성격 — 발화 원문이 아니라 지시문).
사회자 쪽 다리 대사는 별도 캐시(`data/mc_lines.yaml`)에 `cache_key(cue.id, level, point_text)`로
저장한다 — 지금 오프닝 대사가 `cache_key(cue.id, level, mc_brief)`로 저장되는 것과 같은 패턴.

`stage/cues.py::load_cues`에 검증을 더한다: `points`가 있으면 **1개 이상**이어야 하고(빈 목록은
거절), `points`가 있는데 `mc_after`가 없는 큐는 거절한다(라운드 끝에 받아치기로 합류할 자리가
없으면 마지막 도슨트 답 뒤 아무 것도 안 나가고 정적이 된다 — 지금 `_REQUIRED`/`_OPTIONAL_STR`
검증과 같은 자리에 추가).

## 2. 상태기계 확장

`Director`에 진행 중인 라운드 상태를 둔다(`_begin_cue`에서 리셋):

```python
self._points: list[str] = []      # 이번 큐의 포인트 목록(수준별로 고른 것)
self._point_i: int = 0            # 지금 몇 번째 라운드인가(0-based)
```

`on_speaking_ended`의 라우팅:

- `cue_id == cue.id`(사회자 오프닝 끝) — **포인트가 있으면** `points[0]`을 브리프로 도슨트
  생성을 건다(지금 `cue.brief_for(level)[1]` 자리를 `points[0]`로 바꾸는 것뿐, 나머지는 기존
  코드 그대로). `cue_id`는 `f"{cue.id}:pt0:docent"`.
- `cue_id.startswith(f"{cue.id}:pt") and cue_id.endswith(":docent")` — 방금 도슨트가 포인트 i를
  답했다. `i+1 < len(points)`면: 캐시에서 포인트 i+1의 다리 대사를 즉시 꺼내 사회자가 말하게
  하고(`_machine.speak`), **그 순간** 포인트 i+1의 도슨트 답 생성을 `_spawn_generate`로 띄운다
  (`_spawn_after`와 같은 "보내는 순간 다음 것을 함께 띄운다" 수법). `i+1 == len(points)`면
  (마지막 포인트였다): 기존 `f"{cue.id}:docent"` 갈래와 **정확히 같은 코드**로 합류한다 —
  받아치기(`_spawn_after`) 실제+예비를 띄우고 `after_of = cue`를 세운다.
- `cue_id.startswith(f"{cue.id}:pt")` (도슨트 답 아님, 즉 방금 사회자가 다리 대사를 말했다) —
  그 자리에서 바로 도슨트에게 진행을 넘긴다(이미 `i+1`로 띄워 둔 생성을 기다리는
  `_await_pending` 경로 재사용).

기존 `f"{cue.id}:docent"`/`:ack`/`:qa`/`:after` elif들은 **한 글자도 안 바꾼다** — 포인트가 없는
큐(폴백)는 지금 코드 그대로 돈다.

## 3. 분량 재배분

1단계 결정("총 길이는 지금과 비슷하게")을 수치로 못박는다. 지금 도슨트 총 분량
(`data/levels.yaml`):

| 수준 | 지금 총 문장 | 지금 총 글자 | 목표 라운드 수 | 라운드당 문장 | 라운드당 글자 |
|---|---|---|---|---|---|
| 초등 | 2~3 | 70~120 | 2 | 1 | 35~60 |
| 중고등 | 3~4 | 120~200 | 3 | 1 | 40~65 |
| 일반 | 4~5 | 180~280 | 3 | 1~2 | 60~95 |
| 전문가 | 5~7 | 260~400 | 4 | 1~2 | 65~100 |

사회자 다리 대사는 **기존 받아치기 분량 규칙(1~3문장·40~120자, 수준 무관 고정)을 그대로
재사용**한다 — 새 규칙을 안 만든다.

열린 결정: 이 표를 `levels.yaml`에 `point_min_chars`/`point_max_chars` 필드로 **명시적으로
추가**할지, 아니면 기존 `min_chars/max_chars`를 포인트 개수로 나눠 **코드에서 계산**할지는
아직 안 정했다 — 후자가 데이터 중복이 없지만, 전자가 저작자가 "이 라운드는 몇 자까지"를
직접 읽고 쓸 수 있어 검수하기 쉽다. 저작 착수 전에 정한다.

## 4. 선생성 — 발화 중 다음 턴

`_spawn_after`가 이미 쓰는 수법("도슨트 대사를 보내는 순간, 다음 반응의 실제+예비를 나란히
띄운다")을 포인트 왕복에도 그대로 쓴다:

1. 사회자가 포인트 i+1 다리 대사를 말하기 **시작하는 순간** 포인트 i+1 도슨트 답 생성을 띄운다.
2. 다리 대사 자체는 사전 생성·캐싱돼 있어 그 순간 지연이 0이다(핵심 전제 — 다리 대사가
   실시간 생성이면 이 수법이 무너진다).
3. 도슨트가 답하는 동안(추정 5~10초) 다음 다리 대사는 **이미 캐시에 있으므로** 기다릴 것이
   없고, 그동안 번 시간이 그 다음(포인트 i+2) 도슨트 답 생성 시간이 된다.
4. 폴백 사다리는 기존과 같다 — 실제 답이 늦으면 예비, 예비도 없으면 포인트 원문을 그대로
   읽는다(`_ensure_visitor_cue`와 같은 자리는 아니다 — 원문을 그대로 읽어도 문제없는 브리프
   성격이라 별도 안내 삽입이 필요 없다, 단 이 부분은 §6에 남긴다).

## 5. 사회자 말투 카드

다리 대사 생성 프롬프트에 few-shot 예시 몇 개를 심어 톤을 통제한다(`stage/prompts.py`에
사회자 분량 규칙이 이미 있는 자리에 추가). `QA_ACK_LINES`/`QUESTION_PROMPTS`처럼 고정 문구
배열이 아니다 — 라운드마다 포인트 내용이 달라 고정 문구를 못 쓴다. 예시:

```
- "오, 그런데 이런 것도 있다면서요?"
- "잠깐, 그거 말고 다른 것도 궁금한데요."
- "그렇군요. 그럼 이건 어때요?"
```

## 6. 오류 처리 (소리 내서 실패)

- 다리 대사 캐시에 없는 (cue, level, point) 조합 — **기동에서 막는다**(`pregen_mc_lines.py`류
  사전 생성 스크립트가 마지막에 "빠진 조합 N개"를 사람이 읽을 수 있게 찍는다, 지금 "고아"
  안내와 대칭). 시연 중 실시간 생성으로 물러나지 않는다 — 다리 대사가 실시간이면 §4의 지연
  은닉 전제가 깨진다.
- 도슨트 답 생성이 전부 실패(실제·예비 둘 다) — 포인트 원문을 그대로 읽는다. `points`가
  발화 지시문이 아니라 사실 요약이라 그대로 읽으면 어색할 수 있다 — 저작 시 "그대로 읽어도
  말이 되게" 쓰라는 지침을 가이드에 남긴다(원장 대조 규칙과 같은 자리).
- `points`가 있는데 `mc_after`가 없는 큐 — `load_cues`가 기동에서 거절한다(§1).

## 범위 밖 (2단계)

- 관람객 질문 왕복(`_answer`/`:ack`/`:qa`) 자체를 바꾸는 것 — 이미 있고 이 작업과 독립이다.
- 질문 정리해 도슨트에게 넘기기, 여러 질문 처리(로드맵 3단계).
- 단독 모드의 큐시트 지식 Q&A(로드맵 4단계) — 이 작업으로 만든 `points` 구조는 4단계가
  재사용할 수 있는 자원이 되지만, 지금은 설계하지 않는다.
- 캠별 화자 선택, 손들기 감지(둘 다 로드맵 4단계, 로봇 재배포 필요 — 이 작업은 "로봇 재배포
  없음"이 전제다).
