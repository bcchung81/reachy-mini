# 기동 통합과 운영 모드(단독 / 팟캐스트) — 로드맵과 1단계 설계

2026-09-21. 선행: 무대감독 컨트롤러 대시보드(`2026-09-21-stage-dashboard-design.md`).

## 배경 (사용자 요청)

1. 루트 폴더의 **기동 스크립트 하나**로 전부 띄운다.
2. **화면에서 모드를 고른다** — 단독 실행 / 팟캐스트.
3. 단독: 전파체험관 관련 질문과 일상 질문에 답한다.
4. 팟캐스트: 시나리오는 그대로, 큐마다 "사회자 질문 1 · 도슨트 답 1" 을 **더 다채롭게 주고받는다**
   (도슨트가 40~90초 혼자 말하는 동안 사회자가 논다). 사회자가 "질문 있으신가요?" 하면
   **카메라로 손을 들거나 말로 질문**하고, 사회자가 질문을 **정리해 도슨트에게 넘긴다**.

## 결정 (Q&A, 2026-09-21)

| 항목 | 결정 | 근거 |
|---|---|---|
| 모드 전환 방식 | **프로토콜 지시**(`mode`)로 앱이 재시작 없이 전환 | 앱 재시작 방식은 대시보드가 ssh·프로세스 권한을 쥐고 전환에 수십 초 — 시연장 약점 |
| 단독 모드 로봇 | **사회자 한 대만** 답한다 | 두 대가 가까우면 서로의 목소리를 질문으로 받는다 |
| 기동 때 처음 모드 | **팟캐스트** (운영자가 시작 버튼을 누를 때까지 대기) | 지금 운영 흐름 유지 |
| 스크립트 | **`./reachy.sh start --sim \| --robot`** | `reachy.sh` 가 이미 루트 단일 진입점 — 헬스체크·바인드·실기 동기화 지식을 재사용 |
| 손들기 감지 | **비전 LLM**(사회자 카메라 스냅샷 → PC gemma4) | 새 의존성 없음·오프라인. 오탐 대비 대시보드 스위치 |
| 주고받기 횟수 | 수준별 **초등 2 / 중고등 3 / 일반 3 / 전문가 4** (`levels.yaml`) | 총 길이는 지금과 비슷하게, 잘게 나눈다 |
| 캠별 화자 선택(serena·sohee…) | **4단계**에 포함 | 로봇 프로토콜 확장·재배포를 한 번으로 묶는다 |
| 진행 순서 | **1단계부터 순서대로** | |

## 로드맵 — 단계마다 따로 설계·배포·검증

| 단계 | 내용 | 로봇 재배포 | 위험 |
|---|---|---|---|
| **1. 기반** (이 문서) | `reachy.sh start`, 감독의 모드 상태, 대시보드 모드 토글(단독은 로봇이 지원을 알릴 때만 켜짐) | 없음 | 낮음 |
| 2. 팟캐스트 다채롭게 | 큐 = 주고받기 N회(턴 대본), 큐시트 수준별 `points`(오프라인 생성 + 사람 검수), 사회자 말투 카드, 발화 중 다음 턴 선생성 | 없음(PC 쪽만) | 높음 — 감독 핵심 흐름 |
| 3. 질문 흐름 | 사회자가 질문을 한 문장으로 정리 → 도슨트에게 넘김, 여러 질문, 되묻기(음성 질문) | 없음 | 중간 |
| 4. 로봇 앱 + 프로토콜 | `mode` 지시로 단독 루프 전환, 단독 프롬프트 통합 + 큐시트 지식 키워드 검색, 도슨트 발화 중 사회자 **듣는 모션**, 손들기 감지(`watch_hands`/`hand_raised`), 캠별 화자(`voice`) | **필요** | 높음 — 마이크·자기목소리 회귀 |

2~4단계는 각자 설계 문서를 따로 쓴다. 이 문서는 **1단계만** 구현 범위다.

## 1단계 설계

### 1-1. `./reachy.sh start --sim | --robot`

| 순서 | `--sim` | `--robot` |
|---|---|---|
| ① 추론 3종(LLM·STT·TTS) | 없는 것만, loopback(127.0.0.1) | 없는 것만, LAN(0.0.0.0) — 기존 `start_llm_stt`·`start_tts` 재사용 |
| ② 예열 | `scripts/warmup.py` 한 번 | 같다 |
| ③ 로봇 | 모의 데몬 2대(`--mockup-sim`, :8000 사회자 / :8001 도슨트) + 앱 2대(`REACHY_ROLE` mc/docent). `sim2.sh` 의 출력 장치 분리(`REACHY_MC_AUDIO_OUT` / `REACHY_DOCENT_AUDIO_OUT`)와 경고를 옮긴다 | `REACHY_MC_HOST`(기본 192.168.0.4)·`REACHY_DOCENT_HOST`(기본 192.168.0.5) 각각: 도달 확인 → 백엔드 상태/복구 → config 동기화(역할 포함) → 로봇→PC 도달 확인 → 기상 → 앱 기동. 기존 `robot_up` 의 **로봇별 단계**를 호스트·역할을 받아 두 번 돈다. **한 대가 안 닿으면 경고하고 계속**(감독에 이미 1인 모드가 있다) |
| ④ 무대감독 + 대시보드 | **전면**(콘솔 키가 비상 폴백으로 산다), `REACHY_DIRECTOR_HOST=127.0.0.1` | 전면, `0.0.0.0`(로봇이 붙어야 한다) |
| ⑤ 안내 | 대시보드 주소를 찍고 브라우저로 연다(`open`/`xdg-open` 이 있을 때만, 없으면 주소만) | 같다 |

- **정리**: 콘솔이 끝나면(`q`/Ctrl-C/EOF) **`start` 가 띄운 것만** 내린다 — `--sim` 은 데몬·앱, `--robot` 은
  두 로봇의 앱 정지. 추론 3종은 남긴다(기존 관례, 전부 내리려면 `./reachy.sh stop`).
- **`--dry-run`**: 아무것도 띄우지 않고 **띄울 목록**을 한 줄씩 찍는다(대상·포트·역할·바인드). 테스트가 이
  출력을 본다.
- **대상 인자는 필수**다(`--sim`/`--robot` 없이 부르면 쓰임새를 찍고 2 로 끝난다) — 실기와 시뮬을
  기본값 하나로 뭉개면 시연장에서 엉뚱한 쪽이 뜬다.
- **흡수·정리**: `scripts/sim2.sh` 는 `start --sim` 으로 대체하고 지운다. `run_two_sim_test.sh`(미커밋)도
  지운다. 다른 하위 명령(sim/demo/serve/robot/logs/stop/check…)은 **부품**으로 남긴다 — 1대 개발·실기 운영에
  여전히 쓴다. 문서(CLAUDE.md 명령 블록, `docs/two-robot-setup.md`, `docs/two-robot-offline-test.md`)는
  `start` 한 줄을 앞에 둔다.

### 1-2. 모드 개념 (감독·대시보드)

- **감독 상태** `mode`: `"podcast"`(기본) | `"solo"`. 처음 값은 `REACHY_MODE`(틀린 값이면 경고하고 podcast).
- **로봇 능력 알림**: 로봇 hello 에 **선택 필드 `caps`**(문자열 목록)를 받는다. 없으면 빈 목록 — 지금 앱은
  보내지 않으므로 동작이 바뀌지 않는다(4단계 앱이 `["solo"]` 를 보낸다). 감독 쪽 프로토콜만 넓힌다 —
  로봇 앱·재배포 없음.
- **`set_mode(name)`**(콘솔·대시보드 `m solo` / `m podcast`):
  - 모르는 이름 → 경고만.
  - 이미 그 모드 → 경고 한 줄.
  - `solo` 인데 **사회자 로봇이 붙어 있지 않거나 `caps` 에 `"solo"` 가 없다** → 거절 경고
    ("사회자 로봇 앱이 단독 모드를 아직 모른다 — 로봇 앱 업데이트(4단계) 뒤에 켜진다").
  - 전환이 받아들여지면 **먼저 `abort()`**(말하던 것을 멈춘다) 후 모드를 바꾸고 경고 한 줄. 1단계에는
    로봇에 `mode` 를 보내는 일이 없다(4단계에서 여기에 붙는다 — 자리만 주석으로 남긴다).
  - `solo` 인 동안 팟캐스트 명령(`s`·`n`·`p`·`r`·`g`)은 거절 경고(`a` 와 `l`·`m` 은 된다).
- **스냅샷**: `mode`, `solo_available`(사회자가 붙어 있고 `caps` 에 `solo` 가 있는가).
  **hello**: `modes: ["podcast", "solo"]`.
- **대시보드 헤더**: [단독][팟캐스트] 토글. 적용된 모드는 채운 색. 단독 버튼은 `solo_available` 이 거짓이면
  비활성 + 툴팁/옆 문구 "로봇 앱 업데이트(4단계) 후". 단독이면 런다운·진행 버튼을 비활성하고 "단독 모드 —
  사회자 로봇이 관람객 질문에 답합니다" 안내를 보인다(대화 로그는 기존 이벤트 로그에 그대로 흐른다).
  헤더 56px·창 높이 맞춤·1024px 겹침 없음은 유지.

### 1-3. 오류 처리 (소리 내서 실패)

- 추론 서버가 안 뜨면 `start` 전체를 멈춘다(LLM 없이 시연 불가) — 어느 로그를 볼지 안내.
- 로봇이 안 닿으면 그 로봇만 건너뛰고 경고, 감독은 뜬다(1인 모드).
- 포트 충돌(8000/8001/8777/8778)은 기동 전에 검사해 무엇이 쥐고 있는지 보여 주고 멈춘다.
- `REACHY_MODE` 가 틀리면 경고하고 podcast.

### 1-4. 테스트

- 감독: `set_mode` 갈래 전부(모르는 이름·이미 그 모드·caps 없음 거절·사회자 없음 거절·전환 시 abort·solo 에서
  팟캐스트 명령 거절), 스냅샷 `mode`/`solo_available`, hello `caps` 수용(없으면 빈 목록). 기대값은 리터럴.
- 콘솔 `m`, 대시보드 hello `modes`, e2e 통합 테스트에 `caps` 있는 가짜 로봇 한 경우.
- 페이지: 정적 검사(토글 id·`m ` 명령) + 컨트롤러가 실제 브라우저로 확인.
- 스크립트: `./reachy.sh start --sim --dry-run` / `--robot --dry-run` 출력에 대상·포트·역할·바인드가
  있는지(`tests/` 에서 subprocess). 인자 없이 부르면 종료코드 2. 마지막으로 컨트롤러가 `start --sim` 을 실제로
  돌려 포트·대시보드·로봇 접속을 확인한다.

### 범위 밖 (1단계)

로봇 앱의 `mode` 처리, 단독 대화 루프 전환, 손들기, 듣는 모션, 캠별 화자(모두 4단계). 턴 대본·질문 정리(2·3단계).
