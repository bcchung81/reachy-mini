### 2.3 칸 공통 규칙

- main 에서 일한다. 워크트리·브랜치·`git add/commit/stash/checkout` 을 하지 않는다(다른 칸의 미완성 변경이 같은 트리에 있다).
- 테스트는 **자기 파일만** 돌린다(예: `.venv/bin/python -m pytest -q tests/test_handout_webtoon.py`). 전체 묶음은 조율자가 돌린다 —
  다른 칸이 고치는 중인 파일 때문에 빨개진 것을 쫓지 않는다.
- 로봇·외부 API 에 닿는 명령(`start --robot`·`robot up`·`bake`(합성)·OpenAI/ElevenLabs 호출)을 돌리지 않는다. 필요하면 조율자에게 넘긴다.
  임시 서버는 예비 포트(18xxx)로 띄우고 끝나면 내린 것을 확인한다. **재현할 때 로봇이 꺼져 있다고 가정하지 않는다**(lessons 2026-11-13).
- 버그를 잡으면 증상 → 원인 → 규칙 → 테스트 이름을 보고 파일의 "조율자에게" 에 적는다(조율자가 `docs/lessons.md` 에 옮긴다).
- 캡처·임시 파일은 저장소 밖 스크래치에 둔다.

## 3. 갈래 A — 시연 안정화

**목표.** 외부 API·인터넷·맥 화면·로봇 주소 때문에 공연이 조용히 망가지는 길을 막고, 11-13 에 테스트로만 확인한 9가지를 실기에서 확인할
점검표를 만든다.

### A-1(P0-2) 외부 API 사전 점검

확인된 사실
- `run-app.sh` 는 키가 **있는지만** 본다(`has_key` — 값은 읽지 않는다)[코드 확인].
- 예열은 `reachy.sh::robot_warmup` → `scripts/warmup.py`. 단계가 실패하면 `_step` 이 `   LLM … 건너뜀 (HTTPError)` 한 줄, 스크립트가 0 이
  아니면 흐린 색 "일부 예열을 건너뛰었다" 뿐이다[코드 확인 1323~1325줄, warmup.py `_step`].
- 예열은 **게이트웨이·프록시를 거친다**(`REACHY_LLM_URL` 기본 `:8080`). 외부 전용에서 OpenAI 가 실패하면 게이트웨이는 502
  `{"error":"no-local"}` 만 주고 이유(HTTP 401/429·연결 실패)는 `openai-gateway.log` 에만 남긴다[코드 확인 `_no_local`]. 즉 예열 쪽에서는
  **지금 401 과 429 를 가를 수 없다.**
- OpenAI 401 메시지는 키 일부를 되돌려 준다 — 오류 요약을 그대로 실으면 키 조각이 샌다(lessons, `error_summary`·`scrub`).
- `tts_elevenlabs.credits_left(key)` → `(쓴 크레딧, 한도)`[코드 확인 253줄]. 지금 123,571/131,000 남음[조율자 실측].

할 일
1. `openai_gateway.py` — 외부 전용 502 에 **이유 종류만** 싣는다: 응답 본문 `upstream`(`"401"`·`"429"`·`"5xx"`·`"connect"`·`"timeout"`)과
   헤더 `X-Reachy-Upstream`. 메시지 글은 싣지 않는다(키 조각). 로봇은 본문을 안 읽으므로 재배포 없음.
   테스트 `tests/test_openai_gateway.py::test_외부_전용_502_는_실패_종류를_싣고_메시지는_싣지_않는다`.
2. `tts_cache_proxy.py` — wav 요청 실패(외부 전용) 502 에도 같은 `upstream` 표지. 테스트 `tests/test_tts_elevenlabs.py::test_외부_전용_wav_실패는_실패_종류를_싣는다`.
3. `scripts/warmup.py` — `REACHY_LOCAL_MODELS=off` 일 때 `_step` 실패를 "건너뜀" 이 아니라 **점검 실패**로 찍는다. 종류별 문구:
   401 = "키가 틀렸거나 만료 — `.env` 의 OPENAI_API_KEY", 429 = "잔액·한도 — 결제/사용량 확인", connect/timeout = "인터넷 연결", 그 밖 = 로그 경로.
   줄마다 **무엇이 안 되는지**를 붙인다(LLM = 관람객 질문 답 · STT = 음성인식("다음" 포함) · TTS = 관람객 답 목소리. 대본 공연은 계속).
   ElevenLabs 키가 있으면 `credits_left` 로 "남은 크레딧 N / 한도" 를 찍고 U2 문턱으로 색을 정한다(조회 실패도 한 줄 경고).
   로컬 구성(스위치 없음)에서는 지금 문구 그대로 — 로컬 예열 실패는 원래 "느려질 뿐" 이다.
   테스트 `tests/test_reachy_start.py` 또는 새 `tests/test_warmup.py`(A 소유) — `test_외부_전용_예열_실패는_종류와_안_되는_것을_말한다`,
   `test_크레딧이_문턱_아래면_경고한다`, `test_로컬_구성의_예열_문구는_그대로다`.
4. `reachy.sh::robot_warmup` — 외부 전용에서 예열이 실패하면 `say_bad`(빨강) 묶음으로 다시 보여 준다(감독 콘솔이 올라오며 위로 밀리므로
   감독 로그 머리에도 한 줄). U1 이 ②면 여기서 멈춘다(`REACHY_PREFLIGHT=warn|stop`, 기본은 결정대로).
5. `run-app.sh` — "키는 있는지만 본다" 주석 옆에 "키가 맞는지는 기동의 예열이 본다" 한 줄.

완료 기준: 위 테스트. 실측(조율자, 외부 호출): `.env` 키를 일부러 틀린 값으로 둔 채 `RUN_APP_DRY` 가 아닌 예비 포트 기동 →
빨간 줄 3종 확인, 키 조각이 화면·로그에 없는 것 `grep`.
위험: 예열이 실제 요청(작은 토큰·짧은 합성)을 쓰므로 과금이 조금 든다 — 지금도 같다. 429 본문 모양이 "분당 한도" 와 "잔액 없음" 으로
갈리는데 종류만 실으면 둘을 못 가른다 → `429` 한 줄에 두 원인을 다 적는다.

### A-6(P1-7) 로봇 주소 — U4 결정 뒤

3. 테스트 `tests/test_reachy_start.py::test_배역_주소가_안_잡히면_이름으로_찾아_새_주소를_알린다`,

완료 기준: 테스트. 실측은 로봇이 망에 돌아온 뒤 점검표 항목으로.
