## 1. 이번에 달라진 전제 — 초중등 합치기(커밋 `01a5de3`)

고르는 수준은 초중등(내부 이름 **중고등**)·일반·전문가 셋이다. 초등은 더 고를 수 없다 → **웹툰의 새 10큐는 중고등 한 수준만 만든다**
(초등 칸을 그리면 아무도 못 보는 화면이 된다 — 그림 양이 반이다). 하이라이트 9큐의 초등 칸은 지우지 않는다(되돌릴 자리).
빌더·테스트가 "큐마다 두 수준" 을 전제하면 **큐마다 수준 부분집합을 허용하도록** 고친다(새 큐 = 중고등만). 페이지 안 수준 고르개에서
초등을 골랐을 때 새 큐가 없으면 그 큐는 건너뛰거나 "이 수준 화면 없음" 으로 — 공연 모드(감독 수준 = 중고등)에는 영향이 없다.

## 3. 칸 W — 웹툰(중고등) 10큐

1. 시작 확인: `./reachy.sh bake --check`(합성 없음)로 10큐 중고등 문장이 캐시에 다 있는지 · `tests/test_handout_webtoon.py` 초록.
2. **`scenes.js` 를 큐별 파일로 나눈다**(`scenes/<큐>.js`, 빌더가 순서대로 이어 붙인다) — 2,176줄에 10큐를 더하면 4천 줄을 넘는다(갈래 C 보고 §5).
   **나누기 전과 뒤의 생성물이 바이트 단위로 같아야** 다음으로 간다. 위험하면 나누지 않고 보고한다.
3. 빌더·테스트를 "큐마다 수준 부분집합" 으로(§1). 하이라이트 9큐 생성물은 바뀌지 않아야 한다(바이트 비교 또는 칸 캡처 비교).
4. **05 먼저 끝까지**: 대사 → 콘티(칸 목록·칸 깨기 한 번) → 그림 → 빌드 → `?check=1` 이 `[]` → 헤드리스 캡처(칸마다)로 겹침·잘림을 고친다
   → 「## 조율자에게」 쓰고 멈춘다(사용자가 실제 HTML 로 본다).
5. 확인 뒤 06 → 08 → 09 → 10 → 11 → 12 → 13 → 15 → 16. 큐마다 보고 파일에 "큐 · 칸 수 · 깨고 나오는 물체 · 고친 것" 한 줄.
6. 테스트: 전체 코스(19큐)가 중고등으로 다 있다(`data/courses.yaml` 의 "전체") · 모든 큐 `?check=1` `[]` · 기존 콘티·쉼 규칙을 새 큐까지.
7. 가짜 공연: `fake_show.py --port 18xxx --level 중고등 --qa` 로 19큐 끝까지 따라가며 캡처 · 생성물 크기·처음 뜨는 시간.

지켜야 할 것(지난 C 에서 밟은 것): 글은 그 수준의 검증 카드·대사 낱말에서만, 장면 아이디어는 조사 자료 등급 A·B 에서만 · 발화 **안** 문장 간격은
`GAP_SENT` 고정, 연출은 발화 **사이**에서만 · 카드는 그 포인트를 실제로 말하는 칸에 · 그림은 t 의 순수 함수(`Math.random`·`Date`·transition 금지) ·
새 합성 0(빠진 문장이 있으면 빌더가 멈춘다 → 보고).

## 4. 칸 X — 분해도(전문가) 10큐

1. 시작 확인: `bake --check`(전문가 10큐) · `tests/test_handout_exploded.py` 초록.
2. **10큐의 "무엇을 분해하나" 표를 먼저 쓴다**(분해하는 것 · 부품 라벨 · 강조 순서 = 전문가 대사 낱말). 물건이 아닌 큐(05 기증자 · 09 특별교류전시 ·
   12 멀티미디어실 · 13 크로마키 · 16 무선국 검사)는 대안 둘씩.
3. **06(주파수 대역별 기증품 — 가장 물건다운 큐) 먼저 끝까지**: 표 → 모양 → 빌드 → `?check=1` `[]` → 헤드리스 캡처
   (`--enable-unsafe-swiftshader --use-angle=swiftshader`) → 「## 조율자에게」 쓰고 멈춘다(표와 06 화면을 사용자가 본다).
4. 확인 뒤 나머지 9큐. 큐마다 보고 파일에 한 줄.
5. 테스트: 전체 코스 19큐가 있다 · 모든 큐 `?check=1` `[]` · 모든 큐의 도슨트 0턴에 강조 부품.
6. 가짜 공연(`--level 전문가`) 19큐 캡처 · 프레임 시간·생성물 크기(장면 19개 — 큐를 넘길 때 앞 장면을 버리는지 확인).

지켜야 할 것(지난 D): 라벨 = 전문가 대사 + 검증 카드, 빌더 대조 · YAML 흐름 매핑 안 쉼표 든 글은 따옴표 · three `traverse` 도중 자식 붙이지 않기 ·
분해 = 도슨트 0턴 시작, 재조립 = 사회자 받아치기.

- 칸마다 첫 큐가 오면 사용자에게 **실제 HTML** 로 연다(캡처만 보여 주지 않는다).
- `tests/test_live_stage.py` 는 "06 은 전용 화면이 없어 카드 화면" 을 단언한다(180~195·244·267줄). 칸이 06 을 빌드하면 깨진다 →
  **카드 화면으로 이어 보기 시험은 전용 화면이 없는 가짜 큐로 바꾼다**(19큐가 다 차면 실제 큐로는 그 길을 볼 수 없다). 칸들이 06 을 빌드하기 전에 한다.
- 다 들어오면: 전체 묶음 → 그 칸 파일만 커밋 → `/stage/auto` 통합 확인(초중등·전문가 19큐) → 배포 문서 §15.12 범위 줄 · 인계 문서 M5 지움.

## 6. 위험

- 생성물 크기: 웹툰 약 12 MB, 분해도 약 15 MB 어림(지금 9큐 크기에서 비례). 전시장 PC 에서 처음 뜨는 시간을 잰다 — 너무 크면 수준·코스별로 나눠 빌드하는 것을 다음에.
- 추상 주제(분해도 05·09·12·13·16, 웹툰 09 특별교류전시) — 표·콘티를 사용자 확인 전에 그리지 않는다.
- 리허설과 겹침: 칸들은 정적 HTML 만 바꾼다. 조정실은 페이지 수정 시각으로 매니페스트를 다시 읽으므로 공연 중 빌드하면 **다음 큐부터** 새 화면이 쓰인다 —
  이상하면 조정실을 새로고침한다.
