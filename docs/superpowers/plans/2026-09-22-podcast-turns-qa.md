# 해설은 고정 대본, 생성은 관람객 질문에만 — 구현 계획

2026-09-22. 선행: `2026-09-22-podcast-turns-pilot.md`(N회 왕복 파일럿, `voice-chat-mvp` 에 병합됨).
설계 문서 `specs/2026-09-22-podcast-turns-design.md` 의 결정 몇 개를 이 계획이 뒤집는다(§10).

## 배경

1. 02-history 파일럿을 돌려 보니 사회자가 묻고 도슨트가 설명하는 게 아니라, **사회자가 한 말을 도슨트가
   확인만 하는** 대화가 됐다. 포인트가 사실 문장이었고, 턴당 1문장이었고, 오프닝이 답을 먼저 말한 닫힌
   질문이었다.
2. 고치는 과정에서 더 근본적인 문제가 드러났다. **수준과 주제가 정해져 있는데 도슨트 해설을 공연 때마다
   gemma 가 새로 쓴다.** 해설이 나가는 동안은 마이크가 닫혀 있고 사회자 대사도 정해져 있어서, 도슨트가 받는
   맥락은 매 회차 같다. 실시간 생성으로 얻는 게 없는데, 조사 파일로 검증한 사실을 매번 검수 없이 다시 쓰고
   (틀린 문구가 되살아날 수 있다) 생성 대기·폴백 사다리라는 실패 경로만 늘린다.
3. 사회자 오프닝을 미리 만들어 두는 이유로 `stage/mc_cache.py` 가 이미 "사람이 시연 전에 읽어볼 수 있다"를
   들었다. 같은 이유가 도슨트 해설에도 그대로 해당한다.

## 1. 대사마다 어디서 나오나

| 대사 | 지금 | 바뀐 뒤 |
|---|---|---|
| 사회자 오프닝 | 사전 생성 캐시(`data/mc_lines.yaml`) → 없으면 `mc` 원문. 캐시는 한 번도 만들어진 적 없음 | **`mc` 고정** |
| 사회자 턴 질문 | 사전 생성 캐시 → 없으면 `ask` 원문 | **`ask` 고정** |
| 도슨트 턴 설명 | gemma 실시간(`answers` 를 씨앗으로) | **`answers.<수준>` 고정** |
| 도슨트 해설(턴 없는 17개 큐) | gemma 실시간(수준 `docent_brief`) | 17개를 전부 턴 대본으로 저작한 뒤, 전환 때 **해설 생성 경로를 지운다**(`points` 필수) |
| 사회자 받아치기 | gemma 실시간 2벌(실제·예비) → `mc_after` | **`mc_after` 고정**(19개 전부 이미 있음) |
| 관람객 질문 확인 멘트·재질문 | 고정(`QA_ACK_LINES`·`QUESTION_PROMPTS`) | 그대로 |
| **관람객 질문 답** | gemma 실시간, 근거 = 섹션 제목뿐 | **gemma 실시간 — 근거·금지 규칙·구어체 지시 추가**(§4) |

## 2. 데이터 형식

```yaml
- id: 02-history
  mc: "..."            # 오프닝 — 수준 공통, 0턴 질문으로 끝난다. 그대로 말한다
  mc_after: "..."      # 받아치기 — 수준 공통. 그대로 말한다
  docent_brief: "..."  # 옛 최상위 — 런타임 미사용(§8 에서 사실 정정만)
  points:              # 1~3턴
    - answers: {초등: "...", 중고등: "...", 일반: "...", 전문가: "..."}   # 0턴(질문은 mc)
    - ask: "..."       # 사회자 질문 — 수준 공통, 그대로 말한다
      answers: {...}   # 도슨트 설명 — 수준별, 그대로 말한다
  briefs:
    일반:
      mc_brief: "..."      # 런타임 미사용 — 오프닝의 저작 의도 메모(조사 파일 병합이 계속 복사)
      docent_brief: "..."  # 관람객 질문 답의 **근거**(§4)
      guard: "..."         # 관람객 질문 답의 **금지 규칙**(§4)
```

턴 형식·검증(`Turn`/`Point`, 큐 최상위 `points`, `MAX_TURNS`, 0턴 `ask` 금지, 네 수준 `answers` 필수,
`guard` 타입)은 이번 세션에 이미 구현돼 있다 — 그대로 쓴다.

## 3. 구어체 규칙 (고정 대본 데이터 테스트)

모든 고정 문장(`mc`·`ask`·`answers`·`mc_after`)에:

1. **글말 어미로 끝내지 않는다** — 문장이 '~다'(단 '~니다' 는 허용)·'~것'·'~함'·'~음' 으로 끝나면 막는다.
   '~했다/~이다/~한다'(글말), '~라는 것.'(명사형 요약)이 걸린다. 02 파일럿 포인트("…라는 대비", "…라는 것")가
   이 모양이었다. ~~마지막 글자가 요·죠·까·니다 인 것만 허용~~ — 호명("여러분!")·감탄("그렇구나!") 같은 입말까지
   막아서 막는 쪽(글말 목록)으로 바꿨다(2026-09-22).
2. **글에서만 쓰는 기호를 안 쓴다** — '→', '**', '·', 괄호. TTS 가 기호를 읽거나 괄호 속을 끊어 읽는다.
3. **단위는 읽는 대로 쓴다** — '3,500km' → '3,500킬로미터'. 약어(ITU, VLF)는 그대로 둔다.
4. **분량** — `answers.<수준>` 이 그 수준의 `point_min~max` 글자, 2~3문장 안에 든다(`levels.yaml`
   point_* 는 런타임 자르기가 아니라 저작 규칙이 된다 — 사람이 쓴 문장은 런타임에 자르지 않는다).

실측(지금 큐시트): `mc`·`mc_after` 38줄은 1~3을 전부 통과한다. 02·06 턴 문장에서 걸리는 것 —
단위 약어 3줄(02 2턴 중고등·일반·전문가 "3,500km"), 분량 초과 4줄(02 2턴 일반 111자·전문가 143자,
06 1턴 일반 114자, 06 2턴 전문가 135자). A단계에서 다듬는다.

## 4. 관람객 질문 답 강화 (유일한 실시간 생성)

지금 지시문은 `관람객이 '…' 라고 물었다. 지금 섹션은 '제목' 이다. 도슨트로서 답한다.` 뿐이다. 해설이
고정되면 사실 위험이 전부 여기로 몰린다. 지시문을 이렇게 바꾼다:

- **근거**: 이 섹션·지금 수준의 `docent_brief`("이 섹션에서 확인된 내용"). `**` 강조는 조립할 때 걷는다
  (큐시트 원본은 그대로 — 모델이 별표를 흉내 내면 TTS 가 읽는다, `prompts.py` 주석의 경로).
- **금지 규칙**: 지금 수준의 `guard`.
- **규칙**: 질문에 먼저 답한다. 근거와 앞선 해설에 없는 사실·수치는 지어내지 않는다. 모르면 모른다고
  말하고 이 섹션 이야기로 돌린다.
- **이력**: 고정 대사도 말한 순간 이력에 남긴다(지금 `_remember` 자리 그대로) — "아까 말한 헤르츠는…" 같은
  질문에 답할 수 있어야 한다.
- **구어체**: 시스템 프롬프트 공통 규약(`stage/prompts.py::_COMMON`)에 "관람객에게 말하듯 '~요'·'~습니다'로
  끝낸다. '~다'·'~이다'로 끝나는 글말은 쓰지 않는다" 를 넣는다. 생성 직후 글말 어미가 섞이면 **경고**한다
  (`stage/__main__.py::build_generate`, 고치거나 자르지는 않는다 — 소리 내서 알리는 것까지).
- 분량은 지금처럼 수준 프로필(min~max)이 준다.

## 5. 코드 변경 (3단계 — 저작이 끝난 뒤 한 번에)

**감독 턴 흐름(새)**: 오프닝(`mc`) 끝 → 도슨트가 0턴 설명을 바로 말함 → 끝나면 사회자가 1턴 질문을 바로 말함 →
… → 마지막 설명 끝 → 사회자가 `mc_after` 를 바로 말함 → LISTENING. 발화 라벨(`c1:pt0:docent`, 종단
`c1:docent`, `c1:pt1`, `c1:after`)은 지금 것을 그대로 쓴다 — 상태기계와 abort·재접속·타임아웃 테스트가 그
라벨에 기댄다. 생성을 기다리지 않으므로 이 갈래는 `_await_pending`·세대 검사를 안 탄다.

|---|---|
| `stage/director.py` | 턴 설명·질문·받아치기를 **바로 말한다.** 단일 라운드 해설 생성 경로와 그 폴백(`FB_BRIEF`), `_spawn_after`(받아치기 생성 2벌)·예비 슬롯(`FB_SPARE`·`FB_SHEET`) 제거. 오프닝은 `cue.mc`. 관람객 답 지시문 §4. 이번 세션에 넣은 턴 지시문 조립(`_point_brief`·`_POINT_ANSWER_RULE`)·턴 답 대기·턴 분량 자르기 제거 |

## 6. 단계

1. **데이터 정리** — 옛 `docent_brief` 정정(§8), 02·06 턴 문장 7줄 다듬기(§3 실측).
2. **17개 큐 저작** — 시연 순서대로 네 묶음, 묶음마다 검수받고 다음으로 간다:
   ① 01·03·04·05 ② 07·08·09·10 ③ 11·12·13·14 ④ 15·16·17·18·19.
   조사 파일(facts·corrections·수준 briefs)을 근거로 제가 초안을 쓰고 문장마다 근거 등급을 단다. 턴 수는 큐마다
   1~3(내용이 적은 09·19 같은 큐는 1턴). 사회자 대사는 기존 `mc`·`mc_after` 를 살리고 `ask` 만 새로 쓴다.
   큐별 `guard` 는 조사 파일에 넣고 큐시트로 접는다(멱등성 테스트가 둘이 어긋나는 것을 잡는다).
   검수본은 큐시트에서 뽑은 읽기용 표로 보여 드린다(질문 → 수준별 설명, 근거 등급).
3. **한 번에 전환** — §5 코드, §3·§9 테스트, §4, §10 문서.
4. **시뮬 검증** — §11.

저작 중(1~2단계)에는 코드가 이번 세션의 중간 상태 그대로다 — 턴이 생긴 큐는 설명을 씨앗으로 실시간 생성하고
나머지는 옛 경로로 돈다. 시연은 3단계 뒤에 한다.

## 7. 콘텐츠 — 02·06

턴 문장은 이미 `data/cues.yaml` 에 들어가 있다(계획 이전 판 §4·§5 그대로, 근거 등급은 조사 파일 facts).

## 8. 옛 최상위 `docent_brief` 정정

런타임엔 안 읽히지만 사람과 앞으로의 큐시트 지식 검색이 믿는 필드다. 조사 파일 corrections 를 전부 읽고
판정했다 — **틀림**만 고친다.

| 큐 | 고칠 것 → 바꿀 말 | 근거 |
|---|---|---|
| 01 | '교육·홍보, 자료 보존, 연구를 위해' → '전파의 효율적 관리와 방송·통신·전파 진흥, 인력양성을 위해' | C0 |

| 03 | '단위는 주파수, 표기는 헤르츠' → '물리량은 주파수, 단위는 헤르츠' | C0 |
| 06 | 10개 대역 → 개수 없이 '차례로 구간을 나눠 이름을 붙였다' / '대역 이름은 파장 길이와 연관' → '범위가 파장으로 100km~1mm' | C0·C2 |

### 12.1 지금 구현 (실측)

| 층 | 지금 | 빈 곳 |
|---|---|---|
| 대본 | 문장만 있다 | 감정을 적을 자리가 없다 |
| 감독 → 로봇 | `say{cue_id, text, seq}` + `gaze{target}` (`stage/machine.py::speak`) | 감정 필드 없음 |
| 로봇 수신 | `stage_client._on_raw` — say 의 **모르는 필드는 무시**, 모르는 메시지는 경고하고 버림. hello 에 `caps` 로 기능 협상(지금 "camera") | — |
| 로봇 모션 | `session.speak(text, …, category=None)` → `motion.classify(text)` 가 **키워드로 7범주를 추측** → 녹화 모션 1개 + 그 모션의 짧은 발성 1.2초(`sound.REACTION_S`) | 추측이라 대본의 감정과 어긋난다 |
| 모션 재료 | Pollen 감정 라이브러리 85개. `motion.CATEGORY_MOVES`(7범주), `emotions.EMOTION_MOVES`(18감정) | 무대 모드는 7범주만 씀 |
| 목소리 | 역할별 고정 화자·배속·어조(`main.ROLE_VOICE`: 사회자 "밝고 활기차게", 도슨트 "차분하게"). Qwen3-TTS 는 요청마다 `instructions` 를 받는다 | 문장마다 어조를 못 바꾼다 |
| 시선 | 감독은 대사마다 partner/audience 를 보낸다 | **로봇이 무시한다**(`main.py` `on_gaze=lambda t: print(...)`) |
| 대시보드 | 송신 명령의 필드를 그대로 받는다(`server.py` `_publish("sent", …)`) | 감정을 보여 줄 자리 없음 |

결론: 감정을 **표현하는 끝단**(모션 재생·어조 지시)은 이미 있다. 빠진 것은 대본의 감정 자리, 그것을 로봇까지
싣는 필드, 로봇이 추측 대신 그 값을 쓰는 연결이다.

### 12.2 감정 어휘 (안 — 결정 필요)

| 태그 | 로봇 모션 범주 → 녹화 모션 | 목소리 어조(스위치 뒤) | 쓰임 |
|---|---|---|---|
| 반가움 | greet → welcoming1, cheerful1 | 반갑게 인사하듯 | 오프닝 |
| 기쁨 | joy → laughing1, enthusiastic1, success1 | 즐겁고 신나게 | 받아치기, 맞장구 |
| 놀람 | surprise → surprised1, amazed1 | 깜짝 놀란 듯이 | 반전 사실 |
| 궁금 | curious → curious1, inquiring1, thoughtful1 | 궁금해하며 묻듯이 | 사회자 질문 |
| 뿌듯 | **proud(신규)** → proud1~3 | 자랑스럽게 | 도슨트의 "재밌는 부분" |
| 끄덕 | ack → yes1, understanding1, attentive1 | 차분하게 맞장구치듯 | 설명 이어받기 |
| 아쉬움 | **sad(신규)** → sad1, downcast1 | 조금 아쉬운 듯 | 타이타닉 같은 무거운 소재 |
| 설명 | 모션 없음(말할 때 흔들림만) | 역할 기본 어조 | 기본값 |

모션 이름은 전부 라이브러리 실측 목록(`emotions.py`)에 있다. 태그 목록은 감독과 로봇 앱 **두 벌**이다(로봇 앱은
`stage/` 를 import 못 한다) — 둘이 같은지 테스트로 묶는다.

### 12.3 대본 스키마 (턴 형식에 더한다)

```yaml
- id: 02-history
  mc: "..."
  mc_emotion: 반가움          # 선택, 없으면 설명
  mc_after: "..."
  mc_after_emotion: 기쁨
  points:
    - answers: {...}
      answer_emotion: 뿌듯    # 도슨트 — 수준 공통
    - ask: "..."
      ask_emotion: 궁금       # 사회자
      answers: {...}
      answer_emotion: 놀람
      listener_emotion: 놀람  # (선택 범위) 도슨트가 말하는 동안 사회자의 반응
```

- 감정은 **한 줄에 하나, 수준 공통**. 모르는 태그는 `load_cues` 가 거절한다.
- 인라인 태그("[놀람] 와!")는 쓰지 않는다 — 파싱을 빠뜨리면 TTS 가 태그를 읽는다. 필드로 가르면 그 사고가 불가능하다.
- 고정 대사도 감정을 갖는다: 질문 확인 멘트(`QA_ACK_LINES`) 기쁨·궁금, 재질문(`QUESTION_PROMPTS`) 궁금.
  관람객 질문 답(gemma 생성)은 첫 판에서 `설명` 고정 — 생성물에 태그를 붙이게 하면 형식 이탈 위험이 있다.

### 12.4 친근한 말투 (저작 규칙)

- 사회자 질문: **반응 한 마디 + 질문**("와, 원래 있던 거였다니 신기하네요! 그럼 …?"). 반응은 직전 설명의 사실을
  되풀이하지 않는다(사실을 먼저 말하면 확인형 대화로 돌아간다). 60자 안팎. 사회자 대사는 수준 공통이므로
  **반응은 네 수준의 직전 설명 모두에 맞아야 한다** — 한 수준에만 나온 내용("텅 빈 우주")에 반응하지 않는다.
- 도슨트 설명: 답을 먼저, 이어서 이유·예. 친근한 어미를 섞는다(~거든요·~잖아요·~더라고요·~죠). 초등은 "여러분"
  호명과 비유. 전문가도 '~입니다' 일변도가 아니게 '~예요' 와 섞는다.
- 감탄사는 태그와 맞춘다(놀람↔와·우와, 기쁨↔하하, 아쉬움↔안타깝게도).
- **체험관 운영 기관은 모든 수준에서 정식 명칭 '한국방송통신전파진흥원' 으로만 부른다.** 약칭 KCA·"운영 기관"·
  "공공기관" 같은 이름 없는 표현으로 대신하지 않는다(Q&A 2026-09-22). 초등·중고등의 "기관 이름을 말하지 않는다"
  규칙은 이 기관만 예외다(`levels.yaml` sources). 역사 서술에서 조심할 것: 이 이름은 2011년부터다
  (`_kca-history.yaml`) — 16-inspection 의 "1981년부터 무선국 검사" 는 조사 파일이 허용한 표현이지만, 전문가
  수준에서는 "당시 한국무선종사자협회에서 시작해" 를 덧붙인다. 박제: `tests/test_stage_cues.py::
  test_데이터_고정_대사에_약칭_KCA가_없다`, `tests/test_prompts.py::
  test_모든_역할과_수준의_프롬프트가_기관_정식_명칭을_지시한다`(관람객 답 생성은 페르소나 규칙이 이끈다).
- 테스트로 박는 것: 태그가 어휘 안에 있다, 사회자 질문이 물음표로 끝난다(있음), 한 큐 안 사회자 대사의 감정이
  세 번 연달아 같지 않다(단조로움 방지). "친근함" 자체는 검수로 본다.
- 분량: 반응·감탄사가 붙어 길어진다. 저작해 보고 `levels.yaml` point 글자 상한을 실측으로 조정한다.

예시 — 02-history 1턴, 중고등:
- 사회자(궁금): "와, 원래 있던 거였다니 신기하네요! 그럼 눈에 안 보이는 전파를 어떻게 찾아낸 거예요?"
- 도슨트(뿌듯): "그게 이 이야기의 재밌는 부분이에요. 맥스웰이라는 과학자가 먼저 수식만으로 '이런 파동이 있을
  거야' 하고 예언했거든요. 그리고 헤르츠가 실험으로 진짜 있다는 걸 처음 증명했죠."

### 12.5 프로토콜·로봇 앱 (재배포 필요)

- 감독: `say` 에 `emotion` 을 싣는다. 로봇 hello 의 `caps` 에 `"emotion"` 이 없으면 접속 때 한 번 경고
  ("이 로봇 앱은 감정 표현을 모른다 — 재배포 필요").
- 로봇: `stage_client` 가 `emotion` 을 읽어 `on_say(…, emotion)` → `session.speak(category=…)`. 태그가 없거나
  모르면 지금처럼 `classify` 추측 + 경고. `CATEGORY_MOVES` 에 proud·sad 추가. `설명` 은 모션·발성 없음.
- 목소리 어조: `instructions` = 역할 기본 어조 + 감정 한 줄. **요청마다 지시문이 달라지면 음색·음높이가 흔들릴 수
  있다**(추측 — lessons 의 Qwen3-TTS 항목들). 그래서 `REACHY_EMOTION_TTS`(기본 꺼짐) 뒤에 두고, 같은 문장 × 감정
  8개 청취 비교(음높이·음색·첫 소리 지연) 뒤에 기본값을 정한다.
- 대시보드: 대사 옆에 감정 배지. `sent` 이벤트에 필드가 이미 실려 온다.
- 배포 순서 무관: 감독만 새것이면 옛 로봇은 필드를 무시하고 추측 모션으로 돈다. 로봇만 새것이면 감정이 안 오니
  추측한다. 어느 쪽도 멈추지 않고, caps 경고가 "반쯤 배포됨" 을 알린다.

### 12.6 더 능동적인 대담 (선택 범위 — 결정 필요)

- **시선**: 로봇이 `gaze` 를 실제로 따른다 — "상대에게 묻고, 관객에게 설명" 이 몸으로 보인다. 로봇마다 상대가
  어느 쪽인지(`REACHY_PARTNER_SIDE=left|right`, 실기 배치 정보라 config 사다리), driver 의 흔들림 층에 머리 yaw
  오프셋(작은 각도, 부드럽게). 시뮬 2대는 MuJoCo 가 없어 `GET /api/state/full` 로 머리 yaw 를 되읽어 확인한다.
- **듣는 쪽 반응**: 한 로봇이 말하는 동안 다른 로봇이 끄덕·놀람 모션을 한다. 새 메시지 `react{emotion}` —
  옛 로봇은 모르는 메시지를 버리므로 caps `"react"` 가 있을 때만 보낸다. **발성 없이 모션만**(상대 발화 위에
  소리가 겹치면 안 된다). 대본의 `listener_emotion` 이 정한다. 로드맵 4단계("도슨트 발화 중 사회자 듣는 모션")와 겹친다.

### 12.7 단계 재구성

저작은 6개(01~06)만 끝났다 — 말투를 바꾸기에 가장 싼 시점이다.

1. 감정 어휘·선택 범위 확정(Q&A) → 스키마·검증·테스트.
2. 저작 6개를 친근체 + 감정 태그로 다시 쓴다 → 검수(말투 기준을 여기서 확정).
3. 나머지 13개를 새 스타일로 저작(묶음 검수) — §6 의 2단계를 대신한다.
4. 감독 전환(§5) + `say.emotion` + caps 경고 + 대시보드 배지.
5. 로봇 앱: 감정 → 모션, proud·sad, 어조(스위치 뒤), 선택 범위(시선·듣는 반응).
6. 실측·검증: 어조 청취 비교, 시뮬(로그 `[모션 범주/이름]`·`/api/state/full`), 실기 재배포.
