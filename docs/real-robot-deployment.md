# 실기(Reachy Mini) 배포 전 검증

- 검증일: 2026-07-30(1차) · 2026-08-11(2차, SDK 소스 대조)
- **실기가 없으므로 정적 분석 + 이 맥에서 재현 가능한 실험으로만 확인했다.**
  하드웨어가 필요한 항목은 아래 "미검증"에 따로 적었다.

## 배포 대상 — **Reachy Mini Wireless** (2026-08-11 구매 확정)

이게 정해져야 아래 판단이 갈린다. Wireless 는 다음을 뜻한다.

- **앱이 로봇 위에서 돈다.** 온보드 **CM4104016 — RAM 4 GB / eMMC 16 GB**(Pi 5 아님).
  추론 3종은 PC 에 남는다. 온보드 sLLM 은 RAM 4 GB 라 애초에 성립하지 않는다.
- **주소 3종이 네트워크를 탄다.** WiFi 안테나는 2.79 dBi 패치 하나 — 타임아웃 설계가
  loopback 전제로 남아 있으면 안 된다(아래 7번).
- **USB 데이터 연결이 없다.** Wireless 의 USB-C 는 출력(호스트) 방향이라 랩톱 직결이
  안 된다. 접속은 로봇 자체 AP / 내부 무선망 / USB-C→이더넷 셋 중 하나다.
- 오디오 장치는 **XMOS XVF3800**(하드웨어 AEC·리니어-4 마이크·DoA 180°).
  `REACHY_AEC` 는 시뮬 전용이므로 실기에서 켜지 않는다.

## 1. [차단] 실기가 실행하는 앱에 음성대화가 없다

`pyproject.toml` 의 엔트리포인트는 이렇다:

```toml
[project.entry-points."reachy_mini_apps"]
voice_chat = "voice_chat.main:VoiceChat"
```

그런데 `main.py` 의 `VoiceChat.run()` 은 **`reachy-mini-app-assistant create` 가 만든
템플릿 그대로**다 — 머리를 사인파로 흔들고 안테나를 움직이고, 설정 페이지에서
버튼을 누르면 `wake_up.wav` 를 재생하는 것이 전부다. STT·LLM·TTS·VAD 어느 것도 없다.

**음성대화 앱 전체는 `demo.py` 에 있고, 그건 `ReachyMiniApp` 이 아니라 독립 실행
스크립트다**(`if __name__ == "__main__"` + argparse). 즉 로봇에 설치하면
**머리만 흔드는 앱이 돈다.**

→ `demo.py` 의 루프를 `VoiceChat.run(reachy_mini, stop_event)` 안으로 옮겨야 한다.
`stop_event` 기반 종료, `ReachyMini` 인스턴스를 **주입받는 형태**(현재 `demo.py` 는
직접 `ReachyMini()` 를 컨텍스트로 잡는다)로 바꾸는 것이 핵심이다.

## 2. [차단] 마이크가 안 열린다 — `osxaudiosrc`

`audio_in.MicCapture` 의 파이프라인:

```python
Gst.parse_launch(
    "osxaudiosrc ! audioconvert ! audioresample "
    ...
```

`osxaudiosrc` 는 macOS 전용이다. 실기(CM4/Linux)에는 없어 `Gst.parse_launch` 가 실패한다.

이 맥에서 엘리먼트 존재 여부를 조회한 결과:

| 엘리먼트 | 이 맥 |
|---|---|
| `osxaudiosrc` | 있음 |
| `autoaudiosrc` | **있음** |
| `alsasrc` / `pulsesrc` | 없음 (Linux 전용) |

**`autoaudiosrc` 로 바꾸면 된다** — 플랫폼에 맞는 소스를 GStreamer 가 고른다.
이 맥에서 같은 파이프라인으로 실제 캡처가 성공하는 것까지 확인했으므로
**시뮬 쪽 회귀 없이 한 단어만 바꾸면 되는 수정**이다.

## 3. [차단] 의존성이 선언돼 있지 않다

`pyproject.toml` 의 `dependencies = ["reachy-mini"]` 뿐인데, 실제로 앱이 쓰는 외부
패키지는 다음과 같다:

```
numpy, requests, sounddevice, pydantic, gi(PyGObject), reachy_mini
```

로봇에 설치하면 `import numpy` 부터 깨진다. 시뮬에서는 `.venv` 에 이미 다 깔려 있어
드러나지 않았다.

## 4. [높음] TTS 가 실패하면 **소리 없이 벙어리가 된다**

폴백 사다리가 macOS 전용이다.

- `tts.Speaker._worker` — qwen 실패 시 `["say", "-v", voice]`
- `tts._afplay` — 스트림을 못 열면 `["afplay", ...]`

Linux 에는 둘 다 없다. `subprocess.run` 이 `FileNotFoundError` 를 던지고
`_worker` 의 `except Exception: pass` 가 삼킨다.

재현했다 — 폴백 명령을 없는 경로로, TTS 서버를 닫힌 포트로 두고:

```
재생된 오디오: []        (아무 소리도 안 났다)
워커 생존=True, 0.02초
```

**로그도 안 남는다.** 실기에서 TTS 서버가 죽거나 WiFi 가 끊기면 로봇이 조용해지고,
운영자는 이유를 알 방법이 없다.

→ 최소한 실패를 **로그로 남겨야** 한다. 폴백 음성이 필요하면 Linux 경로
(`espeak-ng` 등)를 두거나, `reachy_mini.media.play_sound()` 로 "지금 대답할 수 없어요"
같은 사전 녹음을 재생하는 편이 현실적이다.

## 5. [높음] STT·LLM 주소를 설정으로 못 바꾼다

실기 토폴로지는 **앱이 로봇에서, 추론은 PC 에서** 도는 것이다. 그러면 세 주소가
전부 PC 를 가리켜야 하는데, 환경변수를 지원하는 것은 TTS 하나뿐이다.

| | 기본값 | 환경변수 |
|---|---|---|
| TTS | `127.0.0.1:8099` | `TTS_QWEN_URL` ✓ |
| STT | `127.0.0.1:8090` | **없음** |
| LLM | `127.0.0.1:8080` | **없음** |

`docs/demo-runbook.md` 는 "오디오 백엔드·TTS·서버 주소 3가지만 바꾸면 같은 코드가
실기에서 돈다"고 적었지만, 실제로는 **`stt.py`·`llm.py` 를 고쳐야 한다.**
`REACHY_STT_URL` / `REACHY_LLM_URL` 을 받게 하면 코드 수정 없이 끝난다.

## 6. [중간] 운영 스크립트가 macOS 전용

- `reachy.sh`: `install_name_tool`(rpath 자가치유), `say -v '?'`(상태 점검), `mjpython`(시뮬)

로봇에서는 이 스크립트를 쓸 수 없다. 다만 실기 토폴로지에서 **TTS·LLM·STT 는 PC 에
남으므로** `reachy.sh` 는 PC 쪽 기동 스크립트로 그대로 쓰고, 로봇에는 앱만 설치하는
분리가 자연스럽다. 그 경우 `reachy.sh` 에서 앱 실행 부분만 떼면 된다.

## 7. [중간] 네트워크가 끊기면 오래 매달린다

`tts.QWEN_TIMEOUT` 기본값이 **90초**다. 같은 파일 주석에 이유가 있다 —
"타임아웃으로 연결을 끊으면 서버가 그 소켓에 쓰다 죽는다(실측)".

로컬호스트에서는 타임아웃이 날 일이 거의 없어 안전한 값이었지만, **WiFi 를 타면
사정이 다르다.** 끊기면 한 발화가 90초를 매달리고, 짧게 잡으면 서버가 죽는다.
실기 이전 시 이 균형을 다시 봐야 한다(서버 측 수정이 필요할 수도 있다).

## 8. [차단→고침] SDK 와 오디오 장치를 이중 점유한다

`main.py` 의 `request_media_backend` 가 `None` 이었다. 이 값은 SDK 에서 `"default"` 로
해석돼(`apps/app.py:46-50`) LOCAL 또는 WEBRTC 미디어 백엔드가 뜬다
(`reachy_mini.py:355-368`). 그 상태면 **데몬이 마이크·카메라를 쥐고 있는데**
`audio_in.MicCapture` 가 `autoaudiosrc` 로 같은 장치를 또 연다. USB 오디오는 보통
캡처 클라이언트를 하나만 받는다.

SDK 에 정확한 탈출구가 있다:

```python
# reachy_mini.py:342-350
if media_backend.lower() == "no_media":
    if not getattr(daemon_status, "no_media", False) and not self._media_released:
        self.release_media()
```

`release_media()` 의 docstring 이 우리 설계를 그대로 적는다 — *"After calling this,
the camera and microphone are available for direct access via OpenCV / **sounddevice**
/ etc."* 앱이 끝나면 `ReachyMini.__exit__` 이 `acquire_media()` 로 되돌리므로
데몬 상태를 남기지 않는다(idempotent).

→ **`request_media_backend = "no_media"`.** 영상 스트리밍을 안 쓰는 만큼 CM4 의 CPU 도
같이 아낀다. 박제: `tests/test_deployment_contract.py`(SDK 가 분기 문자열을 바꾸면 실패).

## 9. [차단→고침] `PyGObject` 를 조건 없이 선언했다

`pyproject.toml` 이 `"PyGObject"` 한 줄이었다. reachy-mini 자신은 이렇게 갈라 둔다:

```
PyGObject<=3.46.0,>=3.42.2 ; sys_platform == "linux"
gstreamer-bundle==1.28.3   ; sys_platform != "linux"
```

즉 비-Linux 에서 `gi` 는 `gstreamer_bundle` 이 공급한다. 조건 없는 선언은
macOS/Windows(Lite 구성 — 데몬·앱이 PC 에서 돈다)에서 pip 를 PyGObject 소스 빌드로
몰아 설치를 깨뜨리고, 상한이 없어 3.46 초과가 잡히면 SDK 핀과 충돌한다.

→ **`PyGObject>=3.42.2,<=3.46.0; sys_platform == 'linux'`.** 비-Linux 는 SDK 가 끄는
`gstreamer-bundle` 에 맡기고 재선언하지 않는다(정확 핀이라 충돌만 만든다).
빌드한 휠 METADATA 로 확인했다. 박제: 위와 같은 파일 — SDK 핀이 바뀌면 실패한다.

## 10. [높음→고침] 환경변수가 데몬 유닛에 없으면 조용히 loopback 으로 붙는다

앱은 데몬 프로세스의 환경을 상속한다(`apps/manager.py:159` `app_env = os.environ.copy()`).
Wireless 에서 데몬은 **systemd 유닛**이므로, 운영자가 셸에서 `export REACHY_LLM_URL=…`
해도 앱은 못 본다. 유닛 드롭인을 고쳐야 하는데 그건 SDK 업데이트가 덮어쓴다.
공개 레퍼런스도 같은 자리에서 소스를 패치해야 했다.

나쁜 건 **실패가 조용하다**는 것이다 — 기본값 `127.0.0.1` 로 붙어 STT 는 빈 문자열,
LLM 은 예외 후 폴백 한 줄. "실패는 소리 내서 실패한다" 규칙에 걸린다.

→ **고침(2026-08-11).** 둘을 넣었다:

1. **설정 사다리** (`config.py`) — `환경변수 → 설정파일 → 기본값`. 파일 위치는
   platformdirs(SDK 가 이미 의존) 기준이라 앱 재설치에도 살아남는다:
   ```
   ~/.config/reachy-mini-voice-chat/config.json           # 실기(Linux)
   {"REACHY_LLM_URL": "http://<PC>:8080",
    "REACHY_STT_URL": "http://<PC>:8090/v1/audio/transcriptions",
    "TTS_QWEN_URL":   "http://<PC>:8099/v1/audio/speech"}
   ```
   키 이름은 환경변수와 같다(정신 모델 하나). 환경변수가 언제나 이긴다.
   깨진 파일은 **경고 후** 기본값 — 조용히 무시하면 이 절이 막으려는 상황이 된다.
2. **기동 고지** (`session.announce_endpoints`) — 세 주소와 출처(환경변수/설정파일/
   기본값)를 첫 줄에 찍고, **Linux(실기)에서 loopback 이면 크게 경고**한다.
   시뮬(맥)에서는 loopback 이 정답이라 경고하지 않는다.

박제: `tests/test_config.py` 8건. `custom_app_url` 설정 페이지는 여전히 열려 있는
다음 단계다(지금은 파일 편집으로 충분하다).

## 11. [높음→고침] TTS 24 kHz 출력 vs 장치 16 kHz

`tts.QWEN_PCM_RATE = 24000` 으로 PortAudio 스트림을 열었다. 그런데 탑재 펌웨어
`ua_io16_lin` 의 `io16` 은 **USB 입출력 16 kHz** 를 뜻하고, SDK 도
`media/audio_base.py:59` 에서 `SAMPLE_RATE = 16000`,
`get_output_audio_samplerate() → 16000` 이다.

24k 스트림을 못 열면 `_afplay` 폴백으로 떨어진다 — 절마다 프로세스 기동이
**길이와 무관하게 0.8초 고정비**라(실측) 스트리밍으로 번 첫 청크 0.23초가 통째로
사라진다. 소리는 나지만 대화 리듬이 무너진다.

**TTS 서버에 16k 를 요청하는 길은 안 된다** — Qwen3-TTS 출력은 24 kHz 고정이다.
그래서 우리가 맞춘다.

→ `tts._open_output()` 이 **원본 레이트를 먼저 시도**하고(맥에서는 그대로 열려
리샘플이 안 낀다 — 시뮬 회귀 없음), 안 되면 `16000 → 48000 → 44100` 으로 내려가며
`tts._Resampler` 를 세운다. 물러날 때는 경고를 남긴다.
`REACHY_TTS_OUT_RATE=16000` 으로 탐색을 건너뛸 수 있다.

리샘플러는 **청크 경계에서 필터 상태를 잇는다.** `scipy.signal.resample_poly` 를
청크마다 부르면 상태가 매번 0 에서 시작해 85ms 마다 클릭이 난다. numpy 만 쓰고
(새 의존성 없음) 비용은 실시간 대비 **0.05%**, 청크당 0.042ms 다(이 맥 실측).

**남은 미검증**: 로봇 스피커가 PortAudio 로 잡히는지 자체는 여전히 확인 대상이다
(미검증 1번). 잡히기만 하면 레이트는 이제 맞춰진다.

## 12. [중간→고침] 사용자 발화 중에도 모터가 돈다

XVF3800 의 AEC 는 **스피커 반향**을 지우지 별개인 **모터 소음**은 지우지 않는다.
그런데 `driver.RobotDriver` 가 100 Hz 로 **항상** 목표를 쓴다 — 모션이 없어도
호흡(`animator.BREATH_*`)으로 계속 움직인다("illusion of life"). `Idler` 는 소리 없이
대기 모션을 돌리는데 그때도 서보 9개는 돈다.

시뮬에는 모터 소음이 없어 구조적으로 안 드러난다. 실기에서는 VAD 적응 임계와
끼어들기 결합계수 추정이 모터 소음을 소음 바닥으로 학습해 흔들린다.

→ **고침(2026-08-11).** `voice_loop` 이 매 프레임 `vad.active`(발화 수집 중)를
`player.set_user_speaking()` 으로 넘기고, 그러면:

- **sway·호흡이 접힌다** — `RobotDriver` 의 정숙 포락선(접기 0.15s / 펴기 0.5s,
  급정지 아님). 완전히 접히면 매 틱 같은 중립 자세를 보내 서보가 그 자리에 선다
  (목표 송신은 계속 — 루프 생존 규칙 유지).
- **대기 모션은 돌던 것도 끊는다** — 혼자 노는 동작이 사용자 발화보다 우선일 수
  없다. **응답 모션은 두다** — 로봇 발화 턴과 겹치는 정당한 동작이다.
- **Idler 가 새 대기 모션을 시작하지 않는다.**

스위치는 `REACHY_MOTOR_QUIET`(기본 **켬**). `REACHY_AEC` 와 방향이 반대인 이유:
실기에서만 필요한 것을 꺼짐 기본으로 두면 실기에서 켜는 걸 잊는다.
박제: `tests/test_driver.py` 정숙 4건 + `tests/test_motion.py` 3건.

덤으로 잡은 것: 드라이버 스레드의 SDK 지연 임포트가 **기동 직후 수백 ms 동안
루프를 굳혔다**(vision→huggingface_hub→filelock 연쇄, 스레드 스택 샘플로 실측).
모듈 상단 임포트로 옮겼다 — main.py 가 어차피 SDK 를 먼저 올리므로 비용 0이다.

## 13. [차단→고침] `no_media` 가 감정 모션 발성을 죽였다

§8 의 부작용이다. SDK 의 `play_move(sound=True)` 는 `media_manager.play_sound()` 로
발성을 내는데, `no_media` 면 `MediaManager.audio` 가 None 이라
*"Audio system is not initialized."* 경고 한 줄만 남기고 **조용히 무시한다**
(`media/media_manager.py:271`). 감정 라이브러리 85개 중 **84개가 `.ogg` 를 갖고
있고, 우리가 쓰는 17개는 전부** 갖는다 — 응답 모션이 전부 무음이 될 뻔했다.

→ 발성을 우리 재생 경로로 옮겼다(`sound.py` → `tts.Speaker.play_sound`). 되돌리는
것(=`no_media` 철회)은 답이 아니다 — §8 의 장치 이중 점유가 돌아온다.

옮긴 편이 원래보다 낫다. 셋이 따라온다:

1. **게이팅이 사운드 길이를 따라간다.** 예전에는 `player.busy`(=모션 길이)를 봤는데
   **9개 모션은 사운드가 모션보다 길다**(실측, 최대 `welcoming1` +1.43초). 그동안
   마이크가 자기 발성 꼬리를 주웠고 `POST_PLAYBACK_GUARD_S=0.3` 으로는 못 덮었다.
2. **끼어들기가 모션 구간에도 동작한다**(§14).
3. 발성이 §11 의 리샘플러를 타므로 실기 16 kHz 장치에서도 그대로 난다.

**길이 정책**: 리액션 발성은 2~12초라 답변 앞에 통째로 붙이면 대화가 그만큼 늦는다.
발성의 원래 역할이 LLM 지연 구간을 메우는 것이므로 앞 1.2초만 쓰고 페이드아웃한다
(`REACHY_MOTION_SOUND_S`). 공연(춤)은 요청 자체가 목적이라 16~19초 전체를 낸다.

## 14. [중간→고침] 응답 모션 동안 로봇이 귀머거리였다

`voice_loop` 가 `speaker.speaking` 과 별개로 `player.busy` 를 보고 프레임을 통째로
버렸다. 춤은 17~18초라 **끼어들기를 켜 놔도 그동안은 "미니야"조차 안 들렸다.**

원인은 모션 발성이 SDK 미디어로 나가 우리 에코 추정에 안 잡혔다는 것뿐이다.
§13 으로 발성이 `speaker` 를 타면서 `_note_output`·에코 프로브에 들어오므로
`player.busy` 하드 게이팅을 걷어냈다. 끼어들기가 걸리면 `player.cancel()` 로
**몸도 함께 멈춘다** — 소리만 끊고 18초를 마저 추면 끊긴 것이 아니다.

## 15. [2대 구성] 사회자·도슨트 — 실기에서만 드러나는 것들

설계는 `docs/superpowers/specs/2026-09-11-two-robot-mc-docent-design.md`,
운영 절차는 `docs/two-robot-setup.md`. 여기에는 **실기가 없으면 확인할 수 없는
위험**만 적는다. 시뮬(mockup 2대)에서 도는 것은 근거가 아니다.

### 15.1 코드 수정 없이 옮겨지는가 — 배선 점검

| 항목 | 실기에서 가는 길 |
|---|---|
| `REACHY_ROLE` · `REACHY_DIRECTOR_URL` | **로봇 `config.json`** (`./reachy.sh robot up` 이 써 넣는다) |
| `REACHY_LLM_URL` · `REACHY_STT_URL` · `TTS_QWEN_URL` | 같은 파일 (§10 과 동일) |
| `REACHY_MC_UNIT` · `REACHY_DOCENT_UNIT` | **노트북 셸** — 감독이 노트북에서 직접 도는 프로세스라 export 가 먹는다 |
| 역할별 음성(`serena`/`sohee`) | `main.py` 가 넣되 사다리에 사람이 적은 값이 있으면 비켜난다 |
| `REACHY_PARTNER_SIDE`(`left`/`right`, 기본 `right`) | **로봇 `config.json`** — 로봇마다 다르다(§15.3). 오타는 경고하고 기본값으로 간다 |
| `REACHY_EMOTION_TTS`(기본 **꺼짐**) | 같은 파일. 켜면 감정 어조가 TTS `instructions` 에 실린다(§15.7) |

셸 export 로는 로봇의 앱에 아무것도 닿지 않는다 — 앱이 데몬의 자식이기 때문이다
(`docs/lessons.md` 의 "실기의 앱 설정은 `config.get()` 을 타지 않으면 절대 닿지 않는다").
기동 로그의 `역할: mc (설정파일)` 에서 **출처**를 확인한다. `(기본값)` 이면 안 닿은 것이다.

### 15.2 잔여 위험 — 실기에서 처음 드러난다

1. **감독의 진입 락이 블로킹 `ws.send` 를 쥔 채로 넘어간다.**
   `Director._emit()` → `StageServer._send()` → `ws.send()` 가 `Director._lock` 안에서
   일어난다. WiFi 가 흔들려 한쪽 소켓의 송신 버퍼가 차면 **그 send 가 블록되는 동안
   감독 전체가 멈춘다** — `tick()` 도, 다른 로봇의 보고도 처리되지 않는다.
   시뮬은 loopback 이라 send 가 사실상 즉시 끝나 절대 재현되지 않는다.
   - 관측 방법: 감독이 몇 초씩 아무 로그도 안 내면 이것이다.
   - 고치려면 역할별 송신 큐 + 송신 스레드를 둔다. 지금은 **안 했다** — 동시성
     핵심을 시연 직전에 건드리는 쪽이 더 위험하다고 판단했다.
   - **얼마나 쉽게 나는가(2026-09-20 측정)**: 맥 기본 `SO_SNDBUF` 는 131072 바이트,
     감독이 보내는 `say` 한 통은 328 바이트다 — 실제로 막히려면 **약 400통**이
     밀려야 하는데 19섹션 시연 전체가 80통 남짓이다. 즉 이 workload 에서는 거의
     도달하지 않는다. 게다가 websockets keepalive(`ping_interval=20`/
     `ping_timeout=20`)가 죽은 피어를 ~40초 안에 끊어 send 를 예외로 풀어 준다.
     이 숫자 때문에 연결별 송신 스레드를 **보류**했다. 되돌릴 설계는
     `docs/superpowers/plans/2026-09-20-director-lock-io-split.md` 에 남겨 뒀다.

2. ~~**같은 락을 `_answer()` 의 LLM 왕복 전체가 쥔다.**~~ — **고쳤다(2026-09-14, 리뷰 C1/B3).**
   질문 응답 생성이 도슨트 해설과 같은 생성 슬롯에서 스레드로 돈다. 그동안 사회자가 확인
   멘트(`QA_ACK_LINES`)를 말한다.

2b. ~~**유예 대기(최대 8초)도 같은 락 안이라 비상정지가 그만큼 먹통이다.**~~ —
   **고쳤다(2026-09-20).** `on_speaking_ended()` 가 대기 전에 락을 놓고, 깨어난 뒤
   상태(`abort` → IDLE)와 세대 토큰(다음 큐·질문)을 다시 보고 얹는다. 역할(`_who()`)도
   그때 다시 정해, 기다리는 사이 상대가 끊기면 남은 한 대가 읽는다.
   근거와 박제는 `docs/lessons.md` 의 "같은 규칙의 나머지 구멍".
   남은 것은 `_emit` 의 `ws.send`(1번 항목)뿐이다.

3. **타임아웃 기준점이 실제 발성 시작이 아니다** — 여유분 15초로 막아 뒀다.
   로봇은 `speaker.speak()` 가 **큐에 넣고 돌아온 직후** `speaking_started` 를 보낸다.
   TTS 합성은 그 뒤에 일어나므로 **감독은 발성 시작을 볼 수 없고**,
   `TIMEOUT_MARGIN_S` 가 그 합성 지연을 통째로 덮는 몫이 된다.
   데드라인이 발성 전에 터지면 `force_listening` 이 리스너 마이크를 열고, 직후 로봇이
   말을 시작해 사회자가 그것을 관람객 발화로 받아적는다 — 불변식 ① 이 막으려던
   자기목소리 루프다.
   - **예전 값 5.0 은 그 몫을 감당하지 못했다.** Qwen3-TTS 첫 합성은 Metal 커널 JIT 로
     **8.5초**가 걸린다(`scripts/warmup.py` 실측). 예열을 건너뛴 첫 큐로 계산하면:

     | 대사 | 예산 (`len/4.0 + 여유`) | 필요 (합성 8.5 + 재생) | |
     |---|---|---|---|
     | 짧은 전환 12자 | 8.0초 | 10.7초 | ❌ |
     | 사회자 대사 34자 | 13.5초 | 14.8초 | ❌ |
     | 긴 해설 57자 | 19.2초 | 19.1초 | ✓ (아슬아슬) |

     짧은·중간 길이가 대부분이라 **거의 확실히** 헛타임아웃이 났다. 운영자가 기억해야
     하는 절차(예열)만으로 막기에는 너무 얇았다.
   - **지금**: `TIMEOUT_MARGIN_S = 15.0`. 10.0 이면 위 셋이 다 통과하지만 여유가 1초뿐이라
     15.0 으로 잡았다. 타임아웃이 **늦게** 터지는 비용은 "멈춘 것을 늦게 알아챈다" 뿐이고
     (운영자가 콘솔 `a`/`r` 로 즉시 복구한다), **일찍** 터지는 비용은 자기목소리 루프다 —
     비대칭이 크다.
   - 예열은 그대로 둔다(`docs/two-robot-setup.md` §7). 상수는 방어선이지 대체재가 아니다.
   - 박제: `tests/test_stage_director.py::test_예열을_빠뜨려도_첫_큐가_헛타임아웃되지_않는다`
     (위 표의 세 경우를 그대로 돌린다 — 5.0 으로 되돌리면 12자·34자가 실패한다),
     `::test_여유분이_차가운_합성을_덮는다`,
     `::test_늘어난_여유분이_타임아웃_자체를_없애지는_않는다`.
   - **이것은 임시 방어선이다.** 제대로 된 고침은 §15.4.

4. ~~**사회자의 STT 는 마이크 게이트가 닫혀 있어도 계속 돈다.** 안전에는 문제가 없다
   (구조로 막힌다). 비용의 문제다.~~ — **틀렸다(2026-09-14, 리뷰 A1).** 게이트가 STT
   결과 시점에만 있어 도슨트의 마지막 문장을 사회자 VAD 가 담아 두었다가, 게이트가 열린
   뒤 전사가 도착해 관람객 발화로 올라갔다 — 도슨트가 자기 말에 답하는 무한 루프였다.
   지금은 `voice_loop(mic_open=...)` 이 **캡처 단**에서 막는다(닫힌 동안 프레임을 버리고
   VAD 를 리셋, STT 호출 없음). STT 낭비도 같이 사라졌다. `make_heard_sink` 는 이중
   방어선으로 남는다. 실기에서 확인할 것: 두 로봇의 스피커 간격에서 도슨트 마지막 문장의
   잔향이 게이트 개방 뒤 0.7초 hangover 안에 VAD 를 다시 깨우는지(항목 7).

5. **`unit_id` 대조가 하드웨어에서 한 번도 안 돌아 봤다.**
   `get_hardware_id()` 가 리눅스 sysfs 를 읽으므로 시뮬에서는 언제나 `None` 이고,
   코드는 그때 **경고 후 통과**한다(그래야 시뮬 개발이 막히지 않는다). 결과적으로
   "값이 있는데 다르면 실패" 쪽 분기는 **실기에서 처음 실행된다.**
   - 시연 전에 일부러 두 로봇의 역할을 바꿔 걸어 **정말 기동이 실패하는지** 본다.
     이 검증이 안 돌면 두 대가 뒤바뀐 채 시연이 시작될 수 있다.

6. **CM4 에서 앱 + WS 클라이언트 동시 구동 시 메모리.** 설계 §10 그대로 미검증이다.

7. **두 스피커 간 음향 간섭.** 턴은 게이팅으로 막지만 잔향은 남는다. 사회자 마이크가
   도슨트의 잔향을 줍는 구간이 `LISTENING` 진입과 겹치면 유령 발화가 생길 수 있다.

### 15.4 발성 경계를 제대로 잡는 법 — 나중에 할 일

`TIMEOUT_MARGIN_S = 15.0` 은 **감독이 발성 시작을 볼 수 없다**는 사실을 상수로 덮은
것이다. 다음 사람이 "왜 여유분이 이렇게 크지" 하고 줄이기 전에 읽어야 할 선택지 둘.

#### ① TTS 워커에 첫-오디오 훅을 낸다 — **구조적으로 옳은 고침**

`tts.Speaker` 의 워커가 실제로 첫 PCM 을 재생 스트림에 밀어 넣는 순간
(`StreamPlayer.play_pcm_stream` 의 prebuffer 가 차서 `primed` 가 서는 지점)에
콜백을 부르고, 로봇이 거기서 `speaking_started` 를 보낸다. 그러면 여유분은
합성 지연이 아니라 **재생 지터만** 덮는 값으로 돌아가고, 5초는커녕 2~3초면 충분해진다.
데드라인이 다시 "발화가 이 정도면 끝났어야 한다" 는 뜻을 갖는다.

- **왜 지금 안 했나**: `tts.py` 의 워커는 이 저장소의 오디오 핵심이고(끼어들기 세대
  번호·프리버퍼·리샘플·에코 프로브가 다 얽혀 있다), 시연을 며칠 앞두고 틀리면 가장 비싼
  자리다. 상수 하나짜리 변경과 위험이 비교가 안 된다.
- 붙일 때 같이 볼 것: `speaking_ended` 는 이미 `wait_idle()` 뒤라 정확하다. 훅은
  **시작 쪽에만** 필요하다.

#### ② `speaking_started` 를 하트비트로 쓴다 — **방향은 맞지만 구멍이 있다**

발화 중 주기적으로 `speaking_started` 를 다시 보내고 감독이 받을 때마다 데드라인을
연장한다. 규약 메시지 9종을 안 늘리고도 데드라인이 "발화 길이 예산" 에서 **"살아 있다는
신호"** 로 바뀐다 — 원래 그랬어야 하는 것이다.

- **구멍**: 합성 안에서 멈춘 로봇은 `_speaking` 플래그가 선 채로 있으므로 **계속
  하트비트를 보낸다.** 그러면 타임아웃이 영영 안 터진다 — 타임아웃이 존재하는 이유
  자체를 무력화한다.
- 쓰려면 **절대 상한**(이 큐에 최대 N초)을 함께 둬야 하고, 그건 상수 하나보다 큰 변경이다.
- 그래서 채택하지 않았다. 다만 ① 을 붙인 뒤에 하트비트를 얹으면 두 신호가 서로를
  보완한다("시작했다" 는 ① 이, "아직 살아 있다" 는 ② 가).

### 15.6 카메라·대기모드는 **두 로봇을 같은 커밋으로 동시에 재배포해야** 어긋나지 않는다

설계는 `docs/superpowers/specs/2026-09-22-dashboard-camera-design.md`. 실기가 없으면 확인할
수 없는 **배포 순서** 위험만 적는다(최종 전체 브랜치 리뷰 I9 — 코드로 막는 것은 후속으로
미뤘다, 아래).

- **카메라는 `caps` 게이트가 있어 옛 앱과 섞여도 조용히 물러난다.** `hello.caps` 에
  `"camera"` 를 싣는 것은 `RtcStreamer(...).available()` 이 True 인 새 앱뿐이다
  (`main.py:409`). 옛 앱(이 기능 이전 커밋)은 애초에 `caps` 를 안 보내거나 `"camera"` 가
  없으므로, `CameraRelay._recompute` 는 그 로봇에게 `camera` 지시를 **아예 보내지 않는다**
  — 대시보드 카메라 칸은 "카메라 없음 — 시뮬이거나 로봇 앱이 카메라를 모른다(재배포
  필요)" 를 띄우고 끝난다. 사회자만 새로 올리고 도슨트를 옛 채로 둬도 **안전하게 반쪽만
  된다** — 이 경로는 실기 확인이 필요 없다(설계가 이미 이렇게 짜여 있다).
- **`standby` 는 같은 게이트가 없다 — 여기가 실제 위험이다.** `Director.toggle_standby`
  는 caps 를 보지 않고 그 역할이 **연결만** 돼 있으면(이번 파도의 I7 수정, 위 참고)
  `standby{on}` 을 보낸다. 로봇이 이 기능 이전 커밋으로 떠 있으면 `stage_client.py` 의
  `_DIRECTOR_MSGS`(그 앱 자신의 옛 프로토콜 상수)에 `"standby"` 가 없어, 받는 즉시
  `감독이 보낼 수 없는 메시지다: 'standby'` 로 **거절하고 아무것도 안 한다** — 로봇은
  잠들지 않고 모터도 그대로 켜져 있다. 그런데 감독·대시보드는 `toggle_standby` 가 이미
  `self._standby.add(role)` 를 해 버렸으므로 그 로봇을 "대기 중" 으로 보고 진행에서
  뺀다. **로봇은 깨어 있는데 감독은 재운 줄 아는 상태 불일치**가 남는다 — 두 로봇을
  다른 시점에 배포하면(예: 사회자만 이번 커밋으로 올리고 도슨트는 다음 날) 실제로 벌어질
  수 있다.
  - **관측 방법**: 대시보드 카드가 그 로봇을 "대기" 로 그리는데 로봇이 여전히 서서
    움직이거나 응답한다면 이것이다. 로봇 로그(`REACHY_ROBOT_HOST=<주소> ./reachy.sh
    robot logs`)에서 `감독이 보낼 수 없는 메시지다: 'standby'` 를 찾는다.
  - **지금의 방어**: 코드 게이트가 아니라 **운영 규칙**뿐이다 — `./reachy.sh start
    --robot` 은 두 로봇에 **같은 커밋**을 배포하는 것을 전제한다(`docs/two-robot-setup.md`
    의 배포 절차). 두 로봇을 따로/다른 시점에 올릴 계획이면 배포 직후 반드시 둘 다의
    `hello` 버전(대시보드 헤더 또는 `GET /api/state/full` 대신 감독 로그의
    `[role] 붙었다 (version=…)`)을 대조해 같은 커밋인지 확인한다.
  - **후속(코드 게이트)**: `standby` 에도 `hello.caps` 게이트(예: `"standby"` 능력)를
    추가해 `toggle_standby` 가 caps 없는 역할은 거절하게 만드는 것 — 이번 파도에서는
    범위 밖으로 미뤘다(I9). 다음에 이 기능을 손댈 때 같이 넣는다.

**카메라 CPU 부하 기준선** — 설계 스파이크 실측(사회자 로봇 192.168.0.4, 2026-09-22,
640x480@15fps): 스트림 켬 전후 전체 CPU(4코어 합) **14.9% → 19.1%(+4.2%p ≈ 코어
0.17개)**. 실기에 재배포한 뒤 이 값과 비교해 부하가 눈에 띄게 더 크면(특히 하드웨어
인코더 `v4l2h264enc` 대신 소프트웨어 인코더로 물러난 경우 — `  [카메라] 하드웨어 H264
인코더가 없다 — … 로 물러난다(CPU 를 문다)` 경고를 로그에서 찾는다) 그 로봇의
`gst-inspect-1.0 v4l2h264enc`(또는 앱 venv 의 PyGObject introspection)로 하드웨어
인코더가 실제로 잡히는지부터 본다.

### 15.7 감정 표현 — 모션은 켜짐, 목소리 어조는 스위치 뒤

설계 §12.5 의 계약. 감독이 `say` 에 `emotion` 을 싣고 로봇이 그것으로 모션을
고른다(예전에는 문장 키워드 추측이었다).

- **모션은 기본 동작이다.** 태그가 없거나 모르면 예전처럼 추측으로 내려가되
  **경고를 남긴다**(`motion.category_for`) — 감독이 옛 버전이면 그 줄이 신호다.
  로봇 `hello` 의 `caps` 에 `"emotion"`·`"react"`·`"gaze"` 를 싣는다. 감독은
  caps 에 없는 기능을 보내지 않으므로, **재배포를 빠뜨린 로봇은 옛 로봇으로
  취급돼 감정이 아예 안 온다**(멈추지는 않는다).
- **목소리 어조는 `REACHY_EMOTION_TTS`(기본 꺼짐)** 뒤에 있다. Qwen3-TTS 는
  요청마다 `instructions` 를 받는데 지시문이 발화마다 달라지면 음색이 흔들릴 수
  있다 — VoiceDesign 에서 실제로 겪은 증상이다(`docs/lessons.md`). 같은 문장 ×
  감정 8개 청취 비교 뒤에 기본값을 정한다. 꺼져 있으면 역할 기본 어조 그대로다.
- 듣는 쪽 반응(`react`)은 **발성 없이 모션만** 낸다 — 상대 발화 위에 리액션
  발성이 겹치면 그 대사를 덮는다. 실기에서는 두 로봇이 떨어져 있어 시뮬보다
  안전하지만, 겹치는 것 자체가 연출 사고라 경로를 가른 것이다(`play_for(idle=True)`).

### 15.8 감정 어휘 18종과 춤 라이브러리 — **로봇 재배포 필요**(2026-09-24)

  감사·작별·권유·멋쩍음)을 "모르는 감정 태그" 로 **매번 경고**하고 키워드 추측으로 돈다 — 멈추지
  않는다. 로그에 이 경고가 보이면 재배포를 빠뜨린 것이다.

### 15.12 교육자료 화면 공연 모드 — 로봇 2대가 말하고 화면은 소리 없이 따라간다(2026-11-12)

**실제 시연은 리치미니 2대가 사회자·도슨트로 각자 소리 낸다.** 교육자료 모션 화면(종이 무대·웹툰·분해도)은 미리보기에서는 큐 음성을
품고 스스로 재생하지만, 공연에서는 **소리를 내지 않고 감독 이벤트를 시계로** 장면을 넘긴다. 로봇 재배포 없음 — 바뀐 것은 PC 의 감독
대시보드와 정적 HTML 뿐이다.

- **조정실 안의 시연 화면(2026-11-13 오후)**: 조정실(`http://127.0.0.1:8778/`) 오른쪽 위에 시연 화면이 있다 — **관람객 수준을 고르고 [공연 시작]을
  누르면 그 자리에서 화면이 바뀌고 로봇을 따라간다.** 머리 줄에 고른 화면과 이유가 나온다. 프로젝터는 [프로젝터로 띄우기](= `/stage/auto` 새 창,
  전체 화면 ⌃⌘F). `run-app.sh` 는 조정실만 연다. 왜: 조정실과 화면이 다른 탭이라 "시연영상과 무대조정이 따로 논다" 였다.
- **화면 고르기 = (수준, 지금 큐)**: 그 수준 전용 화면(일반 종이 무대 19큐 · 초등·중고등 웹툰 · 전문가 분해도 — 웹툰·분해도는 아직 01·02큐 시안)이
  이 큐를 가졌으면 그것, 아니면 **그 수준의 카드 화면**(`/stage/hud` — 19큐 × 4수준 검증 카드, 차례에 맞춰 강조·말풍선). 순서·가진 큐는

### 15.13 외부 API 전용 — 이 PC 에 로컬 모델을 띄우지 않는다(2026-11-13)

**`./run-app.sh` 는 `.env` 에 키가 둘 다 있으면 외부 전용으로 띄운다** — `TTS_ENGINE=elevenlabs REACHY_LLM_ENGINE=openai
REACHY_STT_ENGINE=openai REACHY_LOCAL_MODELS=off ./reachy.sh start --robot`. 로봇 재배포 없음(주소·요청 모양 그대로).

- **왜**: 외부 API 로 돌릴 때도 폴백 자리 때문에 로컬 모델 셋이 떠 있었다 — Qwen TTS(CrispASR, 3.2 GB)·Gemma(llama-server)·Whisper(stt_server).
  외부 호출이 성공하는 한 한 번도 안 쓰이면서 맥의 메모리·발열을 썼다. 사용자 결정: 외부 전용을 `run-app.sh` 기본으로.
- **무엇이 안 뜨나**: `:8081`·`:8091`(llamactl) · `:8098`(CrispASR). 뜨는 것은 게이트웨이(`:8080`·`:8090`, `--no-local`)와 TTS 캐시
  프록시(`:8099`, `--no-local`) — 둘 다 헬스에 `local=off` 표지를 싣고, `./reachy.sh check` 도 "외부 전용" 이라고 찍는다.
- **인터넷이 끊기면**: 대본 공연은 **계속된다** — 고정 대사는 구운 ElevenLabs 캐시에서 나간다(외부 호출 0). 멈추는 것은 즉석 답·음성인식이다.
  - LLM 실패 → 게이트웨이가 경고 한 줄 + 502 → 로봇은 "다시 말해 줄래요" 대사(`session.FALLBACK_LINE`), 감독은 폴백 대사.
  - STT 실패 → 502 → 로봇은 못 들은 것으로 친다(`stt.transcribe` → "").
  - TTS(관람객 답) 실패 → 같은 목소리 안내("잠시 연결이 불안정해서…", 구워 둔 것) 한 번 + 짧은 무음. 로컬 모델 폴백은 **없다** —
    예전 구성의 "5초 늦게 로컬로" 대신 바로 실패 경로다. 끊긴 채 즉석 답까지 하려면 `REACHY_LOCAL_MODELS` 를 빼고(기본 on) 다시 띄운다.
- **로봇의 wav 요청**: 앱 기동 확인(`session.announce_voice` 의 `_qwen_synth("준비")`)과 예열은 스트리밍이 아닌 wav 한 방이라 예전에는 로컬
  CrispASR 로 넘겼다. 외부 전용 프록시는 ElevenLabs 로 만들어 WAV 로 싸 준다(실패면 502 + 경고 — 로봇 기동 로그의 "응답 없음" 으로 드러난다).
  로봇 앱의 그 줄은 여전히 "목소리: Qwen3-TTS '…'" 라고 찍는다(로봇 코드라 재배포 때 고칠 표시 문제 — 소리는 ElevenLabs 다).
- **띄우기 전 정리(`./reachy.sh clean-local --robot|--sim`, `run-app.sh` 가 자동으로 부른다)**: 지난 실행의 로컬 모델(`:8081`·`:8091`·
  `:8098`, 예전 직결 `:8080`·`:8090`)과 설정이 다른 게이트웨이·TTS 프록시(폴백을 낀 것, 실기 대상인데 loopback 으로만 듣는 것)를 내린다.
  같은 설정의 외부 전용 서버는 남긴다(`start` 가 재사용). **감독(`:8777`·`:8778`)이 떠 있으면 아무것도 안 내리고 멈춘다** — 공연 중일 수
  있다. `stop` 과 달리 MCP 서버·시뮬 데몬은 안 건드린다. `--dry-run` 은 내릴 것만 말한다. 정리가 멈추면 `run-app.sh` 는 띄우지 않는다.
- **멈추는 경우(소리 내서)**: 외부 전용인데 엔진 하나라도 local(키가 없는 경우 포함) → `start` 가 계획 단계에서 exit 2. 키가 없어 게이트웨이·
  프록시가 못 뜨면 그 이유를 화면에 찍고 멈춘다(로컬로 물러나지 않는다). 지난 실행의 **로컬 구성 서버가 남아 있으면**(`:8099` 가 로컬을 낀
  프록시, `:8080` 이 폴백 있는 게이트웨이) "./reachy.sh stop 후 다시" 로 멈춘다. 로컬 모델만 남아 있으면 경고만 한다(안 쓰지만 메모리를 쓴다).
- **실측(2026-11-13, 이 맥, 예비 포트)**: 외부 전용 게이트웨이·프록시로 예열 — LLM 첫 글자 1.24초(프리픽스 데운 뒤), STT 1.38초('안녕하세요.'),
  TTS wav 1.14초(ElevenLabs). 테스트: `tests/test_openai_gateway.py` 의 `외부_전용` 묶음, `tests/test_tts_elevenlabs.py` 의 `외부_전용` 묶음,
  `tests/test_run_app.py::test_키가_둘_다_있으면_외부_API_전용이고_그렇다고_말한다`.
- **실기에서 확인할 것**: 공연 중 PC 인터넷을 뽑아 대본이 끊김 없이 이어지는지, 관람객 질문에 "다시 말해 줄래요"·안내가 한 번씩만 나오는지,
  `./reachy.sh logs` 에 게이트웨이·프록시 경고가 보이는지.

### 15.14 로봇이 안 잡히거나 한 대만 붙을 때 — Wi-Fi 절전·멈춘 앱 상태·1인 모드(2026-11-13)
- **로봇 확인**: 핑 3번·데몬 API 3번까지 본다(예전에는 핑 한 번 2초 — 켜져 있던 도슨트가 빠졌다). 응답이 2번째 이후면 "Wi-Fi 가 절전에서 깨는 중" 이라 찍는다.
- **Wi-Fi 절전**: 두 로봇 모두 기본이 `power_save on` 이다. `start --robot`·`robot up` 이 기동마다 `sudo iw dev wlan0 set power_save off` 로 끈다(재부팅하면 다시 켜진다 —
  기동마다 끄는 이유). 영구 설정(NetworkManager `wifi.powersave = 2`)은 로봇 OS 확인 뒤 정한다.
- **앱 관리자가 `stopping` 에 멈춤**: 앱 프로세스는 없는데 상태가 안 풀려 시작(400)·정지("No app is currently running") 모두 거절. 기동이 감지하면 데몬을 재시작하고
  다시 깨워 띄운다. 손으로는 `ssh pollen@<로봇> sudo systemctl restart reachy-mini-daemon`.
- **1인 모드**: 한 대만 붙은 채 [공연 시작]을 누르면 남은 로봇이 양쪽 대사를 **자기 목소리로** 읽는다(설계된 폴백 — 막지 않는다). 감독 창에 주소까지 든 합류
  명령이, 조정실 위에 띠가 뜬다. 합류 명령은 꼭 주소와 함께 — `REACHY_ROBOT_HOST` 없이 치면 기본 주소(reachy-mini.local = 도슨트)의 config 를 덮어쓴다.
- **옛 코드 서버 다시 띄우기**(2026-11-14): `clean-local` 은 같은 설정이어도 뜬 뒤에 코드(·대본·읽기 표기)가 바뀐 게이트웨이·TTS 프록시를 내린다 — `start` 가 새 코드로 다시 띄운다.
- **Ctrl-C 정리**: 로봇 앱 정지를 두 로봇에 동시에, 연결 4초 상한(안 닿는 로봇은 건너뛴다) — 두 로봇이 꺼진 채 50초 걸리던 것이 4초.

### 15.15 큐 사이 관람객 질문 — 사회자가 받고 도슨트가 OpenAI 로 답한다, "다음"·"이어서 진행"으로 넘긴다(2026-11-13)
이미 있던 흐름을 확인하고 진행어·안내·대기 시간만 손봤다(로봇 재배포 없음 — 감독·게이트웨이는 PC).
- **흐름**: 도슨트 해설 → 사회자 받아치기("궁금한 점 있으실까요? 이어가려면 '다음'이라고 해 주세요.") → 질문 창(사회자 로봇 마이크) →
  관람객 질문 → 사회자 확인 멘트("좋은 질문이네요. 도슨트, 답해 줄래요?") 동안 도슨트 답 생성 → 도슨트 답 → 사회자 재질문(이제 '다음' 안내까지) →
  다시 질문 창. 1인 모드면 남은 로봇이 받고 답한다(§15.14).
- **답 생성**: 감독(PC) → `:8080` 게이트웨이 → OpenAI(gpt-6-luna). 근거는 지금 큐의 검증된 브리프 + 질문이 더 가까운 다른 큐 하나(`CueIndex.related`)
  + 금지 규칙, "지어내지 않는다·모르면 모른다", 존댓말 구어. 실패하면 도슨트가 사과문(`QA_FALLBACK`).
- **답 분량 — 풍부하게(2026-11-13)**: ~~모든 수준 2~3문장~~ → 초등 3~4문장/90~160자 · 중고등 3~5/120~220 · 일반 4~5/150~260 · 전문가 4~6/180~320
  (`data/levels.yaml`, 말하는 시간 약 14~49초). 답의 모양: 바로 답 → 왜 그런지 → 자료에 있는 예·비유 → 핵심을 짚는 맺음(같은 말머리 되풀이 금지).
  **근거도 같이 늘렸다** — 큐별 조사 자료(`data/cues-research` — 검증 등급 A·B 사실·바로잡은 것·확인 안 된 것, 출처 문자열은 빼고)를 싣는다
  (`stage/research.py`). 실측(OpenAI): 일반 210자·4문장 2.4초, 초등 108자·3문장 1.4초, 전문가 290자·6문장 2.1초(WHO 2020·IARC 2B·SAR 1.6 W/kg —
  조사 자료의 검증 사실). 생성은 사회자 확인 멘트(약 3초) 안에 끝난다. 길이를 다시 바꾸려면 `data/levels.yaml` 의 min/max 만 고친다.
- **진행어**: 끝 낱말이 "다음"·"계속"·"넘어가"·"진행"·"이어서" + 2자 이내(물음표 없음, 15자 이하). STT 가 띄어 쓴 공손한 요청은 끝의
  "주세요"·"줘" 와 "해" 를 한 번씩 떼고 본다("이어서 진행해 주세요" → 진행, "이어서 설명해 주세요" → 질문). 애매하면 질문으로 둔다.
  STT(OpenAI) 키워드에 진행어를 싣는다 — **게이트웨이는 기동 때 키워드를 만든다(대본·진행어를 고치면 게이트웨이를 다시 띄운다)**.
- **침묵 대기 20초**(예전 8초 — 관람객이 질문을 떠올리기 전에 넘어갔다). 아무 말이 없으면 20초 뒤 다음 큐(공연이 멈춰 서지 않게 하는 안전판).
  조정실 '고급' 서랍의 '침묵 대기'(3~60초·끄기)나 `REACHY_QUESTION_WAIT_S` 로 바꾼다.
- **언제나 한국어 · 관계없는 질문은 짧게**(2026-11-14 시뮬 한 바퀴): 다른 언어로 말해 달라면 한국어로 "지금은 한국어로만 안내해요". 전시·전파와 관계없는 질문
  (동물·음식·개인 이야기)은 한두 문장으로 정중히 답하고 지금 이야기로 돌아온다(전시 질문은 수준별 분량 그대로).
- **로봇이 하나도 안 붙었으면 [공연 시작] 거절**(콘솔·조정실 같다) — 붙기 전에 누르면 첫 대사가 버려져 공연이 멈춰 섰다. 한 대면 1인 모드로 시작.
- **프로젝터 창(`/stage/auto`)은 운영자용 안내 줄을 숨긴다** — 점검할 때만 `/stage/auto?note`. 운영자는 조정실 시연 화면 머리 줄에서 본다.
- **답한 관람객 질문은 감독 로그에 한 줄**(2026-11-14 사용자 결정): `관람객 질문: '…'`(단독은 `관람객 질문(단독): '…'`) — 글만, 녹음 없음, 조정실·관람객 화면에는
  안 간다, `.demo-logs/` 는 저장소 밖. 리허설 뒤 되묻기 줄과 함께 모아 되묻기 문턱을 다시 잰다(뽑는 명령 `docs/rehearsal-checklist.md` 1-4).
- **실기에서 확인할 것**: 사회자 마이크가 관람객 질문을 받는지, "다음"·"이어서 진행" 인식률(짧은 말), 확인 멘트 동안 답이 준비되는지(첫 글자 약 1초).

### 15.16 시연 준비 갈래 A — 사전 점검·사과문·잠자기 방지·주소 찾기·되묻기(2026-11-14)
갈래 A 보고(`docs/superpowers/plans/2026-11-14-show-readiness-A.md`)에서 옮겼다. 리허설 점검표: `docs/rehearsal-checklist.md`.
- **§15.13 끝에 — 사전 점검·사과문(2026-11-14)**: 기동 예열이 외부 API 를 실제로 한 번씩 부른다. 외부 전용에서 실패하면 빨간 `FAIL` 묶음으로 무엇이 왜 안 되는지
  (401 = `.env` 키, 429 = 잔액 또는 분당 한도, connect/timeout = 인터넷, 5xx = 업체 일시 오류)와 공연에서 안 되는 것(관람객 질문 답 · 음성인식 · 관람객 답 목소리)을
  말하고 **계속 띄운다**(대본은 캐시). 같은 줄이 감독 콘솔 직전과 감독 로그 머리(`사전 점검 실패: …`)에도 남는다. 멈추게 하려면 `REACHY_PREFLIGHT=stop`.
  `TTS_ENGINE=elevenlabs` 면 남은 크레딧을 찍는다(10,000 아래 WARN, 2,000 아래 FAIL — 관람객 답 하나 약 100). 사과문 둘(질문 답 · 단독 답)도 굽기 목록에 있다 —
  인터넷이 끊겨도 사과문이 매번 들린다(1인 모드 + 인터넷 끊김은 남은 로봇 목소리라 캐시가 빗나가 안내 한 번 뒤 무음 — 알려진 한계).
- **§15.12 또는 §15.13 에 — 공연 PC 잠자기**: `start` 가 감독 바로 앞에서 `caffeinate -dis -w <reachy.sh pid>` 를 건다(끝나면 풀린다). 맥이 아니면 경고만 —
  공연 PC 의 OS 설정에서 화면 끄기·잠자기를 끈다. 끄는 스위치 `REACHY_KEEP_AWAKE=0`.
  **`caffeinate` 는 배터리에서 덮개를 닫는 잠자기를 못 막는다**(2026-11-17 — 시뮬 도중 덮개를 닫아 사회자 마이크 열기가 실패하고, 깬 뒤 첫 LLM 질문들이
  실패했다). 운영 맥은 **전원 연결·덮개 열림**. `start` 가 기동 때 배터리면 경고한다(시뮬은 덮개 닫힘 = 내장 마이크 꺼짐도). 칸 M 보고 `docs/superpowers/plans/2026-11-17-sim-errors-M.md`.
- **§15.14 에 — 주소 찾기와 DHCP 예약**: 배역 주소가 핑 3번에 안 잡히면 `reachy-mini.local`·`reachy-mini-2.local` 을 풀어 응답하는 로봇의 **config 배역**(REACHY_ROLE)을
  읽어 알린다 — 찾은 주소는 쓰지 않는다(두 대의 hostname 이 같아 `-2` 는 켠 순서로 바뀔 수 있다). 새 주소는 ssh 호스트 키가 없어 "배역 미확인" 일 수 있다 —
  `ssh pollen@<주소>` 로 한 번 붙어 키를 받는다.
  **공유기 DHCP 예약(사용자 작업, U4 ①)**: 공유기 관리 화면 → DHCP(주소 할당) → 고정 할당(예약) → 로봇 Wi-Fi 의 MAC 주소(로봇에서 `ip link show wlan0` 의
  `link/ether` 값)를 사회자 192.168.0.4 · 도슨트 192.168.0.5 에 묶는다 → 로봇을 재부팅하고 `ping 192.168.0.4`·`.5` 로 확인 → 리허설 점검표 1-5(b).
  hostname 을 서로 다르게 바꾸는 것(U4 ③)은 다음 재배포 때.
- **§15.15 에 — 되묻기**: 질문 창에서 짧고(공백·문장부호 빼고 7자 이하) 질문 같지 않은 말(물음표·물음말·요청어·물음 어미 없음 — "와 신기하다"·"감사합니다")에는
  도슨트 답 대신 사회자가 "궁금한 점이 있으면 편하게 물어봐 주세요. 이어가려면 '다음'이라고 해 주세요." 로 되묻는다. 연달아 한 번 더 말하면 답한다.
  감독 로그 `질문으로 보지 않고 되묻는다: '…'` 로 놓친 질문을 찾는다. 끄기 `REACHY_QA_REPROMPT=0`(명령 앞에). 발화 라벨은 재질문(`:reask`) 그대로라 화면은 바뀐 것이 없다.

### 15.17 관람객 수준은 셋 — 초등·중고등을 '초중등' 하나로(2026-11-16) — 로봇 재배포 없음
실기 리허설 중 사용자 결정. **합친 수준은 중고등 대본**으로 말한다(용어를 풀어 말하고 비유로 열어 원리를 한 겹 — 고학년 초등에게도 통하고 중고등에게 유치하지 않다).
- 바뀐 것은 **고르는 자리뿐**이다: 조정실 수준 버튼(초중등·일반·전문가), 콘솔 `l`, 기동 `REACHY_AUDIENCE_LEVEL`, 교육자료 주소 `/handout?level=`. 운영자가 습관대로
  `l 초등`·`l 초중등` 을 쳐도, 교사가 옛 `?level=초등` 주소를 열어도 거절하지 않고 합친 수준으로 간다(감독 경고 줄 `관람객 수준 일반 → 초중등` 으로 남는다).
- 데이터(대본·교육자료 카드·조사 자료·웹툰·구운 음성)는 네 수준 그대로다 — 다시 굽지 않았다. 내부 이름(대본·캐시·화면 선택의 열쇠)은 그대로 "중고등" 이라
  감독 스냅샷·`/stage/auto` 의 `level` 값은 `중고등` 이다(사람에게 보이는 곳만 '초중등').
- 로봇은 수준을 모른다(감독이 고른 문장만 받는다) — 재배포 없음. 되돌리려면 `stage/levels.py` 의 `OFFERED_LEVELS` 에 "초등" 을 다시 넣고 `LEVEL_LABELS`·`LEVEL_ALIASES` 를 비운다.
- 시험: `tests/test_stage_main.py::test_main_에서_감독까지_초중등_수준이_이어진다`, `tests/test_levels.py::test_기동_수준이_초등이면_중고등_대본으로_뜬다`,
  `tests/test_stage_director.py::test_별칭은_목록에_없는_이름에만_쓴다`, `tests/test_audience.py::test_교육자료는_보이는_이름을_쓰고_별칭_주소도_받는다`.
- **수준별 화면 범위(2026-11-16, §15.12 갱신)**: 전문가 분해도는 **19큐 전부** — 카드 화면으로 이어지는 큐가 없다. 생성물 12.7 MB, 처음 뜨는 시간 1.2초(GPU 없는 PC)·0.2초(GPU),
  GPU 없는 PC 에서 13~23 fps(SwiftShader 실측), 19장을 다 지으면 형상 약 55 MB. 초중등 웹툰은 하이라이트 밖 10큐를 중고등 한 수준으로 채우는 중(계획
  `docs/superpowers/plans/2026-11-16-level-screens-rest.md`). 로봇 재배포 없음 — PC 의 정적 HTML 이고 조정실이 빌드된 페이지에서 큐 목록을 읽는다.

## 적용한 수정 (2026-07-30)

1. **`main.py`** — `VoiceChat.run(reachy_mini, stop_event)` 이 대화 루프를 돌린다.
   공통 로직은 **`session.py`** 로 뽑았다(`announce_voice`/`build`/`respond`) —
   진입점이 CLI 스크립트를 import 하던 구조를 없앴다. `demo.py` 는 이제
   `--text`/`--no-robot` 폴백만 담은 얇은 래퍼다.
   **`reachy.sh` 의 기본 경로도 `main.py` 로 바꿨다** — 시연에서 돌리는 것과
   배포하는 것을 같게 두려는 것이다. 예전에는 데모가 `demo.py` 만 태워서
   `main.py` 가 생성 템플릿인 채로 방치된 것을 아무도 몰랐다.
   시뮬 데몬에 붙어 음성 모드 진입 → SIGINT 종료(코드 0)까지 확인했다.
   - `build(mini=...)` 로 주입된 인스턴스는 **컨텍스트로 잡지 않는다**(이중 해제 방지).
     직접 만드는 시뮬 경로는 종전대로 `stack.enter_context`.
   - `voice_loop(..., should_stop=stop_event.is_set)` — 프레임마다(30ms) 확인한다.
     단 `respond()` 안에서는 확인하지 않는다(자기소개 대본은 한 번 시작하면 ~50초).
2. **`audio_in.py`** — `autoaudiosrc`. 장치를 강제하려면 `REACHY_MIC_SRC`
   (예: `alsasrc device=hw:1`). macOS 에서 캡처 회귀 확인.
3. **`pyproject.toml`** — 실제 import 를 대조해 `numpy`·`requests`·`sounddevice`·
   `PyGObject` 추가. (`pydantic` 은 템플릿의 설정 페이지를 걷어내며 함께 빠졌다.)
4. **`stt.py`·`llm.py`** — `REACHY_STT_URL`·`REACHY_LLM_URL`.
   TTS 의 `TTS_QWEN_URL` 과 합쳐 **세 주소 모두 코드 수정 없이 PC 를 가리킨다.**
5. **`tts.py`** — 폴백 사다리를 `shutil.which` 로 고른다:
   합성은 `say` → `espeak-ng` → `espeak`, 재생은 `afplay` → `paplay` → `aplay`.
   아무것도 없으면 **경고를 남긴다**(발화마다 반복하지 않고 한 번). `_worker` 의
   `except Exception: pass` 도 예외를 찍도록 바꿨다 — 이게 무음의 진짜 원인이었다.
