# 경영진 시연 런북 (Reachy Mini 음성 일상대화)

## 기동 — 명령 하나

```bash
./scripts/demo.sh
```

이것만 하면 된다. LLM(:8080)·STT(:8090)·시뮬 데몬(:8000)을 **없는 것만** 띄우고,
예열까지 마친 뒤 마이크 음성 모드로 바로 들어간다.
콜드 스타트 실측 약 15초(LLM 5s · STT 2s · 데몬 5s), 이미 떠 있으면 즉시.

| 명령 | 용도 |
|---|---|
| `./scripts/demo.sh` | 음성 모드 (기본, 시연용) |
| `./scripts/demo.sh --text` | 키보드 모드 — 마이크가 말썽일 때 |
| `./scripts/demo.sh --no-robot` | 시뮬 없이 대화·음성만 — 최후 폴백 |
| `./scripts/demo.sh --check` | 기동 없이 상태만 확인 |
| `./scripts/demo.sh --stop` | 띄운 서버 전부 종료 |

앱을 Ctrl-C 로 나가도 **서버는 살아 있다.** 다시 `./scripts/demo.sh` 하면 몇 초 만에
재진입한다 — 시연 중 사고가 나도 빠르게 복구된다.

주의: 시스템 볼륨 70% 이상, 조용한 방(에너지 VAD는 소음에 민감), 전원 연결.
첫 실행 시 macOS 마이크 권한 팝업이 뜰 수 있다 — **시연 전에 미리 한 번 돌려 허용해 둔다.**

수동으로 하나씩 띄우려면: `llama reach-llm` / `./run-sim.sh --scene minimal`.

## 시연 시나리오 (3분)

| 순서 | 말할 것 | 보여주는 것 |
|---|---|---|
| 1 | "안녕!" | 즉시 환영 모션 + 음성 인사 — **반응 속도** |
| 2 | "요즘 뭐가 재밌어?" | 자유 대화 — **sLLM 일상대화** |
| 3 | "아까 내가 처음에 뭐라고 했지?" | 이력 회상 — **문맥 유지** |
| 4 | "헐 대박!" | 놀람 모션 — **감정 표현** |
| 5 | "영어로 대답해줘. 오늘 기분 어때?" | 영어 음성으로 전환 — **다국어** |
| 6 | "노래 한번 불러줘" | 음악에 맞춘 17~18초 춤 — **표현력** |
| 7 | **"슬픈 표정 지어봐"** | 요청한 감정을 그대로 연기 — **감정 표현** |
| 8 | **"넌 어떻게 만들어졌어?"** | 로봇이 직접 구성을 설명 — **약 57초** |
| 9 | "고마워, 잘 있어" | 마무리 |

**대기 중에도 로봇은 혼자 움직인다.** 12~25초마다 감정 라이브러리에서 하나를
골라 재생한다. 소리 없이 재생하므로 그동안에도 말을 걸 수 있고, 말을 걸면
즉시 밀려난다. 시연 시작 전 정적에서 이 점을 보여주면 좋다.

**7번 감정 연기**는 `기쁨·슬픔·화남·놀람·무서움·지루함·피곤·부끄러움·뿌듯함·사랑·
궁금함·혼란·고마움·안도·역겨움·외로움·짜증·평온` 18종을 받는다. "화난 거 표현해봐",
"기쁜 표정 보여줘" 처럼 **감정 단어 + 요청 표현**이 함께 있어야 걸린다 —
"나 슬퍼" 는 연기가 아니라 공감할 상황이라 LLM 이 답한다.

**7번은 고정 대본이다.** 모델명과 수치를 LLM 이 지어내면 안 되므로 질문을 가로채
검증된 문장을 그대로 읽는다(`apps/voice_chat/voice_chat/selfintro.py`).
"어떤 모델 쓰니", "무슨 기술로 동작해", "구조가 어떻게 돼" 로도 걸린다.
57초간 마이크가 닫히니 끝날 때까지 기다린다. 내용을 고치려면 `SCRIPT` 목록만 바꾼다.

한 턴이 끝날 때까지(로봇 발화 종료) 기다렸다 다음 말을 한다 — half-duplex라
말이 겹치면 입력이 버려진다.

**다국어**: 사용자는 한국어로만 말하고, 로봇에게 특정 언어로 답해 달라고 요청한다.
영어·일본어·중국어를 지원하며 문장의 문자체계에 맞춰 음성이 자동으로 바뀐다
(Yuna / Samantha / Kyoko / Tingting). 사용자가 외국어로 *말하는* 것은 지원하지 않는다 —
STT가 한국어로 고정돼 있어 오전사된다.

**노래**: `say`는 노래를 못 하므로, 자체 사운드를 가진 춤 모션(`dance2` 17.3초 /
`dance3` 18.4초)으로 보여준다. 재생 중에는 마이크가 닫히니 끝날 때까지 기다린다.

## 실측 근거 (질문 대비 숫자)

`docs/latency-m0.md` 참조. 2026-07-29 이 장비에서 측정:

- LLM 첫 응답 토큰 **0.03~0.08초**, 첫 문장 완성 **0.17~0.55초**
- TTS 합성 **0.79~0.90초** (최대 단일 비용)
- 발화 종료 → **모션 약 0.95초**, **첫 오디오 약 2.0~2.35초**

자연스러운 발화를 위해 문장 중간을 자르지 않고 VAD 대기를 0.70초로 뒀다.
그 대가로 첫 오디오가 2초를 조금 넘는다 — 되돌리는 방법은 `docs/latency-m0.md` 참조.

## 확장성·기대효과 멘트

- **전 구간 로컬** — 음성·대화 내용이 장비 밖으로 나가지 않는다. 프라이버시·API 비용 0.
- **클라우드 전환은 설정 한 줄** — `llm.py`가 OpenAI 호환이라 base_url 교체만으로
  상용 API로 옮긴다. 품질과 비용을 운영 중에 선택할 수 있다.
- **독립 교체 지점** — 성격(`prompt.md`), 감정 매핑(`motion.py`), 음성(`tts.py`),
  인식(`stt.py`)이 각각 파일 하나다. MCP 도구를 붙이면 사내 시스템 조작으로 확장된다.
- **시뮬 → 실기 이전 비용이 낮다** — 오디오 백엔드·TTS·서버 주소 3가지만 바꾸면
  같은 코드가 실기에서 돈다. 실기에서는 앱이 로봇(Pi5)에서 돌고 추론만 PC가 맡아
  오디오가 네트워크를 타지 않는다.

## 장애 대응 사다리

위에서부터 시도한다.

| 증상 | 대응 |
|---|---|
| 마이크 인식 불량·주변 소음 | `./scripts/demo.sh --text` — 키보드 입력, 모션·음성 응답은 동일 |
| 데몬/시뮬 다운 | `./scripts/demo.sh --no-robot` — 대화·음성만 (모션 없음) |
| 뭐가 죽었는지 모를 때 | `./scripts/demo.sh --check` 로 4개 상태 확인 |
| 서버가 꼬였을 때 | `./scripts/demo.sh --stop` 후 `./scripts/demo.sh` 로 전체 재기동 |
| 시뮬이 안 뜬다 | `tail -30 .demo-logs/sim.log` |
| LLM 다운 | 모션과 폴백 대사는 계속 동작. `./scripts/demo.sh` 재실행이 알아서 살린다 |
| STT 오인식 반복 | 마이크에 30cm 이내로 접근, 또는 텍스트 모드 |
| 로봇이 자기 말에 반응(에코) | 시스템 볼륨을 낮춘다 (게이팅 가드 0.3초 내장) |
| 응답이 너무 길다 | `prompt.md`의 "1~2문장" 규칙 확인, `llm.py`의 max_tokens 축소 |

## 알려진 한계 (선제 고지용)

- **끼어들기 불가** — 로봇이 말하는 중에는 듣지 않는다(half-duplex). 하드웨어
  에코캔슬이 없는 시뮬 환경의 제약이며, 실기의 XMOS AEC에서는 해소 가능하다.
- **모션은 사용자 발화 기준** — LLM 응답을 기다리지 않고 즉시 반응하므로 빠른 대신,
  드물게 로봇의 대답 내용과 모션의 결이 어긋날 수 있다.
- **음원 방향 인식 없음** — 마이크 어레이가 없어 시뮬에서는 의미 있는 값이 안 나온다.
