# 실기 2대 오프라인 테스트 — 순서대로

인터넷 없이, 노트북 1대 + Reachy Mini Wireless 2대 + 전용 공유기 1대로 팟캐스트 시연을
처음부터 끝까지 돌려 보는 절차다. **코드에 있는 것만 적었다** — 자세한 근거는
`docs/two-robot-setup.md`, 실기에서만 드러나는 위험은 `docs/real-robot-deployment.md` §15.

준비물: 로봇 2대, 노트북(추론 3종 + 무대감독), 전용 무선공유기, Reachy Mini Control 앱, 라벨.

---

## ① 공유기 (5분)

1. 공유기를 켜고 노트북을 그 망에 붙인다. **시연장 공용 WiFi 는 쓰지 않는다** — AP isolation
   으로 노트북↔로봇이 막히고, 로봇 데몬 API 에 인증이 없어 공용망에 올리면 안 된다.
2. 5GHz SSID 를 하나 정해 둔다. 공유기를 로봇 가까이 둔다.

## ② 로봇 WiFi 등록 — **반드시 한 대씩** (10분 × 2)

두 로봇의 핫스팟 SSID 가 `reachy-mini-ap` 로 **같다.** 둘 다 켜 두면 어느 쪽에 설정했는지 알 수 없다.

1. **A 만 켠다.** B 는 전원을 끈 채로.
2. 노트북에서 Reachy Mini Control → "First time connecting…" → 로봇 핫스팟에 붙는다.
3. 공유기 SSID·비밀번호를 넣는다 → 로봇이 공유기 망으로 옮겨 간다.
4. 붙은 것을 확인하고 **A 를 끈다.**
5. **B 만 켜고** 2~4 를 반복한다.
6. 둘 다 켠다. 본체에 **사회자 / 도슨트** 라벨을 붙인다(겉모습이 같다).

핫스팟이 안 보이면 Control 앱의 Bluetooth Console(Chrome/Edge) 로 핫스팟을 리셋한다.

## ③ 고정 IP 와 기기 ID (10분)

두 로봇의 hostname 이 **둘 다 `reachy-mini`** 라 `.local` 은 못 믿는다.

1. 공유기 관리 페이지에서 MAC 기준 DHCP 고정 IP 를 준다: 사회자 `.4`, 도슨트 `.5`, 노트북 `.10`.
   `./reachy.sh start --robot` 의 기본값이 이 두 주소다 — 다르게 주면 ⑤ 에서 덮어써야 한다.
2. 확인:
   ```bash
   curl -s http://192.168.0.4:8000/api/daemon/status | head -c 200
   curl -s http://192.168.0.5:8000/api/daemon/status | head -c 200
   ```
   둘 다 JSON 이 나와야 한다.
3. 기기 ID 를 채취해 적어 둔다 — 두 대가 뒤바뀌면 무대감독이 기동에서 거부한다:
   ```bash
   curl -s http://192.168.0.4:8000/api/daemon/status | python3 -c "import sys,json;print(json.load(sys.stdin)['hardware_id'])"
   curl -s http://192.168.0.5:8000/api/daemon/status | python3 -c "import sys,json;print(json.load(sys.stdin)['hardware_id'])"
   ```
   `null` 이 나오면 그 로봇의 오디오 장치가 안 잡힌 것이다(시뮬은 언제나 null, 실기는 값이 있어야 한다).

## ④ 로봇 대시보드에서 startup-app 을 비운다 (2분 × 2)

`http://<로봇IP>:8000` → 자동 시작 앱을 **없음**으로. 켜져 있으면 우리 앱과 모터를 두고 싸운다. 두 대 모두.

## ⑤~⑦ 한 줄로 — `./reachy.sh start --robot` (권장, 10분)

```bash
export REACHY_MC_UNIT=<③의 사회자 hardware_id>
export REACHY_DOCENT_UNIT=<③의 도슨트 hardware_id>
./reachy.sh start --robot --dry-run   # 계획만 — 대상 192.168.0.4 / 192.168.0.5 가 찍혀야 한다
./reachy.sh start --robot
```

이 한 줄이 아래 ⑤~⑦ 을 순서대로 한다: 포트(8777·8778) 점검 → 추론 3종(LAN) → 예열 → 사회자·도슨트
각각 **도달 확인 → 백엔드 상태/복구 → config 동기화(역할·감독 주소) → 로봇→맥 도달 → 기상 → 앱** →
무대감독(`0.0.0.0`)을 **이 터미널에** 띄우고 대시보드(`http://127.0.0.1:8778/`)를 브라우저로 연다.

- 로봇 주소 기본값이 ③ 의 고정 IP 그대로다 — 사회자 `192.168.0.4`, 도슨트 `192.168.0.5`. 주소를
  바꾼 경우에만 `REACHY_MC_HOST=… REACHY_DOCENT_HOST=… ./reachy.sh start --robot` 으로 덮어쓴다.
- **추론 서버가 LAN 에서 안 보이면 멈춘다** — `start --sim`/`demo` 가 loopback 으로 띄워 남긴 서버가
  그 경우다(`loopback 전용 … ./reachy.sh stop 후 다시`). **TTS 가 안 떠도 멈춘다** — 로봇 앱은 이
  노트북의 TTS 로만 말하고 로봇에는 say 폴백이 없다(`tail -30 .demo-logs/tts.log`).
- **한 대가 안 닿으면 경고하고 건너뛴다** — 감독은 남은 한 대로 1인 모드로 뜬다. 건너뛸 때마다 그 로봇의
  합류 명령(`REACHY_ROLE=<역할> REACHY_ROBOT_HOST=<주소> ./reachy.sh robot up`)이 찍힌다 — 로봇을 살린 뒤
  다른 터미널에서 그대로 친다. 그렇게 합류한 앱도 이 콘솔의 `q` 가 함께 멈춘다.
- 로봇 config 에 들어가는 감독 주소는 **이 노트북**(`ws://<LAN IP>:8777`)이다. 셸에 시뮬 때의
  `REACHY_DIRECTOR_URL` 이 남아 있으면 무시한다고 경고가 뜬다.
- 콘솔 `q`(또는 Ctrl-C)로 끝내면 **두 로봇(사회자·도슨트 주소)의 앱만** 멈춘다 — 건너뛰었다가 나중에
  합류시킨 로봇까지. 그때도 꺼져 있는 로봇은 `로봇 앱 정지 실패 (<주소>) — 안 닿는다` 한 줄이 뜬다.
  추론 3종은 남는다 — 전부 내리려면 `./reachy.sh stop`.
- `REACHY_MC_HOST` 와 `REACHY_DOCENT_HOST` 가 같으면 **아무것도 하지 않고 멈춘다**(종료코드 2) — 같은 로봇의
  config 를 도슨트가 덮어써 사회자가 사라지기 때문이다. `--dry-run` 도 같다.
- `./reachy.sh logs` 의 `start-app-*.log` 자리에는 `실기 — 앱 로그는 REACHY_ROBOT_HOST=<주소> ./reachy.sh robot logs`
  한 줄만 있다 — 실기의 앱은 로봇 위에서 돈다. 감독 로그 머리줄의 `target=robot mc=… docent=…` 로
  어느 세션인지 가른다.

아래 ⑤~⑦ 은 **부품별로 띄울 때**다 — 한 대만 다시 올리거나, 어느 단계에서 막히는지 좁힐 때 쓴다.

## ⑤ 노트북: 추론 3종 + 예열 — 부품별로 띄울 때 (5분, 첫 합성 8.5초 포함)

```bash
export REACHY_MC_UNIT=<③의 사회자 hardware_id>
export REACHY_DOCENT_UNIT=<③의 도슨트 hardware_id>
export REACHY_DIRECTOR_PORT=8777
./reachy.sh serve        # LLM :8080 · STT :8090 · TTS :8099 를 LAN 에 연다
./reachy.sh warmup       # Qwen3-TTS Metal JIT 등 — 건너뛰면 첫 큐가 8.5초 늦다
```

`REACHY_AEC` 는 **켜지 않는다**(실기는 XMOS 하드웨어 AEC). 로봇의 셸에서 `export` 하는 것은 아무
효과가 없다 — 로봇의 앱은 데몬의 자식이라 설정파일만 읽는다. 그 파일은 ⑦ 이 써 넣는다.

## ⑥ 무대감독 기동 — 부품별로 띄울 때 (1분)

```bash
.venv/bin/python -m stage
```

`무대감독 대기 중 — ws://0.0.0.0:8777` 이 뜬다. 이 터미널을 열어 둔다 — 콘솔이다.
`⚠ REACHY_MC_UNIT / REACHY_DOCENT_UNIT 이 없다` 가 뜨면 ⑤ 의 export 를 빠뜨린 것이다.

같은 기동에서 `대시보드 — http://127.0.0.1:8778/` 도 찍힌다 — 노트북 브라우저로 그 주소를
열면 방송 조정실 화면(탤리·자막·런다운·이력)이 뜬다. 태블릿 등 다른 기기에서 열려면
`REACHY_DASHBOARD_HOST=0.0.0.0 .venv/bin/python -m stage` 로 기동한다 — 이 화면은 인증이
없으므로 **전용 공유기 안에서만** 열어야 한다(공용 와이파이 금지). 이때 터미널에는
`대시보드 — http://0.0.0.0:8778/` 이 찍히지만 `0.0.0.0` 은 "모든 주소에서 받는다" 는 바인드
표시일 뿐 열 수 있는 주소가 아니다 — 태블릿에서는 **노트북의 LAN IP**(`http://192.168.0.x:8778/`)
로 연다. 콘솔 키(⑨)는 대시보드가 떠 있어도 그대로 먹는다 — 둘은 같은 명령 경로를 나눠 쓸 뿐이다.
관람객 수준은 헤더의 [초등][중고등][일반][전문가] 버튼(콘솔 `l 초등`)으로 바꾼다 — **바로, 다음 발화부터**
적용된다(로그에 `관람객 수준 일반 → 초등 — 바로 적용(지금 문장은 끝까지, 다음 발화부터)`). 말은 끊지 않는다 —
지금 나가는 문장은 끝까지 가고, 이 큐의 남은 도슨트 설명과 질문 답부터 새 수준이다(~~다음 큐부터 적용, 바로
하려면 `r`~~ — 2026-09-25 에 바꿨다). `REACHY_AUDIENCE_LEVEL` 은 처음 수준일 뿐이다.

헤더 왼쪽의 [팟캐스트][단독] 토글은 **운영 모드**다(콘솔 `m podcast` / `m solo`). 시연은 팟캐스트 그대로 두면
된다. **단독**(2026-09-25)은 도슨트 해설 없이 사회자 혼자 관람객과 이야기하는 모드다 — 감독이 대화를 맡으므로
로봇 앱은 그대로다(~~사회자 앱이 단독을 알려야 켜진다, 4단계~~). 켜면 말하던 것이 멈추고 사회자 마이크가 열린다.
관람객이 말하면 사회자가 짧은 확인 멘트("네, 잘 들었어요.") 뒤 답하고 다시 듣는다. 전시 질문은 큐시트에서
가장 가까운 섹션을 근거로 답하고, 인사·잡담은 짧게 받는다. 도슨트는 깨어 있되 말하지 않는다(사회자를 보고
끄덕인다). 침묵 자동 진행은 없다.

- 단독 중 **[즉시 중단](`a`)** = 지금 답을 멈추고 다시 듣는다. 완전히 멈추려면 [팟캐스트](`m podcast`).
- 공연 시작·종료·다음·이전·이동은 거절된다(먼저 팟캐스트로). 관람객 수준(`l`)은 된다.
- 사회자가 끊기면 팟캐스트로 돌아간다(다시 붙으면 `m solo`). 도슨트가 끊기면 단독은 그대로다.
- 버튼 옆 안내가 못 켜는 이유를 가른다: `단독: 사회자 로봇 연결 후` / `단독: 사회자 대기모드 해제 후`.

**코스**(2026-09-25) — 헤더의 [전체][하이라이트](콘솔 `k 하이라이트`). 하이라이트는 9큐(개요·발견·원리·모스·해상·
이동통신·탐사·과학·마무리)다(`data/courses.yaml`). **바로 적용된다** — 지금 큐는 끝까지 말하고 그 뒤로는 새 코스의 큐만
밟는다. 공연 전에 바꾸면 [공연 시작] 이 그 코스의 첫 큐부터다. 런다운에서 코스 밖 큐는 흐리게 `제외` 로 보이고, 눌러서
이동(`g`)은 여전히 된다. 코스 파일이 틀리면 기동 때 경고하고 전체 하나로 돈다.

**관람객 보조 화면과 교육자료**(2026-09-25) — 조정실 헤더의 [관람객 화면 ↗]·[교육자료 ↗] 로 새 탭에 연다.

- **관람객 화면** `http://127.0.0.1:8778/audience` — 관람객 쪽을 향한 모니터에 전체 화면(F11)으로 띄운다. 큰 글씨 자막
  (누가·무엇을, 직전 한 줄은 흐리게), 지금 섹션(코스 안 번호 — 하이라이트면 3 / 9 — 와 제목), 질문 창이 열리면 "궁금한 것이 있으면 지금 말씀해 주세요"
  와 남은 초, 단독이면 "사회자에게 무엇이든 물어보세요". **읽기 전용**이다 — 이 화면(과 그 소켓 `/ws/audience`)으로는
  아무것도 조작할 수 없고, 경고·관람객 음성 인식 원문·연결 상태 같은 운영 정보는 나가지 않는다.
- **띄우는 곳은 운영 노트북에 HDMI 로 연결한 두 번째 모니터가 기본이다.** 관람객 태블릿에서 열려면 대시보드를 망에 열어야
  하는데(`REACHY_DASHBOARD_HOST=0.0.0.0`), 그러면 **조정실(`/`, 명령 가능)도 같은 주소로 열린다** — 인증이 없으므로 전용
  공유기 안에서만, 관람객이 주소를 바꿔 조정실로 갈 수 있다는 것을 알고 쓴다.
- **교육자료** `http://127.0.0.1:8778/handout?level=초등` — 오늘 들은 해설(사회자·도슨트 대화, 그 수준의 설명)을 옮긴 인쇄용
  읽기 자료. 수준 버튼으로 바꾸고 [인쇄하기]. 주소에 수준·코스(`&course=하이라이트`)가 없으면 지금 감독의 것이다 — 하이라이트 코스면 그 9큐만 싣는다. 검수한 고정 대본만 옮긴다 —
  관람 중 나눈 질문과 답은 담기지 않는다(생성 답은 검수 전이라 교육자료로 내보내지 않는다).

## ⑦ 로봇 앱 기동 — 부품별로 띄울 때: 사회자 먼저, 도슨트 다음 (2분 × 2)

노트북에서 로봇마다 한 번씩:

```bash
REACHY_ROLE=mc     REACHY_ROBOT_HOST=192.168.0.4 ./reachy.sh robot up
REACHY_ROLE=docent REACHY_ROBOT_HOST=192.168.0.5 ./reachy.sh robot up
```

`robot up` 하나가 **백엔드 확인 → 추론 3종 → 예열 → 로봇 config 동기화 → 로봇→맥 도달 확인 →
기상 → 앱 기동** 을 순서대로 한다. 무대감독 콘솔에 `[mc] 붙었다`, `[docent] 붙었다` 가 뜨면 된다.

**확인할 로그 줄** (`./reachy.sh robot logs`):

| 줄 | 뜻 |
|---|---|
| `역할: mc (설정파일)` | 정상. `(기본값)` 이면 역할이 안 닿아 1대 모드로 뜬 것 |
| `무대감독: ws://192.168.0.10:8777 (설정파일)` | 정상 |
| `주소: LLM http://192.168.0.10:8080 …` | 정상. `[주소 경고] … loopback` 이면 ⑦ 을 다시 |
| `[mc] 거부됨 — … 뒤바뀌었는지` (감독 콘솔) | 두 대가 바뀌었다. 라벨을 보고 바꿔 건다 |
| `[경고] 청취 루프가 죽었다` | 사회자 마이크가 안 떴다. 콘솔로만 진행된다 |

## ⑧ 시연 리허설 (10분)

콘솔 `s`(또는 대시보드 제어판의 **[공연 시작]**). 그 다음 아래를 **순서대로** 확인한다.

1. **한 큐를 끝까지**: 사회자(주제 넘김) → 도슨트(해설) → 사회자(받아치기 + "다음" 안내) → 정적.
   그 뒤 관람객이 "다음" 이라고 말하면 다음 큐로 간다.
2. **질문 하나**: "타이타닉이 언제 가라앉았어요?" → 사회자 "좋은 질문이네요, 도슨트?" → 도슨트 답 → 정적.
   **도슨트 답 뒤에 도슨트가 혼자 또 말하지 않는지 30초 본다.** 말하면 자기목소리 루프다 —
   `./reachy.sh robot logs` 에서 사회자 쪽 `나(STT …)>` 줄에 도슨트 대사가 보이면 그것이다.
3. **콘솔 `r`** 을 사회자 발화 도중에 누른다 → 사회자가 처음부터 다시 말하고, **도슨트는 사회자가
   끝난 뒤에** 시작해야 한다. 동시에 말하면 안 된다.
4. **콘솔 `a` → `n`** → 다음 큐로 간다(정지 상태에서도 `n` 이 먹어야 한다).
5. **로봇 한 대를 끈다** → 감독 콘솔에 `[docent] 이 끊겼다 — 1인 모드` → 남은 사회자가 양쪽 대사를
   읽는다. 도슨트를 다시 켜면(`robot up`) 2인 모드로 돌아온다.
6. **사회자 앱만 껐다 켠다** (`REACHY_ROBOT_HOST=192.168.0.4 ./reachy.sh robot down --keep-servers` →
   `REACHY_ROLE=mc REACHY_ROBOT_HOST=192.168.0.4 ./reachy.sh robot up`. `--keep-servers` 를 빼면 노트북의
   추론 3종까지 내린다) →
   다시 붙은 뒤 관람객 "다음" 이 먹어야 한다(마이크 재동기화).
7. **`s` 두 번** → `공연이 이미 진행 중이다 — 처음부터 다시 하려면 먼저 공연 종료(e)` 가 뜨고 공연은 그대로 흐른다
   (~~`거절됨: …`~~ — 2026-09-25 `s` 가 [공연 시작] 이 됐다). 사회자 여는 대사가 다시 나오면 안 된다.
9. **[공연 종료](콘솔 `e`)** → 말이 멈추고 마이크가 닫히며 첫 큐로 되감긴다. 버튼이 [공연 시작] 으로 돌아온다.
8. **긴 질문**(15초 넘게 이어 말하기) → 그 다음 보통 질문도 들려야 한다.

## ⑨ 고장 났을 때 — 콘솔 키

| 키 | 언제 |
|---|---|
| `s` | 공연 시작 — **첫 큐부터**(진행 중이면 경고만) |
| `e` | 공연 종료 — 멈추고 마이크를 닫고 첫 큐로 되감는다(다음 관람객을 받을 준비) |
| `a` | 지금 당장 둘 다 멈춘다. 마이크는 안 연다. **지금 큐에 머문다**(이어서 `r`) |
| `n` | 이 섹션을 건너뛴다(`a` 뒤에도 됨) |
| `p` | 오인식으로 넘어가 버렸다 — 한 섹션 되돌린다 |
| `r` | 이 섹션을 처음부터 |
| `q` | 무대감독 종료 |

로그: 노트북 쪽은 무대감독 터미널(`start` 로 띄웠으면 `./reachy.sh logs` 에도 남는다 —
`.demo-logs/start-director.log`), 로봇 쪽은 `REACHY_ROBOT_HOST=<IP> ./reachy.sh robot logs`.
"이상하다" 는 순서 하나다 — **로그 확인 → 재현 → 원인 → 고침 → 테스트로 박제**.

## ⑩ 정리

`start --robot` 으로 띄웠으면: 콘솔 `q` → 두 로봇의 앱이 멈춘다(도중에 `robot up` 으로 합류시킨 로봇도) →
`./reachy.sh stop` 이 맥의 추론 3종까지 내린다.

부품별로 띄웠으면:

```bash
REACHY_ROBOT_HOST=192.168.0.4 ./reachy.sh robot down --keep-servers
REACHY_ROBOT_HOST=192.168.0.5 ./reachy.sh robot down
```

두 번째 호출이 맥의 추론 3종까지 내린다. 콘솔은 `q`.
