# Reachy Mini 음성 일상대화

말을 걸면 알아듣고, 감정 모션으로 즉시 반응하며, 캐릭터 음색으로 답한다.
**추론 3종(STT·LLM·TTS)이 전부 로컬에서 돈다** — 대화 내용이 장비 밖으로 나가지 않는다.

- 개발·시연: MuJoCo 시뮬레이터 (실기 없이)
- 검증 환경: macOS 26.5 / Apple M5 Pro / Python 3.12 (uv)

---

## 기동과 종료

**시작·종료 명령은 `./reachy.sh` 하나뿐이다.** 다른 스크립트를 직접 부르지 않는다.

```bash
./reachy.sh start --sim       # 시작 — 시나리오 시연: 로봇 2대(사회자·도슨트) + 무대감독. 뜬 콘솔에서 s 로 공연 시작
./reachy.sh demo              # 시작 — 1대 자유 대화(음성 모드). 시나리오는 돌지 않는다
./reachy.sh stop              # 종료 — 띄운 것 전부
```

**시나리오(큐시트)를 돌리려면 `start` 다.** `start` 는 로봇과 무대감독만 띄우고 공연을 자동으로
시작하지 않는다 — 로봇이 붙었다는 `붙었다` 로그가 뜬 뒤, 이 터미널의 감독 콘솔에서 `s`(또는 대시보드의
시작 버튼)로 시작한다. 콘솔 키: `s` 시작 · `e` 종료(첫 큐로) · `n` 다음 · `p` 이전 · `a` 비상정지 ·
`r` 이 큐 다시 · `q` 끄기(전체는 `?`). 실기 2대는 `start --robot`.

| 명령 | 하는 일 |
|---|---|
| `./reachy.sh start --sim` | **2대 시연 한 벌** — 추론 3종 · 모의 데몬 2대(`--mockup-sim`) + 앱 2대 · 무대감독 + 대시보드. 이 터미널이 감독 콘솔이고 `q` 로 끝내면 이 실행이 띄운 것만 내린다(추론 3종은 남는다) |
| `./reachy.sh start --robot` | 같은 한 벌을 **실기 2대**로(`REACHY_MC_HOST` / `REACHY_DOCENT_HOST`, 기본 192.168.0.4 / .5). 절차는 `docs/two-robot-offline-test.md` |
| `./reachy.sh start … --dry-run` | 무엇을 어디에 띄울지 `PLAN` 줄만 찍는다 — 아무것도 건드리지 않는다 |
| `./reachy.sh demo` | 전체 스택 기동 + 예열 후 **음성 모드**. 진입점은 `main.py`(실기와 동일) |
| `./reachy.sh demo --text` | 같은 스택, **키보드 대화** — 마이크가 말썽일 때 (`demo.py` 폴백) |
| `./reachy.sh demo --no-robot` | 시뮬 없이 대화·음성만 — 최후 폴백 |
| `./reachy.sh demo --exit-clean` | 앱을 나갈 때 서버까지 함께 내린다 |
| `./reachy.sh sim [--scene minimal\|--headless\|--no-media]` | 시뮬 데몬만 (대화 없이). 포그라운드 — Ctrl-C 로 끝 |
| `./reachy.sh check` | 기동하지 않고 4개 상태만 확인 |
| `./reachy.sh logs [줄수]` | **마지막 세션 로그 + 실시간 이어보기.** 문제가 생기면 여기부터 (`--no-follow` 로 한 번만) |
| `./reachy.sh stop` | 전부 종료 — PID 파일에 없는 고아까지 패턴으로 쓸어낸다 |

`demo` 는 **없는 것만 띄운다.** 앱을 Ctrl-C 로 나가도 서버는 살려 둔다(재진입이 빨라야 한다).
완전히 내리려면 `stop` 이나 `--exit-clean` 이다.

### 실기(Reachy Mini Wireless) 기동

위 명령들은 **시뮬레이터**용이다. 실기는 앱만 로봇에서 돌고 추론 3종은 이 맥에 남으므로
기동이 두 곳에 걸친다. `robot` 서브커맨드가 그 순서를 대신 기억한다.

```bash
REACHY_PROMPT=prompt_exhibit.md ./reachy.sh robot up   # 해설 모드로 기동
./reachy.sh robot up                                   # 일반 대화 모드로 기동
./reachy.sh robot down                                 # 정지 — 앱 + 맥 서버까지 전부
```

| 명령 | 하는 일 |
|---|---|
| `robot up` | 아래 순서를 그대로. 끝나면 상태와 로그를 보여준다 |
| `robot down [--keep-servers]` | 앱 정지 + 맥 추론 3종·MCP 서버까지 정리. `--keep-servers` 면 앱만 |
| `robot deploy` | 소스·설치본 rsync + `__pycache__` 정리 후 `up` |
| `robot logs [줄수]` | 앱 출력만 추려 **실시간**으로 (`--no-follow` 로 한 번만) |
| `robot status` | 데몬·백엔드·모터·제어루프 Hz·nb_error·미디어·앱 |
| `robot fix` | 장애 복구 사다리 (아래) |

**`robot up` 이 하는 일** — 손으로 하면 꼭 하나를 빠뜨리는 순서다.

1. **로봇 도달 확인** — ping + 데몬 API, 백엔드가 죽어 있으면 먼저 복구
2. **맥 추론 3종을 `0.0.0.0` 으로** — 이미 떠 있으면 건너뛴다. **맥의 LAN 주소로** 떠 있는지
   확인한다 — `start --sim` 이 loopback 에 남긴 서버는 로봇에서 안 보인다
3. **예열** — 앱과 **같은 프롬프트로**. 빠뜨리면 첫 발화가 2.5초 늦는다
   (실측: 2.5k 토큰 프롬프트가 예열 시 0.089s, 미예열 시 2.512s). 맥 쪽 일이라 기상보다
   앞에 둔다 — 기상과 앱 기동 사이가 짧을수록 절전으로 빠질 틈이 준다
4. **로봇 `config.json` 동기화** — 망이 바뀌면 맥 IP가 달라지는데 로봇 설정은 그대로라
   앱이 **죽은 주소로 붙어 조용히 벙어리가 된다**. 매번 맞춘다
5. **로봇에서 맥이 보이는지** — 8080·8090·8099 를 로봇 쪽에서 직접 확인
6. **기상** — `set_mode/enabled` → `wake_up`. **순서가 중요하다**: 모터가 꺼진 상태에서
   `wake_up` 을 재생하면 헛돈다. 앱은 로봇을 깨우지 않으므로 이걸 빠뜨리면
   말은 하는데 몸이 안 움직인다
7. **앱 기동** — 옛 앱이 이미 돌고 있으면 멈추고 **다시 깨운 뒤** 새 config 로 띄운다
8. 앱 기동 후 **모터를 다시 확인** — 기상과 기동 사이에 절전으로 빠지는 경합이 있다

**사전 조건**

- 로봇 전원이 켜져 있고 맥과 **같은 망**에 있을 것. 로봇이 자체 AP 모드면 맥이 그 AP에 붙으면 된다
- **Reachy Mini Control 앱을 닫을 것.** WebSocket·WebRTC 세션이 CM4 부하를 올려
  앱의 데몬 연결(타임아웃 5초)이 실패한다. 데몬을 내리는 `daemon-stop` 도 여기서 나온다

**장애 대응 사다리**

| 증상 | 처방 |
|---|---|
| 앱이 `error`, `Could not connect to daemon` | 재시도. Control 앱을 닫으면 재발하지 않는다 |
| `[로봇 루프 오류 #NNNN: Lost connection]` 반복 | 백엔드가 죽은 것 → `./reachy.sh robot fix` → `robot up` |
| `마이크 파이프라인을 기동하지 못했다` | 미디어 스택 꼬임 → `robot fix` (데몬 완전 재시작까지 간다) → `robot up` |
| 말은 하는데 몸이 안 움직임 | 모터 절전 → `robot up` (앱을 멈추고 깨운 뒤 다시 띄운다). ~~`robot fix`~~ 는 앱을 멈추고 깨우기만 해 로봇이 앱 없이 남는다 |

`robot fix` 는 **앱을 멈추고 백엔드를 살리기까지만** 한다 — 앱을 다시 띄우지 않으므로 뒤에 `robot up` 을 잇는다.
| 소리가 작음 | 앱이 기동 시 100%로 올린다. 로그에 `볼륨 최대` 가 없으면 `robot logs` 로 경고 확인 |

**해설 모드 전환** — 로봇 `config.json` 의 `REACHY_PROMPT` 한 줄이다. 앱 재배포가 필요 없다.
`robot up` 은 `REACHY_PROMPT` 환경변수를 그대로 로봇 설정에 옮겨 적고 같은 프롬프트로 예열한다.

### 무엇이 뜨고 내려가나 (2026-08-04 실측)

```
./reachy.sh demo --text          15.3초        ./reachy.sh stop        3.3초
  LLM  :8080  llama-server (gemma 4 E4B Q4_K_M)   → 종료
  STT  :8090  stt_server.py (Whisper v3 Turbo)    → 종료
  데몬 :8000  daemon.app.main --sim               → 종료
  TTS  :8099  crispasr --server (Qwen3-TTS 1.7B)  → 종료
  예열  LLM 프리픽스 캐시 0.94s (TTFT 0.36s → 0.05s) · STT 2s
```

`stop` 뒤 확인: 네 포트 전부 닫힘, `llama-server`·`stt_server`·`crispasr`·`mjpython`
프로세스 0건, PID 파일 정리됨. 손으로 띄운 데몬도 같은 경로로 잡힌다 —
PID 파일로 SIGTERM 을 보낸 뒤 남은 것을 `sweep` 이 패턴으로 한 번 더 잡는다.

### 총 지연 — 발화 종료부터

| 구간 | 실측 | 비중 |
|---|---|---|
| VAD hangover | 0.70s | 설정값 — **가장 크다** |
| STT | 0.49s | |
| **LLM 첫 절** | **0.07s** | **3%** |
| TTS 합성 | 0.31s | 1.7B CustomVoice/serena, speed 1.2 |
| 재생 스트림 | 0.00s | 상주(afplay 0.8초 고정비를 없앴다) |
| **구간 합** | **약 1.6초** | |
| → 모션 | 약 0.95초 | LLM 을 안 기다린다 |

구간 합은 각각을 따로 잰 값을 더한 것이다. **끝단 실측은 1.80초**였는데
그때 TTS 가 0.54초였다(`docs/latency-m0.md`). 지금 구성은 그보다 빠르지만
끝단으로 다시 재지는 않았다.

설계 초기에는 LLM 을 지배적 병목으로 봤지만 **실측하니 3%였다.** 스키마 제약을
걷어낸 뒤로 그 가정은 무효다. 지금 가장 큰 것은 VAD 대기 시간이고, 그건 품질을
위해 의도적으로 늘린 값이다(0.30초로는 질문이 중간에 잘렸다).

## 끼어들기 (barge-in)

로봇이 말하는 중에 말을 걸면 **발화를 끊고 듣는다.**

```bash
REACHY_AEC=1 REACHY_BARGE_IN=1 ./reachy.sh demo    # 스피커 + 마이크
REACHY_BARGE_IN=1 ./reachy.sh demo                 # 헤드셋(에코 없음)이면 AEC 불필요
```

| 환경변수 | 기본 | 뜻 |
|---|---|---|
| `REACHY_BARGE_IN` | `0` | 재생 중에도 마이크를 듣는다 |
| `REACHY_BARGE_IN_RMS` | `0.014` | 임계 **하한** — 조용한 방에서 여기까지 내려간다 |
| `REACHY_BARGE_IN_FACTOR` | `2.0` | 잔여 에코 바닥의 몇 배를 임계 하한으로 쓸지 |
| `REACHY_BARGE_IN_ECHO_MARGIN` | `1.8` | 예측된 에코의 몇 배를 넘어야 사람으로 볼지 |
| `REACHY_BARGE_IN_TRACE` | `2.0` | 판정 상태를 남기는 주기(초). `0`이면 끔 |
| `REACHY_MIC_GAIN` | `1.0` | 마이크 입력 이득. 목소리가 작게 잡히면 2~3 |
| `REACHY_VAD_FACTOR` | `3.0` | VAD 임계 = 소음 바닥 × 이 값 |
| `REACHY_VAD_MIN` | `0.005` | 아무리 조용해도 이 아래로는 안 내린다 |
| `REACHY_VAD_ADAPTIVE` | `1` | `0`이면 예전처럼 고정 임계(0.010) |
| `REACHY_TTS_VOLUME` | `1.0` | **재생 음량. 끼어들기 SNR 을 직접 좌우한다** — 에코가 크면 0.6 |
| `REACHY_TTS_PREBUFFER` | `0.25` | 재생 시작 전에 모아 둘 오디오(초). 첫 음절 깨짐 방지 |
| `REACHY_BARGE_IN_WAKE` | `미니야,그만,잠깐만,스톱` | 호출어 목록. 비우면 에너지 판정만 쓴다 |
| `REACHY_BARGE_IN_WAKE_INTERVAL` | `0.5` | 호출어 확인(STT) 최소 간격(초) |
| `REACHY_BARGE_IN_WAKE_MIN_SPEECH` | `4` | 창에 이만큼(0.12초) 말소리가 있으면 STT 를 부른다 |
| `REACHY_BARGE_IN_WAKE_MIN_WINDOW` | `20` | STT 에 넘길 최소 창 길이(0.6초). 조각을 넘기면 환각이 난다 |
| `REACHY_BARGE_IN_FRAMES` | `5` | 최근 창에서 임계를 넘은 프레임 수 (기침 방어) |
| `REACHY_BARGE_IN_WINDOW` | `9` | 그 창의 크기 — 9 × 30ms = 270ms. **연속이 아니라 비율로 센다** |
| `REACHY_BARGE_IN_ANSWER` | `0` | 끊은 그 발화에 대답할지. 기본은 끊기만 하고 다음 질문을 기다린다 |
| `REACHY_BARGE_IN_DROP_WINDOW` | `3.0` | 이 시간 안에 끝난 발화만 "끼어든 소리"로 본다(초) |
| `REACHY_AEC` | `0` | 소프트웨어 에코 제거 — **재생 경로가 GStreamer 로 바뀐다** |
| `REACHY_AEC_SUPPRESSION` | `moderate` | `low`/`moderate`/`high` |
| `REACHY_BARGE_IN_GRACE` | `1.0` | 끊은 직후 게이팅을 푸는 시간 — **연장하지 않는다** |
| `REACHY_MOTOR_QUIET` | `1` | 사용자 발화 중 sway·대기모션 정지 — 서보 소음이 STT 를 오염시킨다(실기용, §12) |
| `REACHY_ECHO_TAIL` | `3.0` | 자기 목소리 방어선의 적용 창(초) — 마지막 출력 이후 이만큼만 검사 |

### 가장 확실한 길 — 호출어 "미니야"

에너지 판정에는 한계가 있다(아래). 그래서 **내용으로 가르는 길**을 함께 둔다.

```
사용자: "미니야"  →  [호출어 감지 — 발화 중단]
```

에너지가 임계에 못 미치는 작은 소리여도, 그 구간을 STT 에 넘겨 호출어가 확인되면 끊는다.
약 0.5초가 더 걸리지만 **놓치지 않는다.**

호격 **"미니야"** 를 기본으로 쓰는 이유가 있다 — 로봇은 자기를 부르지 않는다. 대본에도
`"저는 리치 미니예요"` 뿐이라, **에코가 이 말을 만들어낼 수 없다.** 자기 목소리 오인이
구조적으로 불가능하다(`"미니"` 만 호출어로 두면 대본이 그대로 걸린다 — 테스트로 고정).

기본 호출어: `미니야` · `그만` · `잠깐만` · `스톱` (`REACHY_BARGE_IN_WAKE` 로 교체)

두 갈래로 판정한다:

| 길 | 조건 | 지연 |
|---|---|---|
| 빠른 길 | 에너지가 예측 에코의 1.8배 초과 | 즉시 (~150ms) |
| 확실한 길 | 창에 말소리 0.24초 이상 + **호출어 확인** | ~0.5초 (STT 한 번, 백그라운드) |

호출어 확인은 **별도 스레드**에서 돈다 — 마이크 루프에서 직접 부르면 STT 가 도는 0.4초
동안 프레임을 못 읽어 정작 호출어 뒷부분을 놓친다(실측). 그리고 **무음은 STT 에 넘기지
않는다** — 넘겼더니 Whisper 가 `'조금 조금 조금 …'` 을 만들어냈다(환각).

### 판정의 핵심 — 우리는 지금 무슨 소리를 내는지 안다

에코는 정상 신호가 아니다. 실측에서 **로봇 말의 조용한 구간은 0.003, 큰 음절은 0.025** 였고
사람 목소리(0.023~0.031)와 그대로 겹쳤다. **에너지 하나로는 못 가른다** — 큰 음절에
헛트리거되거나 사람을 놓치거나 둘 중 하나다.

그래서 **재생 중인 PCM 의 세기(`Speaker.output_level`)** 를 함께 본다. 출력 세기 →
마이크 되돌아옴의 비(결합계수)를 관측으로 추정해두면, "지금 나가는 소리면 마이크에 이만큼
잡혀야 한다"를 예측할 수 있다. 그보다 뚜렷하게(기본 1.8배) 크면 사람이다.

| 상황 | 마이크 | 예전(고정 0.014) | 지금 |
|---|---|---|---|
| 로봇 큰 음절 | 0.025 | **걸림** (헛트리거) | 안 걸림 (임계 0.045) |
| 로봇 보통 음절 | 0.014 | **걸림** (헛트리거) | 안 걸림 (임계 0.025) |
| 사람 — 로봇 큰 음절 위 | 0.050 | 걸림 | 걸림 |
| 사람 — 말 사이 틈 | 0.028 | 걸림 | 걸림 (임계 0.014) |
| 사람 작게 — 틈 | 0.020 | 걸림 | 걸림 |

말 사이 틈에서는 임계가 바닥까지 내려가므로 **작게 말해도 걸린다.** 큰 음절 구간에서는
그만큼 크게 말해야 하는데, 이건 사람의 청각과 같은 규칙이라 어색하지 않다.

### 에코가 크면 임계를 만질 게 아니라 **스피커를 줄인다**

마이크 이득(`REACHY_MIC_GAIN`)은 목소리와 에코를 같이 키워서 **비율이 안 변한다** — 적응
임계도 함께 올라가므로 끼어들기에는 도움이 안 된다(VAD 절대 임계와의 여유만 벌린다).

에코 바닥이 사람 목소리 수준까지 올라오면 `REACHY_TTS_VOLUME=0.6` 으로 **재생을 줄인다.**
그러면 에코만 작아지고 목소리는 그대로라 분리가 쉬워진다. 로그가 그 상황을 이렇게 알린다:

```
[경고] 잔여 에코가 커서 끼어들기 임계가 사람 목소리 수준까지 올라갔다
       — REACHY_TTS_VOLUME=0.6 으로 재생을 낮추거나 REACHY_AEC_SUPPRESSION=high 를 써라
```

### 임계 하한 — 고정이 아니라 에코 바닥의 배수

실측에서 **사용자 목소리가 마이크에 0.029~0.030** 으로 잡혔는데 고정 임계가 0.020 이었다.
여유가 1.5배뿐이라 거리·음량·방 상태가 조금만 달라져도 걸렸다 안 걸렸다 했다.

지금은 로봇이 말하는 동안 마이크에 남는 소리(= AEC 가 못 지운 잔여 에코)의 **중앙값을
계속 추정해 그 2배를 임계로** 쓴다. 방·음량·AEC 성능이 달라져도 따라간다.

| 잔여 에코 바닥 | 적응 임계 | 사용자 0.029 |
|---|---|---|
| 0.005 | 0.014 (하한) | 걸림 |
| 0.010 | 0.020 | 걸림 |
| 0.013 | 0.026 | 걸림 |
| 0.016 | 0.032 | **안 걸림** → 음량을 낮추거나 `REACHY_AEC_SUPPRESSION=high` (로그가 경고한다) |

중앙값을 쓰는 이유는 사람이 잠깐 끼어들어도 바닥 추정이 흔들리지 않게 하기 위해서다.
"임계 아래 프레임만 모으기"는 쓰면 안 된다 — 바닥이 하한보다 높은 방에서는 표본이 하나도
안 쌓여 임계가 영영 학습되지 않는다(닭-달걀).

### 판정 — 연속이 아니라 비율

사람 말은 음절 사이에서 에너지가 순간적으로 떨어진다. "N프레임 **연속**"으로 재면 한 프레임만
내려가도 카운터가 0이 되어, 실측 로그에서 **첫 끼어들기만 우연히 통과하고 그 뒤로는 한 번도
성립하지 않았다.** 지금은 최근 9프레임(270ms) 중 5개 이상이 임계를 넘으면 인정한다.

끊고 나면 **그 발화에는 대답하지 않고** 다음 질문을 기다린다. 끊는 순간의 전사에는 잔여
에코가 섞여 엉뚱한 답을 부르기 때문이다(실측: `"잠깐만."` → `"네, 잠시 기다리고 있을게요"`).

다만 **버리는 것은 끊은 직후 3초 안에 끝난 발화뿐이다.** 시간 제한이 없었을 때는 끊고
20초 뒤에 한 질문까지 "끼어든 말"로 분류돼 통째로 버려졌다(실측). 그리고 호출어 뒤에 말이
이어지면 그건 질문으로 받는다 — `"미니야 오늘 날씨 어때"` → 호출어만 떼고 날씨를 답한다.

| 끊은 뒤 들린 말 | 처리 |
|---|---|
| `"미니야"` (호출어만) | 흘려듣고 다음 질문 대기 |
| `"미니야 오늘 날씨 어때"` | 호출어를 떼고 **질문으로 받는다** |
| 소리로만 끊은 경우(호출어 없음) | 흘려듣는다 — 잔여 에코일 확률이 높다 |
| 3초 지나서 한 말 | **정상 질문으로 받는다** |

재생이 끝날 때마다 `[재생 중 마이크 최대 RMS 0.0xx / 임계 0.02]` 를 로그에 남긴다 —
끼어들기가 안 걸릴 때 임계를 올릴지 내릴지 판단할 근거다.

### 끊는 쪽 — `Speaker.stop()`

셋을 함께 해야 진짜로 멈춘다. ①취소 플래그(청크 루프 탈출) ②큐 비우기(대기 절 폐기)
③`abort()`(PortAudio 버퍼 폐기). 실측: 3.82초를 받던 중 중단 → 추가 수신 청크 1개,
그 뒤 조용. **중단해도 TTS 서버는 죽지 않는다**(중단 직후 `/health` 정상, 재합성 정상).

대본 경로도 같은 규칙이다 — `respond()` 는 큐에 넣고 곧바로 반환한다. 예전에는 거기서
재생 완료를 기다려 마이크 루프가 55초간 멈췄고, 그동안은 끼어들 수 없었다.

### 듣는 쪽 — 에코를 어떻게 지우나

스피커 소리가 마이크로 되돌아오므로, 그냥 켜면 로봇이 자기 목소리에 반응해 스스로
말을 끊는다. `REACHY_AEC=1` 이면 GStreamer 의 WebRTC AEC 가 그걸 뺀다:

```
재생:  TTS 청크 → StreamPlayer(PortAudio 상주 스트림)   ← 검증된 경로 그대로
         └─ 같은 PCM 한 벌 ─→ appsrc → webrtcechoprobe → fakesink(sync=true)
캡처:  autoaudiosrc → webrtcdsp(probe=reachy_echo_probe) → appsink
```

프로브가 far-end 를 기록하고 `webrtcdsp` 가 그 신호를 뺀다. **재생 경로는 건드리지
않는다** — 처음엔 재생 자체를 GStreamer 로 옮겼는데 TTS 청크가 최대 0.5초 간격으로
와서 소리가 끊겼다(`docs/lessons.md`). 프로브는 far-end 를 *듣기만* 하면 되므로
같은 PCM 을 복사해 보내고, `fakesink sync=true` 가 실시간 속도로 소비해 시간축을 맞춘다.

`noise-suppression` 과 `gain-control` 은 기본으로 꺼 둔다 — STT 품질을 깎는 쪽이다.
프로브는 마이크보다 **먼저** 서야 한다(`Speaker` 생성 시점). 늦으면 `webrtcdsp` 가
짝을 못 찾아 캡처가 READY 에서 멈추고 앱이 굳는다 — 지금은 그 경우 경고를 찍고
AEC 없이 계속한다.

실기에서는 이 자리를 XMOS 하드웨어 AEC 가 대신하므로 `REACHY_AEC` 없이 동작한다.

### AEC 로도 다 못 지운다 — 의미로 한 번 더 거른다

`Speaker.said_recently()` 가 STT 결과를 **로봇이 최근에 낸 문장과 대조**해 닮았으면
버린다. 이게 없으면 잔여 에코를 사용자 발화로 오인해 자기 대본을 받아 적고
**스스로에게 다시 대답한다**(실측 로그). 신호처리로 못 지운 것을 의미로 거르는 것이다.

### 검증 — 켜기 전에 잰다

```bash
./reachy.sh measure aec                     # 스피커로 소리가 난다
```

같은 발화를 AEC 끄고/켜고 재생하며 **사람은 조용히 있는 상태로** 마이크를 관찰한다.
판정 기준 둘: 잔여 에코 p95 < 끼어들기 임계, 오탐 0회. 통과하면 스피커로 켜도 된다.

## 프로덕션 구조

### 배치 — 무엇이 어디서 도나

```
┌──────────── 로봇 (Reachy Mini / CM4) ────────────┐
│                                                  │
│   VoiceChat(ReachyMiniApp)   ← main.py           │
│     ├ 마이크 캡처 (GStreamer)                     │
│     ├ VAD · 절 분할 · 모션 재생                   │
│     └ 스피커 출력                                 │
│                                                  │
│   * 오디오가 네트워크를 타지 않는다               │
└──────────────────────┬───────────────────────────┘
                       │ HTTP (WiFi)
                       │ 발화당 파일 하나 — 지터에 강하다
                       │ 전송 실측 14~27ms
┌──────────────────────┴───────────────────────────┐
│                     PC (맥)                       │
│                                                  │
│   :8080  LLM   llama.cpp · Gemma 4 E4B Q4_K_M    │
│   :8090  STT   stt_server.py · Whisper v3 Turbo  │
│   :8099  TTS   CrispASR · Qwen3-TTS 1.7B         │
│                                                  │
│   * 1.7B TTS 는 CM4 에 무리라 어차피 PC 몫이다    │
└──────────────────────────────────────────────────┘
```

로봇의 컴퓨트는 **CM4104016 — RAM 4 GB / eMMC 16 GB** 다(Pi 5 가 아니다. Pi 5 는 최초
발표 자료에만 있었고 출하품은 CM4 로 바뀌었다). 추론 3종이 PC 에 남는 것은 취향이 아니라
**RAM 4 GB 라 올릴 수가 없어서**다. 대상 기종은 **Wireless** 로 확정했다 —
근거와 그로부터 갈리는 것들은 `docs/real-robot-deployment.md` 머리말에 있다.

세 주소는 **코드 수정 없이** 환경변수로 옮긴다:

```bash
REACHY_LLM_URL=http://<PC>:8080
REACHY_STT_URL=http://<PC>:8090/v1/audio/transcriptions
TTS_QWEN_URL=http://<PC>:8099/v1/audio/speech
```

> ⚠ **Wireless 에서는 이 export 가 앱에 안 닿는다.** 앱은 systemd 데몬의 자식이라
> 운영자 셸의 export 를 못 본다. 그래서 사다리가 하나 더 있다 —
> **환경변수 → 설정파일 → 기본값** (`config.py`):
>
> ```
> ~/.config/reachy-mini-voice-chat/config.json     # 키 이름은 환경변수와 동일
> ```
>
> 기동 첫 줄이 세 주소와 출처를 밝히고, **실기(Linux)에서 loopback 이면 크게
> 경고한다** — `docs/real-robot-deployment.md` §10.

### 진입점이 둘인 이유

| | 파일 | 쓰임 |
|---|---|---|
| 정상 | `main.py` | `ReachyMiniApp` — **실기가 실행하는 것.** 시연도 이것으로 돈다 |
| 폴백 | `demo.py` | `--text` / `--no-robot` — `ReachyMiniApp` 이 표현 못 하는 모드 |

`reachy.sh` 의 기본 경로가 `main.py` 다 — **시연에서 돌리는 것과 배포하는 것을
같게** 두려는 것이다. 예전에는 데모가 `demo.py` 만 태워서 `main.py` 가 생성
템플릿인 채로 방치된 것을 아무도 몰랐다.

**대화 로직은 `session.py` 하나뿐이다.** 진입점에 복사하지 않는다.

### 모듈

```
apps/voice_chat/voice_chat/
├ main.py        실기 진입점 (ReachyMiniApp, stop_event 로 종료)
├ demo.py        폴백 진입점 (--text / --no-robot)
├ session.py     ★ 대화 로직 — build() / respond() / announce_voice()
├ voice_loop.py  마이크 루프 + half-duplex 게이팅
│
├ audio_in.py    GStreamer 캡처 + 에너지 VAD
├ stt.py         → STT 서버
├ llm.py         → LLM 서버 (스트리밍, 이력 3쌍)
├ clauses.py     토큰 스트림 → 절 분할
├ tts.py         → TTS 서버 + 상주 오디오 스트림 + 폴백 사다리
│
├ driver.py      **로봇에 쓰는 유일한 스레드**(100Hz) — 모션 + 흔들림 합성
├ motion.py      발화 → 모션 카테고리 분류 · 무엇이 무엇을 밀어내는지
├ sound.py       모션 자체 발성(.ogg) 디코딩 → 발화 큐로
├ emotions.py    감정 연기 18종 · 대기 모션
├ animator.py    흔들림·호흡 계산(순수 상태기계 — 스레드 없음)
├ idler.py       12~25초마다 혼자 감정 표현
├ selfintro.py   "어떻게 만들어졌어?" 고정 대본 + 문장별 시드
└ prompt.md      성격 정의
```

### 고장나도 말은 한다 — 폴백 사다리

```
TTS 서버 (Qwen3-TTS)
   └ 실패 → 로컬 합성기: say(macOS) → espeak-ng → espeak
              └ 없음 → 경고 로그 (조용히 넘어가지 않는다)

오디오 스트림 (PortAudio)
   └ 못 열면 → 외부 재생기: afplay → paplay → aplay
                 └ 없음 → 경고 로그

LLM 서버
   └ 실패 → 고정 폴백 대사 + 모션은 계속 동작
```

`TTS_BACKEND=say` 로 통째로 macOS 음성으로 되돌릴 수도 있다.
